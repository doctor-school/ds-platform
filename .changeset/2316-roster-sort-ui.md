Congress roster sort in admin (044 EARS-22/EARS-37, owner Stage-A pick S1). `DataTable` gains an opt-in server-sort API: a column (or the record column) declares `sortKey`, the table is controlled through `sort` + `onSortChange`, and a sortable header renders as a `<button>` inside `<th aria-sort>` with an always-visible muted double arrow and, on the active column, a single direction arrow in the `primary-action` accent; the active column's body cells are shaded with the new semantic token `table-sorted` (neutral.50 light / neutral.925 dark); a column's optional `headerDetail` renders as a smaller second header line; the sort button follows the column alignment; below `md` `sortSelect` renders a «Сортировка» select over the record cards. With `defaultSort` a header is the tri-state cycle — ascending, descending, back to the default order — and `sortActionLabel` puts what the next click does on its `title`; the sorted cells share the row's `transition-colors`, so a hovered row's sorted cell repaints in the same frame as the row. Tables without `sortKey` are unchanged. `AdminDataList` carries an optional `sort` in its query state (a sort change resets to page 1). The roster sorts by ФИО, специальность, город, телефон and дата регистрации, and by «Присутствие» for the chosen congress day (header «Присутствие» over «день ДД.ММ»); the sort lives in the address (`?sort=&dir=`) and defaults to registration date ascending (a third header click, or the «По умолчанию — …» option, returns to it and clears the address) — an address sort the screen cannot honour (presence after a reload drops the day) is rewritten to the default.
