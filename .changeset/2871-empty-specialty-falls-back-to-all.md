The doctor events feed falls back to every specialty when the doctor's default «Моя и смежные» — own specialty plus adjacent areas — has no events (019 LD-9, EARS-9, #2871); a doctor whose own specialty is empty but whose adjacent areas have events keeps «Моя и смежные». When the read names no specialty scope and the remembered specialty's directions and their adjacent ones carry no upcoming doctors-audience event, `GET /v1/storefront/doctor/events` (and the month reads) answer with `targeting.mode: "all"`; an explicit `specialty` in the request is honoured as before. The new `targeting.defaultScopeEmpty` describes the visitor, not the query: every read reports it, whatever scope the request names. `DoctorEventsFeedQuerySchema.specialty` and the month query's `specialty` are optional with no default, so an absent scope is distinguishable from an explicit «Моя и смежные». The shared facet panel shows «Все специальности» selected under the fall-back as this visitor's default: `EventsFilter` takes `defaultSpecialtyScope` and `countAppliedFacets` an `AppliedCountOptions`, so the default scope is counted in neither «Применено: N» nor «Фильтры (N)» and «Сбросить» appears only for a facet beyond it. For this visitor an explicit `specialty=all` is the default too (uncounted, left out of the URL), while «Моя и смежные» is a narrowing: counted with «Сбросить», written as `specialty=mine-and-adjacent` and kept across later facet changes, so the fall-back does not take it back. Removing the last picked specialty returns to the visitor's default scope (`EventsFilter` uses `defaultSpecialtyScope`), and `hasAppliedFacets` / the empty state treat only that default as no facet. In the no-match state, a picked specialty whose removal falls back to every specialty is passed over — no «Показать смежные специальности» — and the next applied facet is weakened (`WidenMatching` now answers a `WidenRead`).
