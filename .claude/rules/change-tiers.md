# Change tiers (reference)

Procedure is proportional to risk (Ship / Show / Ask). Pick the tier before work starts, by what the change does; the changed-file set sets a mechanical minimum the author may never go below. When unsure → the higher tier. An owner request that turns out to need new logic is re-tiered, and the owner told, before work starts.

| Tier | Qualifies                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | Procedure                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Ship | copy; substituting already-existing data into an existing component (a dynamic value instead of a hardcode); a small presentational tweak — only ship paths (below), no new/removed/renamed non-test file, ≤80 changed non-test lines; **test-only**: a PR changing only tests (below), declared `ship — test-only: <reason>`                                                                                                                                                  | the lead authors inline (no brief, no implementer); worktree + branch as usual; no separate Issue required (`Closes #N` when an owner Issue exists, else `Refs #<epic>`); tests (the only exception to «no production code without a failing test»): none pinning wording, exactly one for a value substitution, existing tests quoting old text updated; green CI; Stage-B = the owner's chat decision (below); no Mode (a); no ui-parity evidence; land with `pnpm pr:land <N>` |
| Show | a new state/behaviour inside an existing feature; no Ask path                                                                                                                                                                                                                                                                                                                                                                                                                  | normal dispatch; merges on green CI once the gate verifies the declaration; one Mode (a) review after the merge, findings → follow-up Issues; ui-parity evidence as for every UI PR, captured from the agent's local run; Stage-B GO on those PR captures for an owner-visible difference, no staging slot                                                                                                                                                                        |
| Ask  | auth (`packages/auth-flow/**`, `lib/**auth*`, `app/**/(auth)/**`, `app/**/{login,register,verify,reset,mfa}/**`, `providers/*auth*`, `lib/**/*session*` modules), server endpoints (`app/**/api/**`, `route.*`) and server actions (`actions/`, `*action*` files; a plain `page`/`layout`/`loading`/`error` route file stays show), DB/migrations, API contracts/schemas, new forms with a data model, security, infra/deploy, CI/guards/tooling, dependencies, new specs/ADRs | the full procedure in `repo-conventions.md` and the skills; Stage-B and stands per the section below (a per-PR staging slot only for an owner-visible difference or the agent's environment-sensitive check)                                                                                                                                                                                                                                                                      |

**Declaration.** Exactly one PR-body line `Change-tier: ship|show|ask — <reason>`. Absent, duplicated, malformed, or a ship/show line without a real reason (`n/a`, `none`, `tbd`, a `<placeholder>`) = `ask`.

**Mechanical minimum** (`tools/lint/lib/change-tier.ts`, one rule for every gate). `ask` always when any changed path (or a rename source) is under `infra/` `tools/` `.github/` `.claude/` `.codex/` `scripts/`, any `design-source/`, or is `AGENTS.md`/`CLAUDE.md`, a `package.json`, the lockfile/workspace/`turbo.json`, a `*.config.*`, `Dockerfile*`, `docker-compose*`, `.env*`, `middleware.*`, `proxy.*`, `apps/docs/content/agent-discipline.md` or a `migrations/` file — a test there included. `ask` when a non-test file is under `packages/{db,schemas,api-client}/`, `apps/api/`, `apps/docs/content/{specs,adr,skills}/` or on the auth / server-endpoint / server-action paths of the Ask row — except the email-copy allowlist `apps/api/src/mailer/code-emails.ts`, `apps/api/src/mailer/notice-emails.ts`, and a **modified** spec `.md(x)` under `specs/` (no rename), which follows the code: it raises neither the tier nor the line count, but a PR whose only non-test changes are such docs stays `ask`; an added/removed/renamed spec file and any ADR or skill change are `ask`. A spec `.feature` (`apps/docs/content/specs/**/*.feature`) is a test when it is modified and every changed hunk line is a tag (`@…`), a `#` comment or blank — proven from the REST `pulls/<n>/files` `patch`; Feature/Scenario/step/table text changes, an added/removed/changed `@host:` tag (it selects the CI projects), a `# language:` line, any line inside a doc string (`"""`/` ``` `, or a hunk opening on a delimiter it cannot place), an added/renamed `.feature`, or no patch = `ask`; a hunk wholly inside a doc string longer than the diff context, with no delimiter in view, reads as outside it, so a blank/`#`/tag line there can pass as a test — accepted: the merge gate re-proves from the REST listing with no PR-head checkout, and no spec `.feature` carries a doc string. Also `ask` when the changed-file set is empty or incomplete. Otherwise `show` when a non-test file is added/removed/renamed, is not a ship path, a test or `.changeset/*.md` file is removed/renamed, or non-test non-changeset files exceed 80 changed lines. Otherwise `ship`. **Tests** = `*.test.*`/`*.spec.*`/`*.e2e-spec.*`, `__tests__/`, `e2e/` (incl. `packages/e2e/**`) except a runner script there (`run-*`, a `bin/` segment: it decides what CI runs), `apps/api/test/**`, plus such `.feature` edits; with `.changeset/*.md` and evidence captures they never raise the tier. A PR made only of them is **test-only**: ship with no Mode (a).

**Ship paths** (an allowlist; tests are exempt): render-capable UI source per `isUiSourcePath` (`tools/lint/lib/ui-surface.ts`); a copy module `packages/*/src/**/{copy.ts,*-copy.ts,copy/**}`; the email-copy allowlist above; `.changeset/*.md`; `DEBT.md`; a package/module `README.md` under `apps/` or `packages/` (not `design-source/`, not docs content); plain product docs `apps/docs/content/**/*.md(x)` outside `specs/`, `adr/`, `skills/` and `agent-discipline.md`. UI- or copy-shaped files carrying server, routing or auth behaviour are never ship paths: a `server/` or `actions/` segment, an `*action*` source, a Next.js `app/**/{page,layout,route,template,default,loading,error,not-found,global-error}` file, `lib/**auth*`, any `auth` path segment outside `src/ui/` or a copy module, `proxy.*`, `middleware.*`, `instrumentation.*`. Everything else (models, `lib/`, hooks, routing helpers) is at least `show`.

**Enforcement.** The `change-tier` guard (BLOCK, `pr-body-guards.yml`, also in `pnpm pr:preflight`) refuses a declaration below the minimum. Merge gate: a body declaring ship or show is re-proven on the REST file listing, bound to the merge head (`headRefOid` read before and after the listing must equal it); verified ship prints `Mode (a) not required — Change-tier ship verified (…)` (`test-only, …` for the test-only class; the listing's `patch` proves a `.feature` edit); verified show prints `Pre-merge Mode (a) not required — Change-tier show verified (…)` and the lead dispatches `request-mode-a-review` on the merged PR — `pnpm bootstrap` lists every Show PR merged since the rule took effect (`SHOW_REVIEW_SINCE`) until a Mode (a) verdict exists after the merge or on the merged head (a full search page is a Warnings row); a Show PR on a reviewer-certified `ui-parity: N/A` route still needs that pre-merge certification; not verified, it prints why and requires the head-pinned Mode (a) APPROVE. `ui-parity` skips a verified ship PR. `.github/ui-evidence/**` captures are exempt from the minimum, like tests. `stage-b` routes on the runtime files only — tests, `.changeset/*.md`, `.github/ui-evidence/**`, `apps/docs/content/**` docs and `.feature` files excluded — so a declaration those files forced up routes by the runtime minimum (one declared above the whole-PR minimum stands): a ship GO needs no live URL; a show GO may cite `Stage-B-evidence: https://…` (a PR capture) in place of `Stage-B-live-url`. Every GO keeps the `Stage-B-head` pin with recorded-at, owner-quote and source; a new head carries it when it is a pure rebase or when the PR's own delta since the recorded head (net of main) is only those non-runtime files — the guard prints the carried files; a runtime file needs a fresh verdict. `N/A (no visual surface) — lead-certified` on a PR without environment-sensitive paths (auth: an `auth` segment, `lib/**auth*`, `app/**/{login,register,verify,reset,mfa}/`, `middleware.*`, `proxy.*`; `apps/api/drizzle/`, `packages/db/src/schema/`, `infra/`, `apps/api/src/mailer/`, `apps/api/src/bot-protection/`, any `idp`/`zitadel`/`captcha` path) needs no slot: a green CI e2e check on the head plus main-vs-head captures of every touched screen as `Stage-B-evidence: https://…`; an environment-sensitive PR keeps the live slot report. An owner quote found verbatim in `AGENTS.md`, `CLAUDE.md`, `.claude/rules/**`, `agent-discipline.md` or `skills/**` is refused: an instruction line is not an owner decision. Both guards treat a PR whose changed-files count is missing or does not match the listing as `ask`.

## Stage-B and stands

The tier sets the Stage-B route; whether there is a Stage-B at all is set by what the user will see. The route is read from the PR's runtime files: test, changeset, capture, doc and `.feature` files may raise a PR's tier (a new spec, a scenario-text change), never its Stage-B route.

1. **Owner Stage-B only for an owner-visible difference.** The owner is asked for a GO only when the user will see or experience something different. No render surface — a spec, ADR, test, tooling or guard change, Ask included — means no Stage-B, no slot and no owner GO: the `stage-b` guard exits before reading the body when no `isUiSourcePath` file changed, and the body records `Stage-B: N/A — no render surface`. A recorded GO carries over a later delta of only those non-runtime files.
2. **The agent's own live check of logic without screens.** Environment-sensitive changes — auth/login/registration, email/SMS, captcha, external integrations, migrations, infra — are verified by the agent itself on the PR slot (`pnpm stage:slot up pr-<N>`), with no owner request; internal logic is proven by API e2e in CI plus the release pre-flight, where `pnpm deploy:prod` converges the stage `main` slot to the target SHA and runs the full stage suite.
3. **Invisible UI changes are proven by green CI e2e + before/after captures.** A UI-source change with no visible difference (refactor, plumbing, a value that renders identically) on a PR without environment-sensitive paths is lead-certified `N/A (no visual surface)`: green CI e2e on the head plus main-vs-head captures of every touched screen as `Stage-B-evidence`, under the owner's `autonomous-merge` authorization — no slot, no owner GO.

Before any owner ask, the lead names what the owner must check that the agent could not. An Issue AC never prescribes the verification route (slot, stand, browser run), and a handoff never carries a stand/GO step as a command: the tier and these rules derive it afresh each session, and recorded GOs carry over as valid.
