# `staff-access` — feature 047 «Доступы» (staff roles)

Spec: [`specs/features/047-staff-access`](../../../docs/content/specs/features/047-staff-access/047-design.md) · ADR-0001 (authz, §10 step-up).

The module owns the `superadmin` surface (049 EARS-3) that lists, grants and revokes the staff roles of `GRANTABLE_STAFF_ROLES` (`@ds/schemas`): `platform_admin`, `event-registrar`, `congress-program-committee` and `broadcast_director`. It also lists the holders of `superadmin` (`LISTED_STAFF_ROLES`) but never grants or revokes that role — only the operator command does (049 EARS-6); each row carries `revocable`, false for `superadmin`, for the caller's own `platform_admin` and for the `platform_admin` of a holder of `superadmin`, whose revocation is refused `409 STAFF_REVOKE_SUPERADMIN_HOLDER` (049 EARS-5). A grant and a revocation each span the IdP, Postgres, the admin session store and the ledger, so each is a fixed sequence of idempotent steps (047-design §Completeness and retry, §Grant cascade, §Revoke cascade); the `auth.role.granted` / `auth.role.revoked` row is the completion mark. A revocation ends every admin session and pending admin sign-in of the person, also when its IdP step failed. Before ending them it bumps the person's admin access generation (`AdminSessionService.endAllAdminAccess`), so a sign-in already in flight with the old roles can no longer mint a session (`AdminSessionStore.createFromPending`).
