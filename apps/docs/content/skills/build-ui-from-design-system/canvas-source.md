## Canvas source → vendor it, build from it (never from prose)

When the design originates in a **Claude Design canvas** (`.dc.html`) — a full re-skin, an auth/webinar screen set, any owner-authored visual language — the canvas is the fidelity SoT, and its **exact values** (px, border widths, colors L+D, states, placeholders) live only in the `.dc.html` inline styles:

- **Import first, before dispatching or building — EVERY canvas the surface renders.** Vendor the `.dc.html` into `design-source/` via `DesignSync get_file` (resolve the project id from verified provenance and check the actual receiving agent capability) and write the file **programmatically from the actual tool-result bytes or export file, never by re-typing the content** (follow the portable capability contract; no assumed transcript/tool-results location; record provenance per `design-source/README.md`) — it is a **repo file**, not a link (a link does not survive the next session; the source must). A canvas whose bytes are not in the repo is **not-ready**, not "prose in the issue". The gate covers **every referenced canvas, not only the headline one**: a demo/composition rendering a unit whose spec lives in a separate canvas (a card inside a rhythm demo, a block inside a screen) requires THAT canvas vendored first — the #514 round-1 reject was headline-only scoping (the card built from §09 prose while `ВебинарКарточка.dc.html` sat unimported).
- **Build from the file.** The issue-body text is a lossy transcription — a coverage checklist, not the spec. Where prose and the `.dc.html` disagree, **the source wins**. Hand implementers the **file path** and state "the source overrides any prose in this brief"; do **not** re-narrate the source's values back as prose (that reintroduces the transcription loss).
- **Diff render vs source before Stage-B — eyes on pixels, not only probes.** The lead compares the rendered surface against `design-source/<file>.dc.html` **element-by-element** — values, geometry, and presentation — before the owner handback, and this MUST include **reading full-page screenshots at both breakpoints (desktop + ≤900 mobile) × both themes with its own eyes**. Computed-style probes (`getComputedStyle` parity) are necessary but **not** the render check: the #514 round-1 render passed every metric probe while the time plate visibly overflowed and «ЭФИР №» wrapped. Token-safety / tokens-only / internal-consistency is **not** fidelity; every gate can be green while the render diverges from the canvas (the #512–514 re-skin miss). No Stage-B handoff without the eyes-on pass. **And static screenshots are state-blind:** the eyes-on pass MUST additionally probe **interaction-state parity** — hover / active / focus-visible of every interactive element against the owning DS primitive's contract (`Link`: hover→underline, `/80` on active; `Button`: translate+shadow) — via a live pointer drive or `CSS.forcePseudoState` captures (ONE CDP session — memory `reference_cdp_forced_pseudo_state_isolation`). The #818 hover inversion (resting underline + hover-fade on a token-clean element) passed tokens-only lint, axe, AND the static 2×2 eyes-on; only the owner's live hover caught it. Memory `feedback_import_design_source_before_building`.
