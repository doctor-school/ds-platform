# 012 — Content taxonomy (Requirements)

## Outcomes

- A content operator describes a project, expert, topic or partner once and reuses the same retained record everywhere.
- Events relate to several projects, experts and topics through real many-to-many rows; projects relate to experts and partners in both directions.
- An expert is one standalone editorial record. `project_experts.role` is `curator | member`; `event_experts` carries the event-specific role, position and optional explicit match to one legacy speaker row.
- Existing free-text speakers continue to render during gradual migration. A linked, published expert replaces only the explicitly matched legacy row in the current projection; there is no name matching, deduplication, overwrite or implicit retirement.
- Operators create, search, edit, publish, retire and restore taxonomy data in the existing Refine admin. No Delete action exists.
- Later Academy surfaces read publish-safe taxonomy records and every relationship direction through `/v1` REST; no copy, export or synchronization step exists.

## Scope

**In:**

- Top-level retained entities:
  - `projects`: stable id + slug, kind `school | media | program`, title, description, optional cover-media reference;
  - `experts`: stable id + slug, name, professional role, credentials, affiliation, bio, optional photo-media reference; no platform-user foreign key in 012;
  - `topics`: stable id + slug and title, maintained as a curated list;
  - `partners`: stable id + slug, title, optional logo-media reference and optional website URL.
- Common entity fields: `status: draft | published | retired`, nullable `deleted_at`, nullable set-once `first_published_at`, monotonic `version`, and timestamps. Create starts in `draft`; ordinary restore returns an entity to `draft` without clearing `first_published_at`. Expert restore additionally requires `pd_erased_at IS NULL`; erased expert PD is the explicit 409 `PD_ERASED` exception.
- Retained joins: `event_projects`, `event_experts`, `project_experts`, `project_partners`, `event_topics`; each has a stable id, `status: active | retired`, nullable `deleted_at`, `version`, timestamps and a uniqueness constraint for its logical endpoint pair.
- `event_experts`: required event-specific `role`, non-negative `position`, and nullable unique `legacy_speaker_id`. The #1278 retained-row runtime prerequisite replaces `event_speakers`' old `(event_id, position)` primary key with stable UUID `id` row identity, adds partial active-slot `UNIQUE(event_id, position) WHERE status='active'` plus explicit `UNIQUE(event_id,id)`, and supplies retained lifecycle fields including nullable `pd_erased_at`. This enables old and replacement occupants of one position to coexist as retained/active rows, makes the same-event composite FK `(event_id,legacy_speaker_id) → event_speakers(event_id,id)` executable, and makes an approved erased legacy row non-restorable/repopulatable.
- Refine resources for entity list/detail/create/edit and lifecycle actions; relationship editors on the relevant event/project forms; search and explicit retained-row filters.
- Publish-safe public entity reads, bidirectional relationship reads and the merged current speaker projection.

**Out:**

- Doctor-facing rendering: `/`, `/webinars` facets/archive, `/projects`, `/experts` and their detail pages belong to 013–016.
- `event_recordings`, `leads`, Payload CMS, partner commercial terms/contracts, public taxonomy search, recommendation/ranking, bulk speaker migration, expert self-service, or a user↔expert identity link.
- New roles or access-policy concepts; 012 reuses `platform_admin`.
- A general audit-history browser. Feature 010 already captures mutations in `audit_ledger`; 012 only keeps retained rows explicitly addressable for inspect/restore.

## Authoring and publication contract

| Kind    | Required on create                                        | Additional fields required to publish                                                                        | Optional fields                 |
| ------- | --------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ | ------------------------------- |
| Project | `title` (trimmed 1–160); `slug` is generated when omitted | `kind: school \| media \| program`, `description` (trimmed plain text 1–2000), exactly one eligible curator  | `cover_ref`                     |
| Expert  | `name` (trimmed 1–160); `slug` is generated when omitted  | `professional_role` (1–160), `credentials` (1–500), `affiliation` (1–240), `bio` (trimmed plain text 1–4000) | `photo_ref`; initials fallback  |
| Topic   | `title` (trimmed 1–120); `slug` is generated when omitted | no additional field or relationship                                                                          | none                            |
| Partner | `title` (trimmed 1–160); `slug` is generated when omitted | no additional field or relationship                                                                          | `logo_ref`, HTTPS `website_url` |

- Every slug is lowercase ASCII, 1–80 characters, and matches `[a-z0-9]+(?:-[a-z0-9]+)*`. If create omits it, the server applies the canonical transliteration/slugification function to the display label; the UI previews the same candidate. A retained conflict returns 409 `SLUG_CONFLICT` so the operator can provide another value. The first successful publication sets `first_published_at` once; any later slug change, including after retire/restore, returns 409 `SLUG_IMMUTABLE`.
- Drafts may leave only the table's additional publish fields unset. Omitted PATCH members stay unchanged; explicit `null` clears an optional field or a nullable draft-only incomplete field. A mutation of an already-published entity must leave its publication contract valid. A refused publish/update returns 409 `PUBLISH_REQUIREMENTS_NOT_MET` with field-addressed errors and makes no mutation.
- A project can publish with zero events and zero partners when its fields and curator are complete. Experts, topics and partners can publish with zero relationships. Optional media and partner website never block publication.
- Website input, when present, is an absolute HTTPS URL no longer than 2048 characters. Media input, when present, is JPEG, PNG or WebP, at most 10 MiB, at most 6000 px on either decoded axis and at most 25 megapixels; no minimum dimensions apply. Refine performs the same preflight, while server validation is authoritative.
- A no-file create/PATCH is strict `application/json`; a media upload is `multipart/form-data` with one JSON `payload` part and at most the kind-specific `cover|photo|logo` file. Clients never submit storage refs/keys. PATCH omission keeps media, JSON `mediaAction: clear` clears it, and a file plus clear/multiple/wrong file parts is 400 `MEDIA_INPUT_CONFLICT`; multipart without a file is 415 `UNSUPPORTED_MEDIA_TYPE`. The first media vertical (#1283) owns one shared decoder/normalizer consumed by project covers, expert photos and partner logos: it re-encodes accepted images to a canonical output, strips EXIF/XMP/GPS/original filename and all ancillary metadata, derives MIME from normalized bytes, and persists no original upload. Object-storage failure is 503 `MEDIA_STORAGE_UNAVAILABLE` with no domain/audit mutation.
- The same #1283 vertical owns a retained `media_cleanup_jobs` queue distinct from claim-scoped upload cleanup. Every committed replace/`mediaAction: clear` writes a cleanup row for the superseded reference in the same transaction as the ref swap; its worker rechecks that the object is unreferenced, deletes every version/derivative, purges or invalidates the CDN key, retries until complete and retains a non-content tombstone after clearing raw keys. Expert erasure stays `executing` until its compliance cleanup jobs succeed; an unavailable store cannot silently complete erasure or lose the old key.
- Input-mask declaration: `none` for every 012 field, because these values are editorial text, a separately validated slug/URL/integer, or a file rather than a fixed-format identifier; a mask would fabricate or rewrite content instead of assisting entry. The admin therefore uses ordinary text/textarea controls with trim and character counters. Slug uses a generated preview plus pattern/length validation; website uses a URL control; `event_experts.position` uses an integer control with step 1 and range 0–32767; event role is trimmed 1–80 characters. File controls declare the accepted formats and reject size/dimension limits before submit.

## Constraints

- **Retained rows only.** No application path issues `DELETE`, `TRUNCATE`, data-bearing drop, `ON DELETE CASCADE`, or identifier reuse for these entities, joins or migrated `event_speakers`. Every foreign key is `RESTRICT`/`NO ACTION`.
- **Lifecycle consistency.** `retired` iff `deleted_at` is non-null; `draft`, `published` and `active` iff it is null. Ordinary entity transitions are `draft → published`, `draft|published → retired`, `retired → draft`; join and migrated-speaker transitions are `active → retired → active`. An expert or migrated legacy speaker with `pd_erased_at IS NOT NULL` is the explicit non-restorable exception. Retiring an entity never changes its joins.
- **Public default deny.** Public reads include only `published` entities with `deleted_at IS NULL`, `active` joins with `deleted_at IS NULL`, and events allowed by the existing public-event policy. A draft, retired or unknown public id produces the same 404 shape.
- **Explicit retained reads.** Admin lists default to non-retired entities / active joins. Retained rows appear only through an explicit status or `includeRetired=true` query; an admin detail by stable id remains addressable for restore.
- **One current speaker projection.** An active mapping suppresses its matched legacy row only when the linked expert is published and non-retired. Otherwise the legacy fallback remains. Rows sort by `position ASC`, then source rank (`expert` before `legacy`), then stable row id; equal-name rows are never deduplicated. Every `event_experts` write locks its affected expert row or rows first and the parent event second; every `event_speakers` write and linked-expert publish/retire joins that same canonical expert→event serialization order. Each command re-reads expert lifecycle plus both speaker tables and revalidates the combined visible slots before commit.
- **Publish completeness.** Drafts may be incomplete only as defined by the authoring matrix. Publication applies that matrix; no relationship is required except a project's exactly one active `curator` linked to a published, non-retired expert.
- **Published-project curator invariant.** A published project has exactly one eligible curator at every committed state. Publication, curator-link mutations, curator replacement and expert lifecycle mutations share LD-4's expert-first lock order and revalidate after locking. Retiring that expert or retiring/demoting the sole curator link is refused until an atomic replacement succeeds or the project itself is retired.
- **Fresh lifecycle consent.** Retire or restore confirmation is valid only for the exact server-signed dependency snapshot shown in `LifecycleImpact`; a target edit, incident-relation change, opposite-endpoint eligibility change or overlapping serialization conflict requires a new preview.
- **Expert PD is erasable without deleting its row.** Ordinary retire/restore remains reversible and keeps expert payload/media. The separate ADR-0009 path blocked on #1305 retains stable row/timestamps as a minimized retained tombstone but erases expert fields/media, every explicitly mapped legacy-speaker `name`/`regalia` copy and active idempotency replay content; relation rows remain only in their legally classified post-erasure shape. It deletes every normalized media object version/derivative and purges or invalidates the CDN key. If the expert is sole curator of a published project, execution requires an explicit resolution per project: atomically install an eligible replacement or retire that project; it never leaves an invalid published project. It mandates a keyed old-slug reservation digest, never heuristic name matching, and makes the erased expert non-restorable with 409 `PD_ERASED`. #1240 approves the taxonomy/product package only; #1305 must record fresh explicit Product Lead and Legal/Compliance sign-off on the exact retention/erasure policy before migration.
- **No stub seam.** Schema, migrations, API, generated SDK, Refine UI and browser wiring ship as real vertical slices. Seeds, fake repositories, placeholder selectors or manual DB steps do not satisfy an EARS clause.
- **Retained, bounded idempotency records.** An idempotency claim is `active` for the 24 h replay window and uses design §6's fenced request-owner and separate orphan-cleanup leases. Its active scope contains only a purpose-keyed actor digest plus method/route template, never a raw admin `sub`; PD-bearing cached responses add sorted active-only `pd_subject_refs`. Expiry UPDATEs it to `status='expired'` plus `deleted_at` and independently clears response payload/headers, request fingerprint, upload digest/object key, actor digest, `pd_subject_refs` and every other content-bearing input at the 24 h boundary; approved erasure performs the same fenced minimization early for matching subject claims. The tombstone retains only the keyed request-key digest, method/route template, terminal lifecycle fields and a non-content cleanup handle while cleanup remains pending. It is never TTL-deleted, reactivated or reused, and recurring reconciliation keeps checking abandoned/expired media claims until no unreferenced object remains, including a late stale-owner PUT.

## Prior decisions

- **ADR-0003 §4:** every application-owned entity and relationship is retained; normal reads filter `deleted_at IS NULL`, historical/restore reads opt in, and all FKs are restrictive.
- **ADR-0002 §§3–4, 9:** Zod is the request/response SSOT, REST is versioned under `/v1`, public growing lists use opaque cursors, admin tables may use offset pagination, mutation errors are RFC 7807 and mutations are idempotent.
- **ADR-0009 §§3, 7:** every new PD-bearing table is classified before migration with legal basis, retention, retained-row erasure mechanism, audit exception and owner; non-exempt PD is erased within 30 days while its Postgres tombstone remains.
- **ADR-0004 §3:** taxonomy editing extends the existing Refine admin through custom data/auth/access providers; it does not create a second backend or use Payload CMS.
- **ADR-0013 + AGENTS.md §6:** implementation runs the design-system-first gate; interaction states and token discipline come from `@ds/design-system`.
- **Feature 007:** the current event aggregate owns `specialties[]` and ordered `event_speakers`; 012 adds taxonomy beside it and changes speaker reconciliation from physical replacement to stable retained rows.
- **Feature 010:** every taxonomy entity/join and migrated speaker-domain table receives the generic audit trigger, so its mutations append attributed `data.<table>.<op>` rows without a taxonomy-specific audit implementation. Retained technical coordination tables stay audit-excluded only through feature 010's explicit allowlist and own constrained lifecycle proof.
- **Feature 011 EARS-10/11:** every admin route accepts only the dedicated MFA-verified admin session and state-changing routes require CSRF double-submit. #1304 aligns ADR-0001/011 inline and supplies token-free high-stakes authority revalidation because the shipped admin session intentionally stores no IdP access/refresh token.

## Lead technical decisions

- **LD-1 — optimistic versioning and lifecycle-snapshot binding.** ADR-0002 requires idempotency but does not prevent two different valid requests from overwriting one another. Every mutable taxonomy/speaker row therefore carries a monotonic `version`, returned as an ETag. Create endpoints require no `If-Match`; PATCH, publish, retire and restore require the target ETag; curator replacement requires the project ETag; `EraseExpertPd` and `EraseLegacySpeakerPd` require the subject expert or speaker ETag. A lifecycle preview additionally returns a signed opaque `impactToken` over transition, target identity/version, issued-at/15-minute expiry and the canonical versions and lifecycle/public-eligibility inputs of every incident relation and opposite endpoint. Retire/restore confirmation runs at `SERIALIZABLE`, recomputes that dependency fingerprint and requires `Lifecycle-Impact-Token`; a target/dependency mismatch, tampered/expired token, wrong transition/target or serialization abort returns 412 `LIFECYCLE_IMPACT_STALE` without mutation and is never auto-retried.
- **LD-2 — stable merged-speaker ordering and serialization.** `position` is the editorial order. The total tie-break is `position ASC`, source rank (`expert` before `legacy`), stable row id ASC; the write path also rejects a conflicting visible slot except when a mapped expert deliberately takes the suppressed legacy row's position. Every 012 `event_experts` create/update/retire/restore locks every old/new affected expert in stable-id order before the parent `events` row, then re-reads expert lifecycle and both child tables before recomputing the projection; every 007 legacy-speaker reconciliation locks that same event boundary. Expert publish/retire already owns its expert lock, then locks every linked parent event in stable-id order and performs the same revalidation because it can reveal an unpaired expert or a matched legacy fallback. The global order remains expert→project→event. This makes every committed read deterministic without name-based behavior or a cross-table uniqueness race.
- **LD-3 — permanent slug lock after first publication.** `first_published_at` is set once in the same transaction as the first publish and never cleared. This distinguishes a restored former publication from a never-published draft and enforces the owner-approved permanent slug identity without inferring history from current status.
- **LD-4 — atomic curator replacement with shared lock order.** Curator-affecting commands lock every affected expert row in stable-id order first, then project rows in stable-id order, then `project_experts` rows; they re-read eligibility and relations only after those locks. `ReplaceProjectCurator(projectId, expertId)` locks the current and candidate experts plus the project, verifies the candidate is still published/non-retired, demotes the previous curator relation to `member`, then promotes or restores the target relation in the same transaction. This order satisfies the immediate partial unique index; if promotion fails, transaction rollback restores the former curator. Expert lifecycle commands lock the expert, re-query its current curator projects, lock them in stable-id order and revalidate before changing status. No committed state has zero or two eligible curators, including under replacement-versus-retirement races.
- **LD-5 — token-free live authority revalidation.** Every 012 admin mutation first passes local dedicated-session/fingerprint/MFA/CSRF checks, then calls #1304's `IdpClient.revalidateAdminAuthority({ zitadelSessionId, sub })` with service authentication before validation, idempotency ownership, upload or handler entry. Inactive/missing/mismatched provider session is 401 `ADMIN_SESSION_REQUIRED`; current-role loss is 403 `PLATFORM_ADMIN_REQUIRED`; timeout, transport, 429, provider 5xx, service-auth/config failure or malformed provider shape is 503 `IDP_REVALIDATION_UNAVAILABLE`, leaves the local session intact and makes no side effect.
- **LD-6 — retained expert PD erasure boundary.** #1305 blocks the expert migration until fresh explicit Product Lead and Legal/Compliance sign-off records the ADR-0009 lawful basis, term, audit exception and owner. Before any expert migration it inventories historical `audit_ledger` `data.event_speakers.*` diffs for plaintext `name`/`regalia`; every hit is legally classified and remediated through an approved feature-010/ADR-0009 append-only-safe encryption or crypto-shred mechanism so raw ledger output contains no unclassified plaintext, with any lawful retention exception carrying its exact term, owner and compatible per-row audit-retention encryption. The command accepts an explicit resolution for every published project where the subject is sole curator: atomically replace that curator with an eligible expert or retire the project and remove it from public surfaces while retaining its joins. It sets `status='retired'`, `deleted_at`/`pd_erased_at`, `slug='erased-<stable-id>'`, `name='[erased]'`, `professional_role=NULL`, `credentials=NULL`, `affiliation=NULL`, `bio=NULL`, `photo_ref=NULL` and a mandatory non-null keyed old-slug reservation digest; mapped legacy rows become `retired` with non-null `deleted_at`/`pd_erased_at`, `name='[erased]'` and `regalia=''`, and cannot be restored or repopulated. Every PD-bearing idempotency response records active-only sorted `pd_subject_refs`; erasure finds every claim containing the expert, advances its fence, expires it and clears replay/fingerprint/upload/target/actor/subject content so a paused owner cannot restore PD and every later key use returns `IDEMPOTENCY_KEY_REUSED`. It preserves stable ids/lifecycle timestamps and the legally classified post-erasure join shape, and uses durable cleanup jobs for every photo version/derivative/CDN key. SQL `audit_pd_columns()` and TS `AUDIT_PD_COLUMNS` list every expert PD column plus `event_speakers.name`/`event_speakers.regalia`, with parity/no-plaintext proof, before any further affected write. Ordinary retire does none of this; heuristic name matching is forbidden.
- **LD-7 — complete replica, linkage and legacy-subject boundary.** #1305 classifies every `event_experts`/`project_experts` field and endpoint link, the whole legacy `event_speakers.name`/`regalia` table, public JSON/HTML/page/card/CDN caches, optional search/index replicas, logs and metrics. Expert erasure retires its joins, clears `legacy_speaker_id`, sets free-text event role to `[erased]`, and leaves stable endpoint ids/position only under the signed pseudonymous operational-evidence basis/term; an explicit `EraseLegacySpeakerPd(eventSpeakerId, approvedRequestId)` handles a legacy-only person without name matching and sets the same irreversible `pd_erased_at` speaker tombstone. The database transaction writes tombstones and durable jobs; the request stays `executing` until object/CDN/cache/index acknowledgements arrive and red-team marker scans find no plaintext, then completes within 30 days. The permanent slug reservation is `HMAC-SHA-256` under a stable non-exportable Vault purpose DEK whose wrapping KEK rotates without changing digests; a unique index plus one candidate-digest transaction lock serializes readable-slug/reservation conflict checks while raw old slugs remain unrecoverable.
- **LD-8 — retained committed-media cleanup.** #1283 owns one `media_cleanup_jobs` technical table distinct from idempotency claim cleanup. It uses retained `status: active | expired`, `execution_state: pending | processing | completed`, nullable `deleted_at`, monotonic fenced `lease_epoch` and bounded leases. A committed replace/clear transaction records the old server-generated object/CDN keys plus entity/slot pointer; a worker rechecks references and retries until every version/derivative and CDN key is acknowledged absent. Completion atomically sets `expired` + `deleted_at`, clears raw keys, endpoint pointer, lease/error content and retains only job id, cleanup kind, outcome and timestamps; no row is deleted/reactivated. The domain reference change remains feature-010 audited, while `media_cleanup_jobs` is an explicit tested technical-table audit exclusion; #1305 classifies its active expert-scoped linkage and erasure acknowledgement.

## Event Model

### Commands

- `CreateTaxonomyEntity(kind, fields)` / `UpdateTaxonomyEntity(kind, id, fields)` — create a `draft` entity or edit the same retained row.
- `PublishTaxonomyEntity(kind, id)` — `draft → published`, after validating its public projection.
- `PreviewLifecycleImpact(target, transition)` — return the currently visible related projections that retire would remove or restore would add plus the signed `impactToken` for that complete dependency snapshot.
- `Retire(target, impactToken)` / `Restore(target, impactToken)` — explicit lifecycle transitions with no cascade; both require the matching `Lifecycle-Impact-Token`, ordinary entity restore targets `draft`, join restore targets `active`, and an expert with `pd_erased_at IS NOT NULL` refuses restore with 409 `PD_ERASED`.
- `CreateRelationship(kind, endpoints, attributes)` / `UpdateRelationship(id, attributes)` — create or change one retained join; `event_experts` accepts `role`, `position`, and optional `legacySpeakerId`.
- `ReplaceProjectCurator(projectId, expertId)` — replace a published project's curator atomically; no retire/demote gap is exposed.
- `EraseExpertPd(expertId, explicitLegacySpeakerIds, approvedRequestId, curatorResolutions)` — execute approved retained-row erasure over only the explicitly enumerated mapped legacy rows and only after every sole-curator project has an explicit eligible replacement or explicit project-retire resolution; all resolutions, lifecycle effects and PD scrubbing commit atomically.
- `EraseLegacySpeakerPd(eventSpeakerId, approvedRequestId)` — erase one explicitly identified legacy-only person's retained `name`/`regalia` without an expert id or name-based search, set its irreversible `pd_erased_at` tombstone and reject later restore/repopulation with 409 `PD_ERASED`.

Every mutating HTTP endpoint requires `Idempotency-Key` as one canonical UUID. Missing/blank is 428 `IDEMPOTENCY_KEY_REQUIRED`; malformed/non-canonical is 400 `IDEMPOTENCY_KEY_INVALID`. POST create requires no `If-Match`; PATCH/publish/retire/restore require the target ETag; replace-curator requires the project ETag; `EraseExpertPd` and `EraseLegacySpeakerPd` require the subject expert or speaker ETag. Retire/restore additionally require `Lifecycle-Impact-Token` from their transition-specific preview.

### Events

| Event                                                      | Meaning                                                                                                                                                                                            |
| ---------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `TaxonomyEntityCreated/Updated/Published/Retired/Restored` | One entity changed state or content; feature 010 records the row diff in the same transaction.                                                                                                     |
| `TaxonomyRelationshipCreated/Updated/Retired/Restored`     | One explicit relationship changed; no endpoint or sibling relation changes with it.                                                                                                                |
| `EventSpeakerMatched`                                      | An `event_experts` row now explicitly references one retained legacy speaker; ordinary matching leaves that row unchanged, while a later approved ADR-0009 erasure may scrub its `name`/`regalia`. |
| `ProjectCuratorReplaced`                                   | One transaction demotes the former curator, then promotes the eligible replacement; rollback preserves the former curator on failure.                                                              |
| `ExpertPdErased`                                           | ADR-0009 erases identifying expert/explicit legacy/replay values and media while retaining minimized DB tombstones.                                                                                |

### Read models

- `TaxonomyAdminList/Detail` — all authoring fields, status, version and relationship summaries; offset/page pagination, search and explicit retained filters.
- Full public entities are exact: `PublicProject { id, slug, kind, title, description, coverUrl }`; `PublicExpert { id, slug, name, professionalRole, credentials, affiliation, bio, photoUrl, initials }`; `PublicTopic { id, slug, title }`; `PublicPartner { id, slug, title, logoUrl, websiteUrl }`; optional URLs are present and nullable.
- Exact summaries are `PublicEventSummary { id, slug, title, school, startsAt, state }`, `PublicProjectSummary { id, slug, kind, title, coverUrl }`, `PublicExpertSummary { id, slug, name, professionalRole, photoUrl }`, `PublicTopicSummary { id, slug, title }`, and `PublicPartnerSummary { id, slug, title, logoUrl, websiteUrl }`. Bidirectional items use those summaries; only event↔expert adds `{ role, position }` and project↔expert adds `{ role: curator | member }`.
- `PublicEventPageSpeaker` is exactly legacy `{ source: legacy, name, credentials }` or expert `{ source: expert, expertId, expertSlug, name, credentials, photoUrl, role }`; `photoUrl` is present/nullable. One resolver feeds both this ordered page/endpoint union and `UpcomingBroadcastCard.speakers[] { name }`.
- `LifecycleImpact` — transition, target id/version, affected currently-public event/project/expert/topic/partner identifiers and opaque signed `impactToken`; it contains no hidden record content.

### Policies

- Slugs and logical endpoint pairs remain unique across retained rows; a duplicate create returns a conflict and points the operator to the retained row for restore. Slug mutability is determined only by `first_published_at`.
- A project has at most one active `curator`; a published project has exactly one eligible curator and changes it only through the atomic replacement command. Other project experts are `member`. A legacy speaker may be matched by at most one retained `event_experts` row, and the speaker must belong to the same event.
- Topic assignment always selects an existing non-retired topic. `specialties[]` is never read from or written to `topics`.
- Media binaries use the existing object-storage abstraction; public DTOs expose CDN URLs, never storage keys. Retiring/restoring a row never deletes its media.

## EARS requirements

> Flat numbering per ADR-0006 §4. Every clause realizes one or more PRD stories and is covered by `012-scenarios.feature`.

- **EARS-1** _(realizes: US-1, US-9)_ — When a `platform_admin` creates or edits a project through its Refine resource, the system shall validate the authoring matrix and persist one first-class retained `projects` row with stable id/slug/version, kind `school | media | program`, title, description and optional cover reference, and render that same row on list/detail; a project shall never be an event string or second copy.
- **EARS-2** _(realizes: US-2, US-9)_ — When a `platform_admin` creates or edits an expert through its Refine resource, the system shall validate the authoring matrix and persist one standalone editorial `experts` row with stable id/slug/version, name, professional role, credentials, affiliation, bio and optional shared-normalizer photo reference, with initials fallback and no required platform-user link or parallel expert type. It shall consume #1305's approved ADR-0009 classification: normal retire/restore keeps payload/media, while approved PD erasure preserves minimized retained DB tombstones, clears/replaces every expert, explicitly mapped legacy-speaker and active-replay PD copy plus photo objects, mandatorily reserves the old slug by keyed digest, and makes restore return 409 `PD_ERASED`; SQL/TS audit-mask parity shall prove no expert PD old/new value enters `audit_ledger` plaintext. Approved erasure of a legacy-only speaker shall target one stable `eventSpeakerId`, set the same irreversible retained speaker tombstone and never select another row by name.
- **EARS-3** _(realizes: US-5, US-9)_ — When a `platform_admin` creates or edits a topic through its Refine resource, the system shall persist one curated `topics` row with stable id/slug/version and title; topics shall never be free-form event tags.
- **EARS-4** _(realizes: US-6, US-9)_ — When a `platform_admin` creates or edits a partner through its Refine resource, the system shall persist one descriptive `partners` row with stable id/slug/version and title plus optional logo reference and optional HTTPS website URL; commercial terms and contacts are not fields of the public contract.
- **EARS-5** _(realizes: US-1, US-2, US-5, US-6, US-10, US-12)_ — When an operator publishes a valid `draft` entity, the system shall validate the exact field matrix, lock its slug permanently by setting `first_published_at` once, and transition it to `published`; only a project additionally requires exactly one active `curator` linked to a published, non-retired expert, and it may have zero events/partners while every other kind may have zero relationships. Public list/detail shall then expose only the kind allow-list and CDN media URLs, while incomplete drafts, retired rows and internal fields/storage keys remain absent and indistinguishable from unknown. Any later PATCH that would make a published projection incomplete shall return 409 `PUBLISH_REQUIREMENTS_NOT_MET` without changing its value, version or audit history.
- **EARS-6** _(realizes: US-4, US-11)_ — When an operator links an event and a project, the system shall create or restore one `event_projects` row, allow one event to have several projects, expose event→projects and project→events reads, and never modify the event or project lifecycle as a side effect.
- **EARS-7** _(realizes: US-3, US-8)_ — When an operator links an expert to an event, the system shall persist one `event_experts` row with required event-specific role, non-negative position and optional explicit `legacySpeakerId`; a supplied legacy id shall resolve to one retained speaker of that same event and be unique across retained expert links, the command shall never infer a match from a name, and every expert-link write shall lock affected experts before the parent event, re-read lifecycle and both speaker tables, and reject a conflicting combined visible slot with 409 `SPEAKER_POSITION_OCCUPIED`.
- **EARS-8** _(realizes: US-2, US-3, US-8, US-10)_ — When a public event speaker projection is read, the system shall merge active linked experts with active legacy rows using LD-2's total order: an eligible published expert supersedes only its explicitly matched legacy row, while unmatched rows and fallback for a draft/retired/unlinked expert remain; ordinary matching shall not overwrite, retire or name-deduplicate any legacy row, with only the separately approved ADR-0009 erasure allowed to scrub an explicitly mapped row's `name`/`regalia`. One canonical resolver shall feed `/events/:key/speakers`, the exact `PublicEventPageSpeaker` union and the thinner `UpcomingBroadcastCard.speakers[] { name }`, so shipped public surfaces cannot disagree.
- **EARS-9** _(realizes: US-1, US-2, US-11)_ — When an operator links an expert to a project or replaces a published project's curator, the system shall persist retained `project_experts` rows with `curator | member`, enforce at most one active curator, perform replacement as one version-checked transaction using LD-4's shared expert/project lock order and post-lock eligibility check, preserve exactly one eligible curator for every published project under concurrent expert lifecycle changes, and expose project→experts and expert→projects reads with the role.
- **EARS-10** _(realizes: US-6, US-11, US-12)_ — When an operator links a partner to a project, the system shall persist one `project_partners` row and expose project→partners and partner→projects public reads using only partner title, logo URL and website URL; commercial/internal data shall never enter the projection.
- **EARS-11** _(realizes: US-5, US-11)_ — When an operator tags an event, the event form shall offer only existing non-retired topics, provide no inline creation, persist one `event_topics` row per pair, expose both directions, and leave `specialties[]` byte-for-byte unchanged.
- **EARS-12** _(realizes: US-10, US-11, US-12)_ — When a public caller reads taxonomy collections or either direction under `/v1/public`, the system shall query the same authored rows, return only the exact full/summary/relationship item DTOs above, apply published/active/non-deleted allow-lists at every hop, use opaque cursor pagination with `{ data, pagination: { nextCursor, hasMore } }`, return no duplicate pair, and never leak a draft, retired endpoint, inactive join or admin-only field. An unknown/ineligible source shall be 404 `RESOURCE_NOT_FOUND`; an eligible source with no eligible relations shall be 200 with empty data and terminal pagination.
- **EARS-13** _(realizes: US-7)_ — When an operator requests retirement of an entity or relationship, the admin shall first show transition-specific `LifecycleImpact` and retain its signed `impactToken`; confirmation shall require the same target `If-Match` plus `Lifecycle-Impact-Token`, and the server shall transactionally reject a changed target/relation/endpoint dependency snapshot with 412 `LIFECYCLE_IMPACT_STALE`. It shall refuse retirement/demotion of the sole eligible curator expert/link of a published project, otherwise set `retired` + `deleted_at` once, preserve every row/FK, change no related lifecycle state, and remove the target from default selectors/current public projections only by filtering.
- **EARS-14** _(realizes: US-7, US-8)_ — When an operator restores a retained entity or relationship, the admin shall first show transition-specific `LifecycleImpact` and retain its signed `impactToken`; confirmation shall require the same target `If-Match` plus `Lifecycle-Impact-Token`, and the server shall reject a changed dependency snapshot with 412 `LIFECYCLE_IMPACT_STALE`. For an expert with `pd_erased_at IS NOT NULL`, the admin shall expose no restore control and a direct attempt shall instead return 409 `PD_ERASED` with zero side effect; otherwise the system shall clear `deleted_at` and transition an entity to `draft` or a join to `active`. Detail and explicit `includeRetired` reads address the same stable row, while defaults still exclude retained rows. No HTTP Delete route or Delete control shall exist. Separately, the feature-007 editor exposes no restore control for a migrated legacy speaker with `pd_erased_at IS NOT NULL`, and a direct restore or payload-repopulation attempt returns 409 `PD_ERASED` with zero side effect.
- **EARS-15** _(realizes: US-9)_ — When an operator lists a taxonomy resource, the admin API and Refine table shall support bounded page/offset pagination, total, case-insensitive title/name/slug search and explicit status/`includeRetired` filters; retired entities shall not appear in new-link selectors, and empty results shall be a successful empty page.
- **EARS-16** _(realizes: US-1, US-2, US-3, US-4, US-5, US-6, US-7, US-8, US-9, US-12)_ — Per feature 011 EARS-10/11, every admin route shall accept only the dedicated MFA-verified admin session and every mutation shall pass CSRF plus #1304's token-free `IdpClient.revalidateAdminAuthority({ zitadelSessionId, sub })` before validation/idempotency/upload/handler, while public reads remain zero-auth `public`. Security-floor refusals shall preserve non-disclosure: 401 `ADMIN_SESSION_REQUIRED` for absent/wrong/expired/fingerprint/MFA/CSRF or inactive/missing/mismatched provider session; 403 `PLATFORM_ADMIN_REQUIRED` for current-role loss; 503 `IDP_REVALIDATION_UNAVAILABLE` for provider transport/timeout/429/5xx/service-auth/config/malformed-shape failure, with the local session intact and zero side effect. All failures shall be RFC 7807 Problem Details with `traceId` and the exact `errorCode`: 400 `VALIDATION_FAILED | MEDIA_INVALID | MEDIA_INPUT_CONFLICT | CURSOR_INVALID | IDEMPOTENCY_KEY_INVALID`; 404 `RESOURCE_NOT_FOUND`; 409 `RELATIONSHIP_CONFLICT | SLUG_CONFLICT | SLUG_IMMUTABLE | PUBLISH_REQUIREMENTS_NOT_MET | PUBLISHED_PROJECT_REQUIRES_CURATOR | INVALID_TRANSITION | LEGACY_SPEAKER_CONFLICT | SPEAKER_POSITION_OCCUPIED | PD_ERASED | IDEMPOTENCY_KEY_REUSED | IDEMPOTENCY_REQUEST_IN_PROGRESS`; 412 `PRECONDITION_FAILED | LIFECYCLE_IMPACT_STALE`; 415 `UNSUPPORTED_MEDIA_TYPE`; 428 `IDEMPOTENCY_KEY_REQUIRED | PRECONDITION_REQUIRED | LIFECYCLE_IMPACT_REQUIRED`; 503 `MEDIA_STORAGE_UNAVAILABLE | IDP_REVALIDATION_UNAVAILABLE`.
- **EARS-17** _(realizes: US-7, US-10, US-11)_ — The system shall require one canonical UUID `Idempotency-Key` on every mutating HTTP endpoint; absent/blank is 428 `IDEMPOTENCY_KEY_REQUIRED` and malformed/non-canonical is 400 `IDEMPOTENCY_KEY_INVALID`, both before upload, ownership, domain or audit side effects. The fingerprint shall include concrete target parameters, canonical JSON/normalized-output digest, `If-Match` and `Lifecycle-Impact-Token`; changed semantic input or a different normalized output/digest under the same key is 409 `IDEMPOTENCY_KEY_REUSED`. During the 24 h active window the scope shall store only a purpose-keyed actor digest plus method/route template, never raw `sub`, and each request/cleanup lease acquisition shall increment monotonic `lease_epoch`; heartbeat and completion are conditional on owner+epoch+purpose. Every deterministic post-claim completion—including 409/412 refusals—is fenced and stores exact status/body plus allowed `ETag`/`Location` in the same transaction as any domain/audit writes, so same-key retries replay the same outcome and a stale owner rolls everything back; PD-bearing responses additionally store sorted active-only `pd_subject_refs` so approved erasure can fence and minimize every relevant claim. Provider/DB faults without a trustworthy terminal verdict remain explicitly takeover-eligible. Request takeover alone may HEAD/reuse/upload and resume the command; a separately claimed cleanup lease never enters the domain handler and only removes an unreferenced claim object/marks abandonment. At 24 h, independently of object-storage availability, expiry shall UPDATE the row to `expired` + `deleted_at` and clear response payload/headers, request fingerprint, upload digest/object key, actor digest, `pd_subject_refs` and all content inputs. It shall retain only the keyed request-key digest, method/route template, terminal lifecycle fields and a non-content cleanup handle while pending, without delete/reactivate/reuse; recurring reconciliation shall recheck abandoned/expired claims until no unreferenced claim object remains, including a late stale-owner PUT, and every later key use in that method/route scope is 409 `IDEMPOTENCY_KEY_REUSED`. This claim cleanup is distinct from LD-8's retained old-reference cleanup required on committed media replace/clear. Per LD-1, method-specific ETag preconditions prevent lost writes; LD-2/LD-4 commands serialize and revalidate shared dependencies. Every committed taxonomy entity, relationship or speaker-domain mutation receives feature 010 audit capture in the same transaction; `idempotency_keys` and `media_cleanup_jobs` mutations remain feature 010's explicit parity-tested technical-table audit exclusions.
- **EARS-18** _(realizes: US-1, US-2, US-3, US-4, US-5, US-6, US-7, US-8, US-9)_ — Before any new or changed taxonomy/event-admin UI slice starts, the team shall complete Stage A: run `build-ui-from-design-system`, present 2–3 concrete Refine compositions and record the product-owner choice; implementation shall use `@ds/design-system` primitives with full states and no Delete UI, and the real result shall pass live-stand Playwright plus owner Stage-B confirmation before merge.

## Invariants

- No taxonomy entity, join or migrated legacy speaker row is physically deleted or cascade-deleted; stable ids/slugs/pairs are never reused.
- A slug is editable only while `first_published_at IS NULL`; retirement and restore never reset that permanent identity lock. The sole exception is ADR-0009 expert-PD erasure, which replaces readable identity with a minimized retained tombstone while a mandatory keyed digest prevents old-slug reuse.
- `retired ⇔ deleted_at IS NOT NULL`; ordinary entity restore yields `draft`, ordinary join/migrated-speaker restore yields `active`, and an erased expert or migrated legacy speaker returns 409 `PD_ERASED`.
- Every published project has exactly one active curator whose expert is published and non-retired; curator replacement is atomic and direct invalidation is refused.
- Every committed event speaker projection has at most one visible row per position; 012 expert-speaker writes lock affected experts before the event, while 007 legacy-speaker writes and linked-expert publish/retire share those affected per-event boundaries under the global expert→project→event order.
- Retire and restore confirmation are accepted only against the unchanged transition-specific signed dependency snapshot that the operator saw.
- A public relationship is visible only when the join is active and every taxonomy endpoint is published and non-retired.
- A matched legacy speaker remains stored and unchanged under ordinary matching/lifecycle; the only value-erasure exception is an approved ADR-0009 command over explicitly mapped `event_speakers.name`/`event_speakers.regalia`, whose `pd_erased_at` tombstone cannot be restored or repopulated, and an explicit eligible mapping remains the only projection-suppression rule.
- `specialties[]` and topics are different axes and never synchronize.
- One authored Postgres row feeds admin and public projections; no export/sync/fake seam exists.
- Expert product retirement is reversible; lawful PD erasure is distinct, preserves DB tombstones, resolves every sole-curator project by atomic replacement or retirement, scrubs every explicitly linked copy/media/replay, and leaves neither an invalid published project nor unclassified plaintext PD in current or historical audit evidence.
- Idempotency rows use fenced request/cleanup leases, expire by retained lifecycle UPDATE, clear every payload/fingerprint/upload reference, and are never physically deleted or reused; per feature 010's explicit allowlist they do not produce domain-audit rows.
