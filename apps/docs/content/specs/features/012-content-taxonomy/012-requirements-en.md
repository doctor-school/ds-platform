# 012 — Content taxonomy (Requirements)

## Outcomes

- A content operator describes a project, expert, topic or partner once and reuses the same retained record everywhere.
- Events relate to several projects, experts and topics through real many-to-many rows; projects relate to experts and partners in both directions.
- An expert is one standalone editorial record. `project_experts.role` is `curator | member`; `event_experts` carries the event-specific role, position and optional explicit match to one legacy speaker row.
- Existing free-text speakers continue to render during gradual migration. A linked, published expert replaces only the explicitly matched legacy row in the current projection; there is no name matching, deduplication, overwrite or implicit retirement.
- Operators create, search, edit, publish, retire and restore taxonomy data in the existing Refine admin. No Delete action exists.
- Later Academy surfaces read publish-safe taxonomy records and every relationship direction through `/v1` REST; no copy, export or synchronization step exists.

## Scope

**In:**

- Top-level retained entities:
  - `projects`: stable id + slug, kind `school | media | program`, title, description, optional cover-media reference;
  - `experts`: stable id + slug, name, professional role, credentials, affiliation, bio, optional photo-media reference; no platform-user foreign key in 012;
  - `topics`: stable id + slug and title, maintained as a curated list;
  - `partners`: stable id + slug, title, optional logo-media reference and optional website URL.
- Common entity fields: `status: draft | published | retired`, nullable `deleted_at`, nullable set-once `first_published_at`, monotonic `version`, and timestamps. Create starts in `draft`; ordinary restore returns an entity to `draft` without clearing `first_published_at`. Expert restore additionally requires `pd_erased_at IS NULL`; erased expert PD is the explicit 409 `PD_ERASED` exception.
- Retained joins: `event_projects`, `event_experts`, `project_experts`, `project_partners`, `event_topics`; each has a stable id, `status: active | retired`, nullable `deleted_at`, `version`, timestamps and a uniqueness constraint for its logical endpoint pair. `project_partners` additionally carries `is_primary`; at most one active link per project is primary, while any number of non-primary links preserves the approved many-to-many model.
- `event_experts`: required event-specific `role`, non-negative `position`, and nullable unique `legacy_speaker_id`. The #1278 retained-row runtime prerequisite replaces `event_speakers`' old `(event_id, position)` primary key with stable UUID `id` row identity, adds partial active-slot `UNIQUE(event_id, position) WHERE status='active'` plus explicit `UNIQUE(event_id,id)`, and supplies retained lifecycle fields including nullable `pd_erased_at`. This enables old and replacement occupants of one position to coexist as retained/active rows, makes the same-event composite FK `(event_id,legacy_speaker_id) → event_speakers(event_id,id)` executable, and makes an approved erased legacy row non-restorable/repopulatable.
- Refine resources for entity list/detail/create/edit and lifecycle actions; relationship editors on the relevant event/project forms; search and explicit retained-row filters; plus the separate ADR-0009 compliance-queue detail that shows a server-derived editorial erasure plan and collects only per-project curator resolution before `pd_officer` approval.
- Publish-safe public entity reads, bidirectional relationship reads and the merged current speaker projection.

**Out:**

- Doctor-facing rendering: `/`, `/webinars` facets/archive, `/projects`, `/experts` and their detail pages belong to 013–016.
- `event_recordings`, `leads`, Payload CMS, partner commercial terms/contracts, public taxonomy search, recommendation/ranking, bulk speaker migration, expert self-service, or a user↔expert identity link.
- New roles for ordinary taxonomy authoring; it reuses `platform_admin`. The separate ADR-0009 erasure queue is not a taxonomy-admin action and consumes the prerequisite ADR-required `pd_officer` + fresh-step-up policy from #1304/#1305.
- A general audit-history browser. Feature 010 already captures mutations in `audit_ledger`; 012 only keeps retained rows explicitly addressable for inspect/restore.

## Authoring and publication contract

| Kind    | Required on create                                        | Additional fields required to publish                                                                        | Optional fields                 |
| ------- | --------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ | ------------------------------- |
| Project | `title` (trimmed 1–160); `slug` is generated when omitted | `kind: school \| media \| program`, `description` (trimmed plain text 1–2000), exactly one eligible curator  | `cover_ref`                     |
| Expert  | `name` (trimmed 1–160); `slug` is generated when omitted  | `professional_role` (1–160), `credentials` (1–500), `affiliation` (1–240), `bio` (trimmed plain text 1–4000) | `photo_ref`; initials fallback  |
| Topic   | `title` (trimmed 1–120); `slug` is generated when omitted | no additional field or relationship                                                                          | none                            |
| Partner | `title` (trimmed 1–160); `slug` is generated when omitted | no additional field or relationship                                                                          | `logo_ref`, HTTPS `website_url` |

- Every authored slug is lowercase ASCII, 1–80 characters, matches `[a-z0-9]+(?:-[a-z0-9]+)*`, is not a canonical UUID and, for experts, does not start with reserved `erased-`. If create omits it, the server applies the canonical transliteration/slugification function to the display label and rejects a reserved/conflicting candidate rather than silently changing identity; the UI previews the same candidate. A retained/reservation conflict returns 409 `SLUG_CONFLICT`. Detail resolution treats canonical UUID text as id-only and every other token as slug-only, so `/:idOrSlug` is unambiguous. The first successful publication sets `first_published_at` once; any later slug change, including after retire/restore, returns 409 `SLUG_IMMUTABLE`.
- Drafts may leave only the table's additional publish fields unset. Omitted PATCH members stay unchanged; explicit `null` clears an optional field or a nullable draft-only incomplete field. A mutation of an already-published entity must leave its publication contract valid. A refused publish/update returns 409 `PUBLISH_REQUIREMENTS_NOT_MET` with field-addressed errors and makes no mutation.
- A project can publish with zero events and zero partners when its fields and curator are complete. Experts, topics and partners can publish with zero relationships. Optional media and partner website never block publication.
- Website input, when present, is an absolute HTTPS URL no longer than 2048 characters. Media input, when present, is one still JPEG, PNG or WebP, at most 10 MiB, at most 6000 px on either post-orientation decoded axis and at most 25 million aggregate decoded pixels; no minimum dimensions apply. Multi-frame/animated PNG or WebP and any decoder page/frame count other than one are 400 `MEDIA_INVALID` before full-frame allocation or upload. Refine performs the same preflight, while server validation is authoritative.
- A no-file create/PATCH is strict `application/json`; a media upload is `multipart/form-data` with one JSON `payload` part and at most the kind-specific `cover|photo|logo` file. Clients never submit storage refs/keys. PATCH omission keeps media, JSON `mediaAction: clear` clears it, and a file plus clear/multiple/wrong file parts is 400 `MEDIA_INPUT_CONFLICT`; multipart without a file is 415 `UNSUPPORTED_MEDIA_TYPE`. The first media vertical (#1283) owns one shared decoder/normalizer consumed by project covers, expert photos and partner logos: it applies orientation, converts to sRGB, and re-encodes the one still frame as canonical WebP under one pinned codec/profile version; that version and exact options enter the fingerprint. It strips EXIF/XMP/GPS/ICC/original filename and every ancillary block, derives MIME from normalized bytes, and persists no original upload. Object-storage failure is 503 `MEDIA_STORAGE_UNAVAILABLE` with no domain/audit mutation.
- The same #1283 vertical owns a retained `media_cleanup_jobs` queue distinct from claim-scoped upload cleanup. Every committed replace/`mediaAction: clear` writes a cleanup row for the superseded reference in the same transaction as the ref swap; its worker rechecks that the object is unreferenced, deletes every version/derivative, purges or invalidates the CDN key, retries until complete and retains a non-content tombstone after clearing raw keys. Expert erasure stays `executing` until its compliance cleanup jobs succeed; an unavailable store cannot silently complete erasure or lose the old key.
- Input-mask declaration: `none` for every 012 field, because these values are editorial text, a separately validated slug/URL/integer, or a file rather than a fixed-format identifier; a mask would fabricate or rewrite content instead of assisting entry. The admin therefore uses ordinary text/textarea controls with trim and character counters. Slug uses a generated preview plus pattern/length validation; website uses a URL control; `event_experts.position` uses an integer control with step 1 and range 0–32767; event role is trimmed 1–80 characters. File controls declare the accepted formats and reject size/dimension limits before submit.

## Constraints

- **Retained rows only.** No application path issues `DELETE`, `TRUNCATE`, data-bearing drop, `ON DELETE CASCADE`, or identifier reuse for these entities, joins or migrated `event_speakers`. Every foreign key is `RESTRICT`/`NO ACTION`.
- **Lifecycle consistency.** `retired` iff `deleted_at` is non-null; `draft`, `published` and `active` iff it is null. Ordinary entity transitions are `draft → published`, `draft|published → retired`, `retired → draft`; join and migrated-speaker transitions are `active → retired → active`. An expert or migrated legacy speaker with `pd_erased_at IS NOT NULL` is the explicit non-restorable exception. Retiring an entity never changes its joins.
- **Public default deny.** Public reads include only `published` entities with `deleted_at IS NULL`, `active` joins with `deleted_at IS NULL`, and events allowed by the existing public-event policy. A draft, retired or unknown public id produces the same 404 shape.
- **Explicit retained reads.** Admin lists default to non-retired entities / active joins. Retained rows appear only through an explicit status or `includeRetired=true` query; an admin detail by stable id remains addressable for restore.
- **One current speaker projection.** An active mapping suppresses its matched legacy row only when the linked expert is published and non-retired. Otherwise the legacy fallback remains. Rows sort by `position ASC`, then source rank (`expert` before `legacy`), then stable row id; equal-name rows are never deduplicated. Every `event_experts` write locks its affected expert row or rows first and the parent event second; every `event_speakers` write and linked-expert publish/retire joins that same canonical expert→event serialization order. Each command re-reads expert lifecycle plus both speaker tables and revalidates the combined visible slots before commit.
- **Publish completeness.** Drafts may be incomplete only as defined by the authoring matrix. Publication applies that matrix; no relationship is required except a project's exactly one active `curator` linked to a published, non-retired expert.
- **Published-project curator invariant.** A published project has exactly one eligible curator at every committed state. Publication, curator-link mutations, curator replacement and expert lifecycle mutations share LD-4's expert-first lock order and revalidate after locking. Retiring that expert or retiring/demoting the sole curator link is refused until an atomic replacement succeeds or the project itself is retired.
- **Fresh lifecycle consent.** Retire or restore confirmation is valid only for the exact server-signed dependency snapshot shown in `LifecycleImpact`; a target edit, incident-relation change, opposite-endpoint eligibility change or overlapping serialization conflict requires a new preview.
- **Expert PD is erasable without deleting its row.** Ordinary retire/restore remains reversible and keeps expert payload/media. The separate ADR-0009 path is an asynchronous `erasure-execute` worker owned by #1306, never a taxonomy-admin Delete/erase POST. It consumes one locked, unexpired `erasure_requests` row whose immutable plan was freshly step-up-approved by a `pd_officer`, has no legal hold and atomically moves `approved → executing`; the job payload/idempotency key is only that request id. The plan derives all and only currently mapped legacy-speaker ids under locks, never accepts a caller list or heuristic name match, and resolves every sole-curator project by eligible replacement or project retirement. Execution retains exact expert/speaker/join tombstones, zeroizes purpose-separated external Vault keys so live/MVCC/WAL/backup copies are unreadable, cleans every media/cache/index replica and makes restore 409 `PD_ERASED`. #1240 approves only the taxonomy/product package; #1305 must first record fresh Product Lead and Legal/Compliance sign-off on the exact lawful basis, term, legacy-backup gate and erasure policy.
- **PD copies are encrypted and subject-fenced before use.** Expert logical fields/slug/media pointer, legacy-speaker `name`/`regalia`, `event_experts.role` and PD-bearing idempotency request/response content are stored as ciphertext under external purpose-scoped keys; lookup uses non-reversible purpose-keyed digests. Retained `pd_subject_fences` reserve subject digests/epochs at claim time before upload or handler work. Erasure closes the gate and advances the epoch before enumerating every processing/completed claim, so an omitted pre-response claim or concurrent acquisition cannot commit/replay PD. Future and historical audit handling covers every classified expert, speaker and `event_experts`/`project_experts` field/link, not only names.
- **No stub seam.** Schema, migrations, API, generated SDK, Refine UI and browser wiring ship as real vertical slices. Seeds, fake repositories, placeholder selectors or manual DB steps do not satisfy an EARS clause.
- **Retained, bounded idempotency records.** A canonical UUID key is globally reserved across actors/routes from first use, so its permanent non-PD digest remains sufficient after active actor/request content is cleared; cross-actor or cross-route reuse is always 409 `IDEMPOTENCY_KEY_REUSED`. A claim is `active` for the 24 h replay window, encrypts PD-bearing content under a claim DEK and uses fenced request-owner plus separate cleanup leases. Expiry/approved erasure UPDATEs the row to `expired` + `deleted_at`, closes replay, clears live actor/request/response/upload/subject/key references, and durably schedules service-only DEK destruction; no application decrypt path remains while Vault zeroization is retried to acknowledgement. A bounded upload authorization expires with its lease; cleanup retains the deterministic locator and waits past the maximum authorization plus clock-skew grace before its final HEAD/delete/absence decision, so no stale owner can PUT after completion. The row is never physically deleted, reactivated or reused.

## Lead technical decisions

- **LD-1 — optimistic versioning and lifecycle-snapshot binding.** ADR-0002 requires idempotency but does not prevent two different valid requests from overwriting one another. Every mutable taxonomy/speaker row therefore carries a monotonic `version`, returned as an ETag. Create endpoints require no `If-Match`; PATCH, publish, retire and restore require the target ETag; curator replacement requires the project ETag. A lifecycle preview additionally returns a signed opaque `impactToken` over transition, target identity/version, issued-at/15-minute expiry and the canonical versions and lifecycle/public-eligibility inputs of every incident relation and opposite endpoint. Retire/restore confirmation runs at `SERIALIZABLE` and recomputes that dependency fingerprint. For those two lifecycle methods, any target-ETag/token/dependency mismatch, tampered/expired token, wrong transition/target or serialization abort has precedence as 412 `LIFECYCLE_IMPACT_STALE`; 412 `PRECONDITION_FAILED` is reserved for a stale `If-Match` on non-lifecycle methods. Either deterministic refusal makes no domain/media/audit mutation but fenced-completes and replays its idempotency result; it is never auto-retried.
- **LD-2 — stable merged-speaker ordering and serialization.** `position` is the editorial order. The total tie-break is `position ASC`, source rank (`expert` before `legacy`), stable row id ASC; the write path also rejects a conflicting visible slot except when a mapped expert deliberately takes the suppressed legacy row's position. Every 012 `event_experts` create/update/retire/restore locks every old/new affected expert in stable-id order before the parent `events` row, then re-reads expert lifecycle and both child tables before recomputing the projection; every 007 legacy-speaker reconciliation locks that same event boundary. Expert publish/retire already owns its expert lock, then locks every linked parent event in stable-id order and performs the same revalidation because it can reveal an unpaired expert or a matched legacy fallback. The global order remains expert→project→event. This makes every committed read deterministic without name-based behavior or a cross-table uniqueness race.
- **LD-3 — permanent, disjoint slug identity.** `first_published_at` is set once in the same transaction as the first publish and never cleared. Authored slugs cannot be canonical UUIDs; expert slugs additionally cannot enter the reserved `erased-` namespace. UUID-shaped detail tokens resolve by id only and all others by slug only. Erasure locks both the old-slug reservation digest and deterministic tombstone candidate, so create-versus-erasure cannot collide.
- **LD-4 — atomic curator replacement with shared lock order.** Curator-affecting commands lock every affected expert row in stable-id order first, then project rows in stable-id order, then `project_experts` rows; they re-read eligibility and relations only after those locks. `ReplaceProjectCurator(projectId, expertId)` locks the current and candidate experts plus the project, verifies the candidate is still published/non-retired, demotes the previous curator relation to `member`, then promotes or restores the target relation in the same transaction. This order satisfies the immediate partial unique index; if promotion fails, transaction rollback restores the former curator. Expert lifecycle commands lock the expert, re-query its current curator projects, lock them in stable-id order and revalidate before changing status. No committed state has zero or two eligible curators, including under replacement-versus-retirement races.
- **LD-5 — ordinary-admin versus erasure authority.** Every ordinary 012 admin mutation first passes local dedicated-session/fingerprint/MFA/CSRF and #1304's exact token-free `IdpClient.revalidateAdminAuthority({ zitadelSessionId, sub, requiredRole })` with `requiredRole: 'platform_admin'`. The separate compliance approval uses the same interface with `requiredRole: 'pd_officer'`; `@Authz({ step_up: true })` requires fresh MFA within 30 minutes, and the token-free admin session records a server-verified elevated timestamp rather than storing an IdP token. Missing fresh elevation is 401 `STEP_UP_REQUIRED` with `stepUpUrl`; role loss is 403 `PD_OFFICER_REQUIRED`; provider unavailability remains 503 `IDP_REVALIDATION_UNAVAILABLE`. The worker itself accepts no human bearer/session and consumes only the approved request id.
- **LD-6 — encrypted subject/key and audit boundary.** #1305 blocks affected migrations until fresh Product Lead and Legal/Compliance sign-off fixes lawful basis, finite terms, owners and exact erasure. Logical expert identity/slug/media fields, legacy-speaker `name`/`regalia`, `event_experts.role` and PD-bearing claim content use AES-256-GCM ciphertext under external Vault purpose DEKs; Postgres stores only ciphertext, non-reversible lookup digests and opaque external key references. Expert and each legacy-only speaker extend ADR-0009's retained `subject_keys` contract plus a separate one-to-one `pd_subject_fences` gate; claims reference `subject_key_id`, never a second digest/key SoT. Physical `experts.name_search_tokens` is bounded sorted-unique `bytea[] NOT NULL DEFAULT '{}'::bytea[]` with 32-byte elements, at most 477 1–3-gram HMACs and `USING gin (name_search_tokens array_ops)` containment before bounded exact verification. Existing plaintext audit is not “fixed” by a view, compensating row or unrestricted update: #1305 must formally amend live feature 010 with retained `audit_pd_remediation_manifests`, a one-use manifest-bound SECURITY DEFINER transition that replaces only approved plaintext leaves by `{ masked: true, legacyCiphertextRef, preimageHash }`, and per-row `audit_retention_keys`; ledger identity/non-PD facts stay unchanged, DELETE stays forbidden, replay is impossible, and key destruction at the approved term makes the retained ciphertext unreadable. Future SQL/TS masks cover the exact physical expert/speaker/join/key columns. Publication and erasure-request acceptance remain disabled until manifest completeness, marker scan and restore proof show no unclassified recoverable plaintext in DB/MVCC/WAL/offsite copies.
- **LD-7 — approved-plan execution and complete subject fencing.** #1306 owns the post-joins `erasure-execute` runtime. The `pd_officer` approves one immutable plan with `plan_expires_at = approved_at + 24 hours`, subject kind/id digest, all-and-only server-derived mappings, exact curator resolutions, legal-hold verdict, reviewer/time and dependency fingerprint; no executor body carries subject ids. Before any gate/domain work the worker locks the request: an expired still-`approved` plan atomically returns to `review_required`, records `approval_expired_at`, retains the plan as evidence, terminates that job as a no-op and yields 409 `ERASURE_PLAN_EXPIRED`; an unexpired plan atomically enters `executing`, after which the former deadline does not cancel it. It then locks the canonical subject/project/event/relation set, rejects an omitted/extra/unrelated mapping or a mapped row in the legacy-only path as 409 `ERASURE_SCOPE_STALE`, and closes the subject gates. Every PD-bearing claim reserves `subject_key_id` plus fence epoch before upload/handler entry and conditionally completes against them; erasure expires matching processing/completed claims, clears live content/key references, retains exact tombstones, resolves sole-curator projects and writes durable post-commit key-destruction/cleanup work. The request remains `executing` until every acknowledgement completes; replay never re-executes.
- **LD-8 — retained committed-media cleanup.** #1283 owns one `media_cleanup_jobs` technical table distinct from idempotency claim cleanup. It uses retained `status: active | expired`, `execution_state: pending | processing | completed`, nullable `deleted_at`, monotonic fenced `lease_epoch` and bounded leases. A committed replace/clear transaction records the old server-generated object/CDN keys plus entity/slot pointer; a worker rechecks references and retries until every version/derivative and CDN key is acknowledged absent. Completion atomically sets `expired` + `deleted_at`, clears raw keys, endpoint pointer, lease/error content and retains only job id, cleanup kind, outcome and timestamps; no row is deleted/reactivated. The domain reference change remains feature-010 audited, while `media_cleanup_jobs` is an explicit tested technical-table audit exclusion; #1305 classifies its active expert-scoped linkage and erasure acknowledgement.
- **LD-9 — base taxonomy versus surface read models.** 012 owns exact base entity/relationship DTOs and one primary-partner designation, but it does not make a page issue N relationship calls. Feature 015 owns one batched project-catalog/page projection with kind-specific content count, nullable primary partner and enriched team; feature 016 owns one batched expert-catalog projection with name search, single project filter and filtered/total counts. Their PRDs/specs must declare exact DTOs and query plans with bounded SQL before implementation, while 012 relationship reads remain independently cursor-paginated.

## Event Model

### Commands

- `CreateTaxonomyEntity(kind, fields)` / `UpdateTaxonomyEntity(kind, id, fields)` — create a `draft` entity or edit the same retained row.
- `PublishTaxonomyEntity(kind, id)` — `draft → published`, after validating its public projection.
- `PreviewLifecycleImpact(target, transition)` — return the currently visible related projections that retire would remove or restore would add plus the signed `impactToken` for that complete dependency snapshot.
- `Retire(target, impactToken)` / `Restore(target, impactToken)` — explicit lifecycle transitions with no cascade; both require the matching `Lifecycle-Impact-Token`, ordinary entity restore targets `draft`, join restore targets `active`, and an expert with `pd_erased_at IS NOT NULL` refuses restore with 409 `PD_ERASED`.
- `CreateRelationship(kind, endpoints, attributes)` / `UpdateRelationship(id, attributes)` — create or change one retained join; `event_experts` accepts `role`, `position`, and optional `legacySpeakerId`.
- `ReplaceProjectCurator(projectId, expertId)` — replace a published project's curator atomically; no retire/demote gap is exposed.
- `ApproveEditorialErasurePlan(erasureRequestId, curatorResolutions)` — `pd_officer` + fresh step-up locks a `review_required` request, derives and stores the exact expert or unmapped legacy-speaker subject set/fingerprint, proves no legal hold, records reviewer/24-hour expiry and enqueues one job while atomically setting `approved`; the client never submits mapped legacy ids.
- `ExecuteApprovedEditorialErasure(erasureRequestId)` — the internal `erasure-execute` worker alone consumes the immutable plan by request id, atomically enters `executing`, closes subject fences and applies exact retained tombstones/key zeroization/cleanup; it has no public/admin taxonomy route and replay never executes twice.

Every ordinary mutating taxonomy HTTP endpoint requires `Idempotency-Key` as one canonical globally reserved UUID. Missing/blank is 428 `IDEMPOTENCY_KEY_REQUIRED`; malformed/non-canonical is 400 `IDEMPOTENCY_KEY_INVALID`. POST create requires no `If-Match`; PATCH/publish/retire/restore require the target ETag; replace-curator requires the project ETag. Retire/restore additionally require `Lifecycle-Impact-Token` from their transition-specific preview. The separate approval route and BullMQ worker use ADR-0009's request-id idempotency contract, not a caller-selected taxonomy key.

| Event                                                      | Meaning                                                                                                                                                                                            |
| ---------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `TaxonomyEntityCreated/Updated/Published/Retired/Restored` | One entity changed state or content; feature 010 records the row diff in the same transaction.                                                                                                     |
| `TaxonomyRelationshipCreated/Updated/Retired/Restored`     | One explicit relationship changed; no endpoint or sibling relation changes with it.                                                                                                                |
| `EventSpeakerMatched`                                      | An `event_experts` row now explicitly references one retained legacy speaker; ordinary matching leaves that row unchanged, while a later approved ADR-0009 erasure may scrub its `name`/`regalia`. |
| `ProjectCuratorReplaced`                                   | One transaction demotes the former curator, then promotes the eligible replacement; rollback preserves the former curator on failure.                                                              |
| `ExpertPdErased`                                           | ADR-0009 erases identifying expert/explicit legacy/replay values and media while retaining minimized DB tombstones.                                                                                |

### Read models

- `TaxonomyAdminList/Detail` — all authoring fields, status, version and relationship summaries; offset/page pagination, search and explicit retained filters.
- Full public entities are exact: `PublicProject { id, slug, kind, title, description, coverUrl, primaryPartner }`; `PublicExpert { id, slug, name, professionalRole, credentials, affiliation, bio, photoUrl, initials }`; `PublicTopic { id, slug, title }`; `PublicPartner { id, slug, title, logoUrl, websiteUrl }`; `primaryPartner` is `PublicPartnerSummary | null`, and optional URLs are present and nullable.
- Exact summaries are `PublicEventSummary { id, slug, title, school, startsAt, state }`, `PublicProjectSummary { id, slug, kind, title, description, coverUrl, primaryPartner }`, `PublicExpertSummary { id, slug, name, professionalRole, credentials, affiliation, photoUrl }`, `PublicTopicSummary { id, slug, title }`, and `PublicPartnerSummary { id, slug, title, logoUrl, websiteUrl }`. Bidirectional items use those summaries; only event↔expert adds `{ role, position }` and project↔expert adds `{ role: curator | member }`.
- `PublicEventPageSpeaker` is exactly legacy `{ source: legacy, name, credentials }` or expert `{ source: expert, expertId, expertSlug, name, credentials, photoUrl, role }`; `photoUrl` is present/nullable. One resolver feeds both this ordered page/endpoint union and `UpcomingBroadcastCard.speakers[] { name }`.
- `LifecycleImpact` — transition, target id/version, affected currently-public event/project/expert/topic/partner identifiers and opaque signed `impactToken`; it contains no hidden record content.
- Base taxonomy lists and relationship reads keep the ADR-0002 cursor envelope and deliberately omit surface-specific aggregate totals/search. Feature 015 owns a single batched project-card/page read model with kind-specific content counts, nullable `primaryPartner` and enriched team; feature 016 owns a single batched expert-catalog read model with `q`, one project filter, filtered count and total. Neither feature may implement those surfaces as N+1 calls to 012 relationship routes.

### Policies

- Slugs and logical endpoint pairs remain unique across retained rows; a duplicate create returns a conflict and points the operator to the retained row for restore. Slug mutability is determined only by `first_published_at`.
- A project has at most one active `curator`; a published project has exactly one eligible curator and changes it only through the atomic replacement command. Other project experts are `member`. A project may have many partner links but at most one active `is_primary=true`; public project DTOs show only that optional primary partner while bidirectional partner reads return every eligible link. A legacy speaker may be matched by at most one retained `event_experts` row, and the speaker must belong to the same event.
- Topic assignment always selects an existing non-retired topic. `specialties[]` is never read from or written to `topics`.
- Media binaries use the existing object-storage abstraction; public DTOs expose CDN URLs, never storage keys. Retiring/restoring a row never deletes its media.

## Invariants

- No taxonomy entity, join or migrated legacy speaker row is physically deleted or cascade-deleted; stable ids/slugs/pairs are never reused.
- A slug is editable only while `first_published_at IS NULL`; retirement and restore never reset that permanent identity lock. The sole exception is ADR-0009 expert-PD erasure, which replaces readable identity with a reserved non-authored tombstone while a mandatory keyed digest prevents old-slug reuse; authored UUID/tombstone namespaces and id/slug resolution remain disjoint.
- `retired ⇔ deleted_at IS NOT NULL`; ordinary entity restore yields `draft`, ordinary join/migrated-speaker restore yields `active`, and an erased expert or migrated legacy speaker returns 409 `PD_ERASED`.
- Every published project has exactly one active curator whose expert is published and non-retired; curator replacement is atomic and direct invalidation is refused.
- Every committed event speaker projection has at most one visible row per position; 012 expert-speaker writes lock affected experts before the event, while 007 legacy-speaker writes and linked-expert publish/retire share those affected per-event boundaries under the global expert→project→event order.
- Retire and restore confirmation are accepted only against the unchanged transition-specific signed dependency snapshot that the operator saw.
- A public relationship is visible only when the join is active and every taxonomy endpoint is published and non-retired.
- A matched legacy speaker remains stored and unchanged under ordinary matching/lifecycle; the only value-erasure exception is an approved ADR-0009 command over explicitly mapped `event_speakers.name`/`event_speakers.regalia`, whose `pd_erased_at` tombstone cannot be restored or repopulated, and an explicit eligible mapping remains the only projection-suppression rule.
- `specialties[]` and topics are different axes and never synchronize.
- One authored Postgres row feeds admin and public projections; no export/sync/fake seam exists.
- Expert product retirement is reversible; lawful PD erasure is distinct, consumes one approved immutable plan, preserves exact non-identifying DB tombstones, resolves every sole-curator project by atomic replacement or retirement, zeroizes external keys for current/MVCC/WAL/backup copies, scrubs every linked media/cache/index/replay copy, and leaves neither an invalid published project nor unclassified plaintext in future or historical audit evidence.
- Idempotency UUIDs are globally reserved. Rows use subject-fenced request/cleanup leases, expire by retained lifecycle UPDATE, clear every live payload/fingerprint/upload/actor/subject/key reference, durably destroy claim keys to provider acknowledgement, and are never physically deleted or reused; per feature 010's explicit allowlist they do not produce domain-audit rows.
