# 012 — Контентная таксономия (Требования)

## Результаты

- Контент-оператор один раз описывает проект, эксперта, тему или партнёра и везде переиспользует ту же сохраняемую запись.
- Мероприятия связаны с несколькими проектами, экспертами и темами настоящими m2m-строками; проекты связаны с экспертами и партнёрами в обоих направлениях.
- Эксперт — одна самостоятельная редакционная запись. `project_experts.role` равен `curator | member`; `event_experts` несёт роль на мероприятии, позицию и опциональное явное сопоставление с одной legacy-строкой спикера.
- Существующие свободнотекстовые спикеры продолжают отображаться во время постепенной миграции. Связанный опубликованный эксперт заменяет в текущей проекции только явно сопоставленную legacy-строку; нет сопоставления по имени, дедупликации, перезаписи или неявного вывода строки из оборота.
- Операторы создают, ищут, редактируют, публикуют, выводят из оборота и восстанавливают таксономию в существующей Refine-админке. Действия Delete нет.
- Последующие поверхности Академии читают безопасные публичные записи и каждое направление связей через REST `/v1`; копии, экспорта или шага синхронизации нет.

## Рамки

**Входит:**

- Верхнеуровневые сохраняемые сущности:
  - `projects`: стабильные id + slug, тип `school | media | program`, название, описание, опциональная ссылка на медиа обложки;
  - `experts`: стабильные id + slug, имя, профессиональная роль, регалии, аффилиация, био, опциональная ссылка на фото; FK на пользователя платформы в 012 нет;
  - `topics`: стабильные id + slug и название, поддерживаемый курируемый список;
  - `partners`: стабильные id + slug, название, опциональные ссылка на логотип и URL сайта.
- Общие поля сущности: `status: draft | published | retired`, nullable `deleted_at`, nullable set-once `first_published_at`, монотонная `version` и timestamps. Создание начинает с `draft`; обычное восстановление возвращает сущность в `draft`, не очищая `first_published_at`. Восстановление эксперта дополнительно требует `pd_erased_at IS NULL`; стёртые PD эксперта — явное исключение с 409 `PD_ERASED`.
- Сохраняемые джойны: `event_projects`, `event_experts`, `project_experts`, `project_partners`, `event_topics`; у каждого стабильный id, `status: active | retired`, nullable `deleted_at`, `version`, timestamps и уникальность логической пары концов. `project_partners` дополнительно несёт `is_primary`; у проекта не более одной active primary-связи, а любое число non-primary связей сохраняет подтверждённую many-to-many модель.
- `event_experts`: обязательный event-specific `role`, неотрицательная `position` и nullable unique `legacy_speaker_id`. Runtime-prerequisite #1278 заменяет старый primary key таблицы `event_speakers` — `(event_id, position)` — стабильной UUID `id` row identity, добавляет partial active-slot `UNIQUE(event_id, position) WHERE status='active'` плюс явный `UNIQUE(event_id,id)` и retained lifecycle fields, включая nullable `pd_erased_at`. Поэтому старая retained и новая active строки одной позиции сосуществуют, same-event composite FK `(event_id,legacy_speaker_id) → event_speakers(event_id,id)` исполним, а approved erased legacy row нельзя восстановить или заново наполнить PD.
- Refine-ресурсы списка/детали/создания/редактирования сущностей и lifecycle-действий; редакторы связей на соответствующих формах мероприятия/проекта; поиск и явные фильтры сохранённых строк; плюс отдельный ADR-0009 compliance-queue detail, который показывает server-derived editorial erasure plan и собирает только per-project curator resolution до approval ролью `pd_officer`.
- Безопасные публичные чтения сущностей, двунаправленные чтения связей и объединённая текущая проекция спикеров.

**Не входит:**

- Врачебный рендеринг: `/`, фасеты/архив `/webinars`, `/projects`, `/experts` и их страницы относятся к 013–016.
- `event_recordings`, `leads`, Payload CMS, коммерческие условия/договоры партнёров, публичный поиск по таксономии, рекомендации/ранжирование, массовая миграция спикеров, самообслуживание эксперта или связь user↔expert.
- Новые роли для обычного редактирования таксономии; оно переиспользует `platform_admin`. Отдельная ADR-0009 erasure queue не является taxonomy-admin действием и потребляет обязательную ADR-политику `pd_officer` + fresh step-up из #1304/#1305.
- Универсальный интерфейс просмотра аудита. Фича 010 уже пишет мутации в `audit_ledger`; 012 лишь сохраняет строки адресуемыми для просмотра/восстановления.

## Контракт редактирования и публикации

| Вид     | Обязательно при создании                                 | Дополнительно обязательно для публикации                                                                     | Опционально                     |
| ------- | -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ | ------------------------------- |
| Проект  | `title` (trimmed 1–160); пропущенный `slug` генерируется | `kind: school \| media \| program`, `description` (trimmed plain text 1–2000), ровно один допустимый куратор | `cover_ref`                     |
| Эксперт | `name` (trimmed 1–160); пропущенный `slug` генерируется  | `professional_role` (1–160), `credentials` (1–500), `affiliation` (1–240), `bio` (trimmed plain text 1–4000) | `photo_ref`; фолбэк-инициалы    |
| Тема    | `title` (trimmed 1–120); пропущенный `slug` генерируется | дополнительных полей и связей нет                                                                            | нет                             |
| Партнёр | `title` (trimmed 1–160); пропущенный `slug` генерируется | дополнительных полей и связей нет                                                                            | `logo_ref`, HTTPS `website_url` |

- Каждый authored slug — lowercase ASCII длиной 1–80, соответствует `[a-z0-9]+(?:-[a-z0-9]+)*`, не является canonical UUID, а для экспертов не начинается с reserved `erased-`. Если slug не задан при создании, сервер применяет каноническую transliteration/slugification к display label и отвергает reserved/conflicting candidate, а не молча меняет identity; UI показывает тот же candidate. Конфликт с retained/reservation даёт 409 `SLUG_CONFLICT`. Detail resolution трактует canonical UUID text только как id, любой другой token — только как slug, поэтому `/:idOrSlug` однозначен. Первая успешная публикация один раз ставит `first_published_at`; любое последующее изменение slug, включая после retire/restore, даёт 409 `SLUG_IMMUTABLE`.
- В draft можно не заполнить только дополнительные publish-поля из таблицы. Пропущенные члены PATCH не меняются; явный `null` очищает опциональное поле или nullable-поле неполного draft. Мутация уже опубликованной сущности обязана сохранить валидность её publish-контракта. Отклонённая публикация/правка возвращает 409 `PUBLISH_REQUIREMENTS_NOT_MET` с ошибками по полям и ничего не меняет.
- Проект может публиковаться с нулём мероприятий и партнёров, когда заполнены поля и куратор. Эксперт, тема и партнёр могут публиковаться с нулём связей. Опциональные медиа и сайт партнёра никогда не блокируют публикацию.
- URL сайта, если задан, — абсолютный HTTPS длиной не более 2048 символов. Медиа, если задано, — один still JPEG, PNG или WebP не более 10 MiB, не более 6000 px по каждой post-orientation decoded axis и не более 25 миллионов aggregate decoded pixels; минимального размера нет. Multi-frame/animated PNG или WebP и любой decoder page/frame count не равный одному дают 400 `MEDIA_INVALID` до full-frame allocation или upload. Refine выполняет такой же preflight, серверная валидация остаётся авторитетной.
- Create/PATCH без файла — строгий `application/json`; media upload — `multipart/form-data` с одной JSON-частью `payload` и не более чем kind-specific файлом `cover|photo|logo`. Клиент никогда не передаёт storage refs/keys. Omission в PATCH сохраняет медиа, JSON `mediaAction: clear` очищает его, а file плюс clear/multiple/wrong file parts дают 400 `MEDIA_INPUT_CONFLICT`; multipart без файла — 415 `UNSUPPORTED_MEDIA_TYPE`. Первая media vertical (#1283) владеет одним shared decoder/normalizer для project covers, expert photos и partner logos: он применяет orientation, переводит в sRGB и заново кодирует один still frame в canonical WebP под одной pinned codec/profile version; эта version и exact options входят в fingerprint. Он удаляет EXIF/XMP/GPS/ICC/original filename и каждый ancillary block, выводит MIME из normalized bytes и не сохраняет original upload. Ошибка object storage — 503 `MEDIA_STORAGE_UNAVAILABLE` без domain/audit mutation.
- Та же #1283 vertical владеет retained-очередью `media_cleanup_jobs`, отдельной от claim-scoped upload cleanup. Каждый committed replace/`mediaAction: clear` в той же транзакции, что ref swap, пишет cleanup row для superseded reference; worker повторно проверяет отсутствие ссылок, удаляет все versions/derivatives, purge/invalidate CDN key, retry до завершения и сохраняет non-content tombstone после очистки raw keys. Expert erasure остаётся `executing` до успеха compliance cleanup jobs; недоступный store не может молча завершить erasure или потерять старый key.
- Декларация input mask: `none` для каждого поля 012, потому что значения — редакционный текст, отдельно валидируемый slug/URL/integer либо файл, а не идентификатор фиксированного формата; маска выдумывала бы или переписывала содержимое вместо помощи при вводе. Поэтому админка использует обычные text/textarea-контролы с trim и счётчиками символов. Slug получает generated preview и проверку шаблона/длины; сайт — URL-контрол; `event_experts.position` — целочисленный контрол с step 1 и диапазоном 0–32767; роль на мероприятии — trimmed 1–80 символов. File-контролы объявляют форматы и отклоняют лимиты размера/разрешения до отправки.

## Ограничения

- **Только retained rows.** Ни один прикладной путь не выполняет `DELETE`, `TRUNCATE`, data-bearing drop, `ON DELETE CASCADE` и не переиспользует идентификаторы этих сущностей, джойнов или мигрированных `event_speakers`. Все FK — `RESTRICT`/`NO ACTION`.
- **Согласованный lifecycle.** `retired` тогда и только тогда, когда `deleted_at` не null; у `draft`, `published` и `active` он null. Обычные переходы сущности: `draft → published`, `draft|published → retired`, `retired → draft`; джойна и migrated speaker: `active → retired → active`. Expert или migrated legacy speaker с `pd_erased_at IS NOT NULL` — явное невосстановимое исключение. Вывод сущности из оборота никогда не меняет её джойны.
- **Публичный default deny.** Публичные чтения включают только сущности `published` с `deleted_at IS NULL`, джойны `active` с `deleted_at IS NULL` и мероприятия, разрешённые существующей публичной политикой событий. Публичные draft/retired/unknown дают одинаковую форму 404.
- **Явное чтение сохранённого.** Admin-списки по умолчанию показывают не-retired сущности / active джойны. Сохранённые строки появляются только при явном status или `includeRetired=true`; admin-detail по стабильному id остаётся доступен для восстановления.
- **Одна текущая проекция спикеров.** Active-сопоставление подавляет matched legacy-строку только при опубликованном не-retired эксперте. Иначе legacy-фолбэк остаётся. Строки сортируются по `position ASC`, затем source rank (`expert` перед `legacy`), затем стабильному row id; одинаковые имена никогда не дедуплицируются. Каждая запись в `event_experts` сначала блокирует затронутую строку эксперта или строки экспертов, затем parent event; каждая запись в `event_speakers` и publish/retire связанного эксперта входят в тот же канонический порядок expert→event. Каждая команда после блокировок перечитывает lifecycle эксперта и обе таблицы спикеров и перед commit повторно проверяет объединённые видимые слоты.
- **Полнота публикации.** Draft может быть неполным только по правилам матрицы редактирования. Публикация применяет эту матрицу; никакая связь не обязательна, кроме ровно одной active-связи `curator` проекта с published/non-retired экспертом.
- **Инвариант куратора опубликованного проекта.** В каждом committed-состоянии у published-проекта ровно один допустимый куратор. Публикация, мутации curator-связей, замена куратора и lifecycle-мутации эксперта используют общий expert-first порядок блокировок LD-4 и повторно проверяют состояние после блокировки. Retire этого эксперта и retire/понижение единственной curator-связи запрещены, пока не выполнена атомарная замена либо не retired сам проект.
- **Актуальное согласие на lifecycle-переход.** Подтверждение retire или restore действует только для точного подписанного сервером dependency snapshot, показанного в `LifecycleImpact`; изменение цели, incident relation, eligibility противоположного конца или пересекающийся serialization conflict требуют нового preview.
- **PD эксперта стираются без удаления строки.** Обычные retire/restore остаются обратимыми и сохраняют payload/media эксперта. Отдельный ADR-0009 путь — asynchronous worker `erasure-execute` из #1306, а не taxonomy-admin Delete/erase POST. Он потребляет одну locked/unexpired строку `erasure_requests`, чей immutable plan свежо step-up-approved ролью `pd_officer`, не имеет legal hold и атомарно переходит `approved → executing`; job payload/idempotency key — только id этого запроса. Plan под блокировками выводит все и только текущие mapped legacy-speaker ids, никогда не принимает caller list или heuristic name match и разрешает каждый sole-curator project через eligible replacement либо retire проекта. Execution сохраняет точные expert/speaker/join tombstones, zeroize purpose-separated external Vault keys, чтобы live/MVCC/WAL/backup copies стали нечитаемыми, очищает каждую media/cache/index replica и делает restore 409 `PD_ERASED`. #1240 подтверждает только taxonomy/product package; #1305 сначала должен получить свежее sign-off Product Lead и Legal/Compliance по точным lawful basis, term, legacy-backup gate и erasure policy.
- **PD-копии шифруются и subject-fenced до использования.** Логические expert fields/slug/media pointer, legacy-speaker `name`/`regalia`, `event_experts.role` и PD-bearing idempotency request/response content хранятся как ciphertext под external purpose-scoped keys; lookup использует необратимые purpose-keyed digests. Retained `pd_subject_fences` резервируют subject digests/epochs при claim-time до upload или handler work. Erasure закрывает gate и двигает epoch до перечисления каждого processing/completed claim, поэтому пропущенный pre-response claim или concurrent acquisition не может commit/replay PD. Future и historical audit handling покрывает каждое classified поле/link expert, speaker, `event_experts` и `project_experts`, не только имена.
- **Без заглушек.** Схема, миграции, API, generated SDK, Refine UI и браузерная проводка поставляются настоящими вертикальными слайсами. Seeds, fake repositories, placeholder-селекторы и ручные шаги в БД не закрывают EARS.
- **Сохраняемые ограниченные записи идемпотентности.** Canonical UUID key глобально резервируется между actors/routes с первого использования, поэтому его permanent non-PD digest остаётся достаточным после очистки active actor/request content; cross-actor или cross-route reuse всегда даёт 409 `IDEMPOTENCY_KEY_REUSED`. Claim остаётся `active` 24 часа replay-окна, шифрует PD-bearing content под claim DEK и использует fenced request-owner плюс отдельные cleanup leases. Expiry/approved erasure UPDATE row в `expired` + `deleted_at`, закрывает replay, очищает live actor/request/response/upload/subject/key references и durably планирует service-only уничтожение DEK; application decrypt path уже нет, пока Vault zeroization повторяется до acknowledgement. Bounded upload authorization истекает вместе с lease; cleanup сохраняет deterministic locator и ждёт позже maximum authorization плюс clock-skew grace перед final HEAD/delete/absence decision, поэтому stale owner не может PUT после completion. Row никогда физически не удаляется, не reactivated и не reused.

## Prior decisions

- **ADR-0003 §4:** каждая прикладная сущность и связь сохраняется; обычные чтения фильтруют `deleted_at IS NULL`, historical/restore чтения подключают строки явно, все FK restrictive.
- **ADR-0002 §§3–4, 9:** Zod — SSOT запросов/ответов, REST версионирован под `/v1`, растущие публичные списки используют opaque cursor, admin-таблицы могут использовать offset, ошибки мутаций — RFC 7807, мутации идемпотентны.
- **ADR-0009 §§3, 7:** каждая новая PD-bearing table классифицируется до миграции с legal basis, retention, retained-row erasure mechanism, audit exception и owner; non-exempt PD стираются за 30 дней, а Postgres tombstone сохраняется.
- **ADR-0004 §3:** редактирование таксономии расширяет существующую Refine-админку через custom data/auth/access providers; второй backend и Payload CMS не создаются.
- **ADR-0013 + AGENTS.md §6:** реализация проходит design-system-first гейт; interaction states и token discipline приходят из `@ds/design-system`.
- **Фича 007:** текущий агрегат мероприятия владеет `specialties[]` и упорядоченными `event_speakers`; 012 добавляет таксономию рядом и переводит reconciliation спикеров с физической замены на стабильные сохраняемые строки.
- **Фича 010:** каждая таблица сущностей/связей таксономии и migrated speaker-domain получает generic audit trigger, поэтому её мутации пишут атрибутированные `data.<table>.<op>` без отдельной реализации аудита таксономии. До любой затронутой записи #1305 расширяет SQL и TypeScript PD registries и исправляет historical plaintext для expert fields, `event_speakers.name/regalia` и каждого classified `event_experts`/`project_experts` field/link; retained technical coordination tables остаются без audit только через явный allowlist фичи 010 и собственное доказательство ограниченного lifecycle.
- **Фича 011 EARS-10/11 + ADR-0001 §§7/10:** обычные taxonomy routes принимают выделенную MFA-verified admin session, а state-changing routes требуют CSRF double-submit. #1304 согласует shipped contracts и даёт token-free authority revalidation для `platform_admin`; отдельное approve erasure plan требует текущую роль `pd_officer` и server-verified свежий `step_up`, без хранения IdP access/refresh token.

## Технические решения лида

- **LD-1 — оптимистические версии и привязка lifecycle snapshot.** ADR-0002 требует идемпотентность, но не мешает двум разным валидным запросам перезаписать друг друга. Поэтому каждая mutable taxonomy/speaker-строка несёт монотонную `version`, возвращаемую как ETag. Create endpoints не требуют `If-Match`; PATCH, publish, retire и restore требуют ETag цели; curator replacement — ETag проекта. Lifecycle preview дополнительно возвращает подписанный opaque `impactToken` по transition, identity/version цели, issued-at/15-minute expiry и каноническим версиям и lifecycle/public-eligibility inputs каждой incident relation и противоположного конца. Confirmation retire/restore работает на `SERIALIZABLE` и пересчитывает dependency fingerprint. Для этих двух lifecycle methods любой target-ETag/token/dependency mismatch, tampered/expired token, wrong transition/target или serialization abort имеет precedence как 412 `LIFECYCLE_IMPACT_STALE`; 412 `PRECONDITION_FAILED` остаётся только для stale `If-Match` non-lifecycle методов. Каждый deterministic refusal не меняет domain/media/audit, но fenced-completes и replay idempotency result; auto-retry нет.
- **LD-2 — стабильный порядок и сериализация объединённых спикеров.** `position` задаёт редакционный порядок. Полный tie-break: `position ASC`, source rank (`expert` перед `legacy`), stable row id ASC; write path также отвергает конфликт видимого слота, кроме случая, когда mapped expert намеренно занимает позицию подавленной legacy-строки. Каждый create/update/retire/restore `event_experts` 012 сначала блокирует все затронутые old/new строки экспертов в порядке stable id, затем parent-row `events`, после чего перечитывает lifecycle экспертов и обе child-таблицы и пересчитывает проекцию; каждый reconciliation legacy-спикеров 007 блокирует ту же event boundary. Publish/retire эксперта уже держит expert lock, затем блокирует все связанные parent events в порядке stable id и выполняет ту же проверку, потому что может раскрыть unpaired expert или matched legacy fallback. Глобальный порядок остаётся expert→project→event. Поэтому каждое committed-чтение детерминировано и не имеет name-based поведения или cross-table uniqueness race.
- **LD-3 — постоянная и разделённая slug identity.** `first_published_at` один раз ставится в транзакции первой публикации и никогда не очищается. Authored slugs не могут быть canonical UUID; expert slugs дополнительно не входят в reserved namespace `erased-`. UUID-shaped detail tokens разрешаются только по id, остальные — только по slug. Erasure блокирует и old-slug reservation digest, и deterministic tombstone candidate, поэтому create-versus-erasure не конфликтуют.
- **LD-4 — атомарная замена куратора с общим порядком блокировок.** Команды, влияющие на куратора, сначала блокируют все затронутые expert rows в порядке stable id, затем project rows в порядке stable id, затем `project_experts`; eligibility и связи перечитываются только после этих блокировок. `ReplaceProjectCurator(projectId, expertId)` блокирует текущего и кандидата плюс проект, проверяет, что кандидат всё ещё published/non-retired, понижает прежнюю curator-связь до `member`, затем повышает или восстанавливает целевую связь в той же транзакции. Этот порядок удовлетворяет immediate partial unique index; при ошибке promotion rollback возвращает прежнего куратора. Lifecycle-команда эксперта блокирует эксперта, заново запрашивает его текущие curator-проекты, блокирует их по stable id и повторно валидирует перед сменой status. Committed-состояния с нулём или двумя допустимыми кураторами нет и при гонке replacement с retire.
- **LD-5 — authority обычного admin и erasure разделены.** Каждая обычная admin mutation 012 сначала проходит local dedicated-session/fingerprint/MFA/CSRF и #1304 live authority revalidation для `platform_admin`. #1304 также inline-согласует ADR-0001/feature 011 для отдельной compliance queue: approve/reject erasure plan доступен только `pd_officer`, `@Authz({ step_up: true })` требует fresh MFA в пределах 30 минут, а token-free admin session записывает server-verified elevated timestamp, не сохраняя IdP token. Нет свежего elevation — 401 `STEP_UP_REQUIRED` с `stepUpUrl`; потеря роли — 403 `PD_OFFICER_REQUIRED`; provider unavailable — 503 `IDP_REVALIDATION_UNAVAILABLE`. Worker не принимает human bearer/session и потребляет только approved request id.
- **LD-6 — encrypted subject/key и audit boundary.** #1305 блокирует affected migrations до свежего sign-off Product Lead и Legal/Compliance по lawful basis, finite terms, owners и exact erasure. Логические expert identity/slug/media fields, legacy-speaker `name`/`regalia`, `event_experts.role` и PD-bearing claim content используют AES-256-GCM ciphertext под external Vault purpose DEKs; Postgres хранит только ciphertext, non-reversible lookup digests и opaque external key references. Expert и каждый legacy-only speaker расширяют retained-контракт `subject_keys` из ADR-0009 одной editorial subject kind/digest/key-tombstone row плюс отдельной one-to-one `pd_subject_fences` epoch/gate row; fence не хранит вторую Vault reference. Claim имеет свой DEK, поэтому его multi-subject replay можно уничтожить независимо от другого claim. Indexed expert-name search использует только bounded normalized 1–3-gram HMAC tokens под отдельным versioned Vault key; erasure очищает subject tokens, rebuild non-erased rows в shadow version, atomically flip и уничтожает old key до completion, поэтому runtime search и old backups не требуют plaintext/full-roster scan. Existing plaintext speaker/audit/backups инвентаризируются: feature не включает expert publication и не принимает erasure request, пока каждый pre-encryption snapshot/WAL/offsite copy необратимо не expired/purged по approved provider record и restore drill не доказал отсутствие plaintext recovery. До первой записи каждой таблицы SQL/TS future masks используют точные physical columns: `experts.slug_ciphertext`, `experts.slug_lookup_digest`, `experts.slug_reservation_digest`, `experts.name_ciphertext`, `experts.photo_ref_ciphertext`, `experts.professional_role_ciphertext`, `experts.credentials_ciphertext`, `experts.affiliation_ciphertext`, `experts.bio_ciphertext`, `experts.name_search_tokens`, `experts.subject_key_id`, `event_speakers.name`, `event_speakers.regalia`, `event_speakers.subject_key_id`, `event_experts.expert_id`, `event_experts.legacy_speaker_id`, `event_experts.role_ciphertext`, `project_experts.expert_id`, `project_experts.role`, `subject_keys.subject_kind`, `subject_keys.subject_digest` и `subject_keys.vault_key_ref`; historical remediation покрывает их pre-mask equivalents.
- **LD-7 — approved-plan execution и полное subject fencing.** #1306 владеет post-joins runtime `erasure-execute`. `pd_officer` approve один immutable 24-hour plan с subject kind/id digest, all-and-only server-derived current mappings, exact curator resolutions, legal-hold verdict, reviewer/time и dependency fingerprint; executor body не несёт subject ids. Worker блокирует request и canonical subject/project/event/relation set, отвергает omitted/extra/unrelated mapping или mapped row в legacy-only path как 409 `ERASURE_SCOPE_STALE` и атомарно потребляет `approved → executing`. Каждый PD-bearing claim резервирует subject fence epochs до upload/handler entry и conditional-completes по ним; erasure сначала закрывает gates/двигает epochs, затем database transaction expires matching processing/completed claims, очищает их live content/key references, сохраняет exact expert/speaker/join tombstones, очищает join subject FKs/free text, разрешает sole-curator projects и пишет durable key-destruction/cleanup outbox. Только committed outbox вызывает Vault; request остаётся `executing`, пока не завершены все subject/claim DEK, media/CDN/cache/index и backup-key acknowledgements. Replay worker jobs видят тот же request state и не re-execute.
- **LD-8 — retained cleanup committed-media.** #1283 владеет одной technical-таблицей `media_cleanup_jobs`, отдельной от cleanup нового upload в idempotency claim. В ней есть retained `status: active | expired`, `execution_state: pending | processing | completed`, nullable `deleted_at`, монотонный fenced `lease_epoch` и bounded leases. Транзакция committed replace/clear записывает старые server-generated object/CDN keys плюс entity/slot pointer; worker перечитывает ссылки и повторяет работу, пока отсутствие каждой версии/производной и CDN key не подтверждено. Completion атомарно ставит `expired` + `deleted_at`, очищает raw keys, endpoint pointer, lease/error content и сохраняет только job id, cleanup kind, outcome и timestamps; строка не удаляется и не реактивируется. Изменение domain reference остаётся под feature-010 audit, а `media_cleanup_jobs` — явное проверяемое technical-table audit exclusion; #1305 классифицирует её active expert-scoped linkage и erasure acknowledgement.
- **LD-9 — base taxonomy и surface read models разделены.** 012 владеет точными base entity/relationship DTO и одним primary-partner designation, но не заставляет page issue делать N relationship calls. Feature 015 владеет одной batched project-catalog/page projection с kind-specific content count, nullable primary partner и enriched team; feature 016 — одной batched expert-catalog projection с name search, single project filter и filtered/total counts. Их PRD/spec обязаны зафиксировать exact DTO и query plans с bounded SQL до реализации, а 012 relationship reads остаются независимо cursor-paginated.

## Модель событий

### Команды

- `CreateTaxonomyEntity(kind, fields)` / `UpdateTaxonomyEntity(kind, id, fields)` — создать сущность в `draft` или изменить ту же сохраняемую строку.
- `PublishTaxonomyEntity(kind, id)` — `draft → published` после валидации публичной проекции.
- `PreviewLifecycleImpact(target, transition)` — вернуть текущие видимые связанные проекции, которые retire уберёт или restore добавит, и подписанный `impactToken` полного dependency snapshot.
- `Retire(target, impactToken)` / `Restore(target, impactToken)` — явные lifecycle-переходы без каскада; оба требуют совпадающий `Lifecycle-Impact-Token`, обычная сущность восстанавливается в `draft`, джойн — в `active`, а expert с `pd_erased_at IS NOT NULL` отказывает с 409 `PD_ERASED`.
- `CreateRelationship(kind, endpoints, attributes)` / `UpdateRelationship(id, attributes)` — создать или изменить один сохраняемый джойн; `event_experts` принимает `role`, `position` и опциональный `legacySpeakerId`.
- `ReplaceProjectCurator(projectId, expertId)` — атомарно заменить куратора опубликованного проекта, не открывая gap для retire/понижения.
- `ApproveEditorialErasurePlan(erasureRequestId, curatorResolutions)` — `pd_officer` + fresh step-up блокирует `review_required` request, выводит и сохраняет exact expert или unmapped legacy-speaker subject set/fingerprint, доказывает отсутствие legal hold, записывает reviewer/24-hour expiry и enqueue один job, атомарно ставя `approved`; клиент не передаёт mapped legacy ids.
- `ExecuteApprovedEditorialErasure(erasureRequestId)` — только internal worker `erasure-execute` потребляет immutable plan по request id, атомарно входит в `executing`, закрывает subject fences и применяет exact retained tombstones/key zeroization/cleanup; public/admin taxonomy route нет, replay никогда не выполняет работу дважды.

Каждый обычный mutating taxonomy HTTP endpoint требует `Idempotency-Key` как один canonical globally reserved UUID. Missing/blank даёт 428 `IDEMPOTENCY_KEY_REQUIRED`; malformed/non-canonical — 400 `IDEMPOTENCY_KEY_INVALID`. POST create не требует `If-Match`; PATCH/publish/retire/restore требуют ETag цели; replace-curator — ETag проекта. Retire/restore дополнительно требуют `Lifecycle-Impact-Token` из transition-specific preview. Отдельный approval route и BullMQ worker используют ADR-0009 request-id idempotency contract, не caller-selected taxonomy key.

### Модели чтения

- `TaxonomyAdminList/Detail` — все поля редактирования, status, version и сводки связей; page/offset, поиск и явные retained-фильтры.
- Полные публичные сущности точны: `PublicProject { id, slug, kind, title, description, coverUrl, primaryPartner }`; `PublicExpert { id, slug, name, professionalRole, credentials, affiliation, bio, photoUrl, initials }`; `PublicTopic { id, slug, title }`; `PublicPartner { id, slug, title, logoUrl, websiteUrl }`; `primaryPartner` — `PublicPartnerSummary | null`, optional URL присутствуют как nullable.
- Точные summaries: `PublicEventSummary { id, slug, title, school, startsAt, state }`, `PublicProjectSummary { id, slug, kind, title, description, coverUrl, primaryPartner }`, `PublicExpertSummary { id, slug, name, professionalRole, credentials, affiliation, photoUrl }`, `PublicTopicSummary { id, slug, title }`, `PublicPartnerSummary { id, slug, title, logoUrl, websiteUrl }`. Bidirectional items используют эти summaries; только event↔expert добавляет `{ role, position }`, project↔expert — `{ role: curator | member }`.
- `PublicEventPageSpeaker` — ровно legacy `{ source: legacy, name, credentials }` либо expert `{ source: expert, expertId, expertSlug, name, credentials, photoUrl, role }`; `photoUrl` присутствует и nullable. Один resolver питает эту ordered page/endpoint union и `UpcomingBroadcastCard.speakers[] { name }`.
- `LifecycleImpact` — переход, id/version цели, идентификаторы затрагиваемых сейчас публичных событий/проектов/экспертов/тем/партнёров и opaque подписанный `impactToken`; скрытого содержимого в ответе нет.
- Base taxonomy lists и relationship reads сохраняют ADR-0002 cursor envelope и намеренно не несут surface-specific aggregate totals/search. Feature 015 владеет одной batched project-card/page read model с kind-specific content counts, nullable `primaryPartner` и enriched team; feature 016 — одной batched expert-catalog read model с `q`, одним project filter, filtered count и total. Ни одна feature не реализует эти поверхности через N+1 вызовы relationship routes 012.

### Политики

- Slug и логические пары концов остаются уникальными среди сохранённых строк; конфликт создания направляет оператора к сохранённой строке для restore. Возможность менять slug определяется только `first_published_at`.
- У проекта не более одного active `curator`; у опубликованного проекта ровно один допустимый куратор, меняемый только атомарной командой замены. Остальные эксперты проекта — `member`. У проекта может быть много partner links, но не более одной active `is_primary=true`; public project DTO показывает только этого optional primary partner, а bidirectional partner reads возвращают все eligible links. Legacy-спикер сопоставлен не более чем одной сохранённой строке `event_experts` и обязан принадлежать тому же событию.
- Тема выбирается только из существующих не-retired тем. `specialties[]` никогда не читается из `topics` и не записывается туда.
- Медиа используют существующую абстракцию object storage; публичные DTO отдают CDN URL, не storage keys. Retire/restore никогда не удаляет медиа.

## EARS-требования

> Плоская нумерация по ADR-0006 §4. Каждая формулировка реализует одну или несколько историй PRD и покрыта `012-scenarios.feature`.

- **EARS-1** _(realizes: US-1, US-9)_ — Когда `platform_admin` создаёт или редактирует проект через его Refine-ресурс, система должна проверить матрицу редактирования и сохранить одну полноценную retained-строку `projects` со стабильными id/slug/version, типом `school | media | program`, названием, описанием и опциональной ссылкой на обложку, а затем показать ту же строку в list/detail; проект никогда не должен быть строкой мероприятия или второй копией.
- **EARS-2** _(realizes: US-2, US-9)_ — Когда `platform_admin` создаёт или редактирует эксперта через его Refine-ресурс, система должна проверить матрицу редактирования и сохранить одну самостоятельную редакционную строку `experts` со стабильными id/slug/version, именем, профессиональной ролью, регалиями, аффилиацией, био и опциональной ссылкой на фото из shared normalizer, с фолбэком из инициалов и без обязательной связи с пользователем платформы или параллельного типа эксперта. Каждое PD-bearing значение expert/legacy-speaker/join/claim до первой persisted copy шифруется по approved #1305 subject/key, retention и audit policy; publication остаётся выключена, пока не пройден historical plaintext/backup gate. Обычные retire/restore сохраняют payload/media. Только worker #1306 может выполнить unexpired, legal-hold-free, one-use plan, freshly step-up-approved ролью `pd_officer`: под locks он выводит все и только текущие subject copies, fence каждый in-flight claim, разрешает sole-curator projects, сохраняет точные non-identifying DB tombstones и keyed slug reservation, zeroize subject/claim keys, удаляет каждую media/cache/index copy и делает restore 409 `PD_ERASED`. Тот же plan path адресует одного явно указанного unmapped legacy speaker без name matching; mapped или unrelated speaker отклоняется.
- **EARS-3** _(realizes: US-5, US-9)_ — Когда `platform_admin` создаёт или редактирует тему через её Refine-ресурс, система должна сохранить одну курируемую строку `topics` со стабильными id/slug/version и названием; темы никогда не должны быть свободными тегами мероприятия.
- **EARS-4** _(realizes: US-6, US-9)_ — Когда `platform_admin` создаёт или редактирует партнёра через его Refine-ресурс, система должна сохранить одну описательную строку `partners` со стабильными id/slug/version и названием плюс опциональные ссылку на логотип и HTTPS URL сайта; коммерческие условия и контакты не являются полями публичного контракта.
- **EARS-5** _(realizes: US-1, US-2, US-5, US-6, US-10, US-12)_ — Когда оператор публикует валидную сущность из `draft`, система должна проверить точную матрицу полей, навсегда заблокировать slug однократной установкой `first_published_at` и перевести сущность в `published`; только проект дополнительно требует ровно одного active `curator`, связанного с published/non-retired экспертом, и может иметь ноль мероприятий/партнёров, а каждый другой вид — ноль связей. Public list/detail после этого отдают только allow-list вида и CDN URL, а incomplete draft, retired и internal/storage поля остаются скрыты и неотличимы от unknown. Любой последующий PATCH, который сделал бы published-проекцию неполной, должен вернуть 409 `PUBLISH_REQUIREMENTS_NOT_MET` без изменения значения, version или audit history.
- **EARS-6** _(realizes: US-4, US-11)_ — Когда оператор связывает мероприятие с проектом, система должна создать или восстановить одну строку `event_projects`, позволить мероприятию иметь несколько проектов, отдать event→projects и project→events и не менять lifecycle концов побочным эффектом.
- **EARS-7** _(realizes: US-3, US-8)_ — Когда оператор связывает эксперта с мероприятием, система должна сохранить одну строку `event_experts` с обязательной ролью, неотрицательной позицией и опциональным явным `legacySpeakerId`; legacy id обязан указывать на retained-спикера того же события и быть уникальным среди retained expert links, имя никогда не используется для сопоставления, а каждая запись expert link должна заблокировать затронутых экспертов до parent event, перечитать lifecycle и обе speaker tables и отвергнуть конфликт объединённого видимого слота с 409 `SPEAKER_POSITION_OCCUPIED`.

- **EARS-17** _(realizes: US-7, US-10, US-11)_ — Система требует один canonical UUID `Idempotency-Key` для каждого обычного mutating taxonomy HTTP endpoint; absent/blank даёт 428 `IDEMPOTENCY_KEY_REQUIRED`, malformed/non-canonical — 400 `IDEMPOTENCY_KEY_INVALID`, оба до upload, ownership, domain или audit side effects. Первый claim глобально резервирует его purpose-keyed UUID digest между actors, routes и expiry; любое позднее использование вне exact active replay даёт 409 `IDEMPOTENCY_KEY_REUSED`, поэтому permanent tombstone не нужен actor identifier. Fingerprint включает concrete target params, canonical JSON/canonical-normalized-media digest, `If-Match` и `Lifecycle-Impact-Token`; другой semantic input или normalized output с тем же active key даёт тот же conflict. Каждый claim шифрует content своим external DEK и до upload или handler entry резервирует каждый server-derived PD subject digest плюс текущий fence epoch; каждое request/cleanup lease увеличивает monotonic `lease_epoch`, а heartbeat/domain completion обусловлены owner+lease epoch+всеми subject epochs. Каждое deterministic post-claim completion, включая 409 и оба вида 412, fenced-сохраняет точные status/body плюс разрешённые `ETag`/`Location`; lifecycle mismatch completes/replays `LIFECYCLE_IMPACT_STALE`, non-lifecycle stale ETag — `PRECONDITION_FAILED`, и оба не меняют domain/media/audit. Provider/DB faults без достоверного verdict остаются takeover-eligible. Только request takeover продолжает command; cleanup в него не входит. Upload authorization claim-scoped и истекает не позже request lease; cleanup сохраняет deterministic locator и продолжает reconciliation до максимального срока authorization плюс clock-skew grace, прежде чем очистить locator, поэтому old owner не может записать объект после final absence. На границе 24 часов, независимо от Vault/storage availability, одна database transaction ставит `expired` + `deleted_at`, закрывает replay/upload access, очищает actor/request/response/upload/subject ciphertext и live key references и durably записывает service-only обязанность уничтожить claim DEK. После этого commit ни один application path не расшифровывает claim; retrying worker получает подтверждение zeroization от Vault и лишь затем очищает opaque destruction handle, сохраняя только global key digest и terminal non-content cleanup state. Row никогда не удаляется, не reactivated и не reused. Этот claim cleanup отделён от old-reference queue LD-8. Каждая committed mutation taxonomy entity, relationship, speaker-domain или retained `subject_keys` получает audit capture фичи 010 в той же транзакции. Только `idempotency_keys`, `idempotency_claim_subjects`, `pd_subject_fences`, `pd_key_destruction_jobs` и `media_cleanup_jobs` являются explicit parity-tested technical-table exclusions.
- **EARS-18** _(realizes: US-1, US-2, US-3, US-4, US-5, US-6, US-7, US-8, US-9)_ — До старта любого нового/изменённого taxonomy/event-admin/compliance-queue UI slice команда должна завершить Stage A: выполнить `build-ui-from-design-system`, представить 2–3 Refine-композиции и записать выбор владельца; реализация использует `@ds/design-system` с полными states, без entity Delete UI или manual API seam, а реальный результат проходит live Playwright и owner Stage B до merge.

## Инварианты

- Ни одна сущность таксономии, джойн или мигрированная legacy-строка спикера физически или каскадно не удаляется; стабильные ids/slugs/pairs не переиспользуются.
- Slug редактируется только пока `first_published_at IS NULL`; retire и restore никогда не сбрасывают этот постоянный identity-lock. Единственное исключение — ADR-0009 erasure PD эксперта, заменяющее readable identity на зарезервированный non-authored tombstone, пока mandatory keyed digest запрещает reuse старого slug; authored UUID/tombstone namespaces и id/slug resolution остаются disjoint.
- `retired ⇔ deleted_at IS NOT NULL`; обычное восстановление сущности даёт `draft`, обычное восстановление джойна/migrated speaker — `active`, а erased expert или migrated legacy speaker возвращает 409 `PD_ERASED`.
- У каждого published-проекта ровно один active curator с published/non-retired экспертом; замена атомарна, прямая инвалидация запрещена.
- В каждой committed-проекции спикеров события не более одной видимой строки на position; expert-speaker writes 012 блокируют затронутых экспертов до event, а legacy-speaker writes 007 и publish/retire связанного эксперта используют те же затронутые per-event boundaries в глобальном порядке expert→project→event.
- Подтверждение retire и restore принимается только для неизменившегося transition-specific подписанного dependency snapshot, который видел оператор.
- Публичная связь видима только при active-джойне и published/non-retired концах таксономии.
- Сопоставленная legacy-строка спикера остаётся сохранённой и неизменной при обычном matching/lifecycle; единственное исключение стирания значений — одобренная ADR-0009 команда над явно mapped `event_speakers.name`/`event_speakers.regalia`, чей `pd_erased_at` tombstone нельзя restore/repopulate, а единственное правило подавления в проекции — явное допустимое сопоставление.
- `specialties[]` и topics — разные оси и никогда не синхронизируются.
- Одна авторская Postgres-строка питает admin и public проекции; export/sync/fake seam нет.
- Product retire эксперта обратим; lawful PD erasure отделён, потребляет один approved immutable plan, сохраняет точные non-identifying DB tombstones, разрешает каждый sole-curator project через atomic replacement или retirement, zeroize external keys для current/MVCC/WAL/backup copies, очищает каждую linked media/cache/index/replay copy и не оставляет ни invalid published project, ни unclassified plaintext в future/historical audit evidence.
- Idempotency UUID глобально reserved. Rows используют subject-fenced request/cleanup leases, expire через retained lifecycle UPDATE, очищают каждый live payload/fingerprint/upload/actor/subject/key reference, durably уничтожают claim keys до provider acknowledgement и никогда не удаляются физически и не переиспользуются; по explicit allowlist фичи 010 они не создают domain-audit rows.

## Зависимости и последовательность

- Фича 007 даёт существующую форму мероприятия и legacy-проекцию спикеров; #1278 делает speaker rows стабильно retained, а 012 добавляет явный expert match/current-projection без поломки немигрированных событий.
- GitHub [#1278](https://github.com/doctor-school/ds-platform/issues/1278) — critical-path runtime prerequisite после merge спеки и policy/masking из #1305, и до любой новой entity 012: он владеет retained-row conformance текущих таблиц, UUID-PK `event_speakers` с partial active-position uniqueness и `UNIQUE(event_id,id)`, общей parent-event блокировкой, globally reserved idempotency claims с subject fences/DEK/bounded upload authorization и удалением существующих cascade/delete paths. 012 потребляет этот runtime и не дублирует его.
- GitHub [#1304](https://github.com/doctor-school/ds-platform/issues/1304) должен inline-согласовать ADR-0001/011 и поставить token-free live authority revalidation для обычных `platform_admin` mutations плюс `pd_officer`/fresh-step-up erasure approval до появления любого из этих route classes; ни один handler не хранит user IdP token и не превращает provider outage в 401.
- GitHub [#1305](https://github.com/doctor-school/ds-platform/issues/1305) — policy/schema-readiness prerequisite, а не будущий erasure runtime: он получает fresh Product Lead и Legal/Compliance sign-off; inline-согласует ADR-0009, чтобы editorial subjects расширяли retained `subject_keys` и всегда требовали manual `review_required` approval; определяет fences, точные tombstones и каждую current/backup/cache/audit copy; исправляет historical plaintext; блокирует affected writes/publication до успешного restore drill. Затем #1283 поставляет still-only shared normalizer плюс retained old-reference cleanup queue; #1284 — encrypted expert vertical без erase route.
- GitHub [#1306](https://github.com/doctor-school/ds-platform/issues/1306) владеет approved-plan worker только после появления реальных `project_experts`, `event_experts` и publication handlers. Он реализует exact subject-set locking, claim fencing, curator resolution, retained tombstones/key zeroization и acknowledged cleanup и блокирует release фичи/final protocol sweeps.
- Фича 010 даёт generic audit capture; каждая новая entity/join/speaker-domain таблица должна попасть под его coverage guard, а каждый technical-table exclusion — под явный allowlist parity guard.
- 013–016 потребляют base public API 012 только после попадания этой спеки в `main`; весь врачебный рендеринг принадлежит им, а 015/016 также владеют явно указанными в LD-9 batched surface projections.
- EARS-18 Stage A — первый UI-гейт и блокирует UI-части EARS-1…15; каждый entity kind и каждый join/projection остаётся отдельным bounded vertical slice, а не одним CRUD issue на четыре сущности.
- Исполнимая последовательность срезов: #1305 policy/masking → #1278 retained/fenced runtime → project → encrypted expert → topic → partner → `project_experts` → `event_experts` → publication → #1306 erasure runtime → оставшиеся joins/projections → cross-route verification. Publication — реальный committed handler, поэтому #1306 тестирует реальные published-state invariants, но никакой runtime 012 не выпускается, пока #1306 и final protocol sweep не закроют parent; ни один prerequisite не тестирует будущую table/handler и partial deployment запрещён.
- EARS-16 и EARS-17 — сквозные критерии приёмки каждого применимого read/mutation начиная с первой project-вертикали. Их поздние WBS-дети — verification sweeps по уже compliant real handlers, а не отложенная реализация протокола или scaffold seam.
