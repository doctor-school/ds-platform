# 012 — Контентная таксономия (Требования)

## Результаты

- Контент-оператор один раз описывает проект, эксперта, тему или партнёра и везде переиспользует ту же сохраняемую запись.
- Мероприятия связаны с несколькими проектами, экспертами и темами настоящими m2m-строками; проекты связаны с экспертами и партнёрами в обоих направлениях.
- Эксперт — одна самостоятельная редакционная запись. `project_experts.role` равен `curator | member`; `event_experts` несёт роль на мероприятии, позицию и опциональное явное сопоставление с одной legacy-строкой спикера.
- Существующие свободнотекстовые спикеры продолжают отображаться во время постепенной миграции. Связанный опубликованный эксперт заменяет в текущей проекции только явно сопоставленную legacy-строку; нет сопоставления по имени, дедупликации, перезаписи или неявного вывода строки из оборота.
- Операторы создают, ищут, редактируют, публикуют, выводят из оборота и восстанавливают таксономию в существующей Refine-админке. Действия Delete нет.
- Последующие поверхности Академии читают безопасные публичные записи и каждое направление связей через REST `/v1`; копии, экспорта или шага синхронизации нет.

## Рамки

**Входит:**

- Верхнеуровневые сохраняемые сущности:
  - `projects`: стабильные id + slug, тип `school | media | program`, название, описание, опциональная ссылка на медиа обложки;
  - `experts`: стабильные id + slug, имя, профессиональная роль, регалии, аффилиация, био, опциональная ссылка на фото; FK на пользователя платформы в 012 нет;
  - `topics`: стабильные id + slug и название, поддерживаемый курируемый список;
  - `partners`: стабильные id + slug, название, опциональные ссылка на логотип и URL сайта.
- Общие поля сущности: `status: draft | published | retired`, nullable `deleted_at`, nullable set-once `first_published_at`, монотонная `version` и timestamps. Создание начинает с `draft`; обычное восстановление возвращает сущность в `draft`, не очищая `first_published_at`. Восстановление эксперта дополнительно требует `pd_erased_at IS NULL`; стёртые PD эксперта — явное исключение с 409 `PD_ERASED`.
- Сохраняемые джойны: `event_projects`, `event_experts`, `project_experts`, `project_partners`, `event_topics`; у каждого стабильный id, `status: active | retired`, nullable `deleted_at`, `version`, timestamps и уникальность логической пары концов.
- `event_experts`: обязательная роль именно на мероприятии, неотрицательная `position` и nullable unique `legacy_speaker_id`. Runtime-prerequisite #1278 заменяет старый PK `event_speakers(event_id, position)` стабильной UUID `id` row identity, добавляет partial active-slot `UNIQUE(event_id, position) WHERE status='active'` плюс явный `UNIQUE(event_id,id)` и retained lifecycle fields, включая nullable `pd_erased_at`. Поэтому старая retained и новая active строки одной позиции сосуществуют, same-event composite FK `(event_id,legacy_speaker_id) → event_speakers(event_id,id)` исполним, а approved erased legacy row нельзя восстановить или заново наполнить PD.
- Refine-ресурсы списка/детали/создания/редактирования сущностей и lifecycle-действий; редакторы связей на соответствующих формах мероприятия/проекта; поиск и явные фильтры сохранённых строк.
- Безопасные публичные чтения сущностей, двунаправленные чтения связей и объединённая текущая проекция спикеров.

**Не входит:**

- Врачебный рендеринг: `/`, фасеты/архив `/webinars`, `/projects`, `/experts` и их страницы относятся к 013–016.
- `event_recordings`, `leads`, Payload CMS, коммерческие условия/договоры партнёров, публичный поиск по таксономии, рекомендации/ранжирование, массовая миграция спикеров, самообслуживание эксперта или связь user↔expert.
- Новые роли или концепции политики доступа; 012 переиспользует `platform_admin`.
- Универсальный интерфейс просмотра аудита. Фича 010 уже пишет мутации в `audit_ledger`; 012 лишь сохраняет строки адресуемыми для просмотра/восстановления.

## Контракт редактирования и публикации

| Вид     | Обязательно при создании                                 | Дополнительно обязательно для публикации                                                                     | Опционально                     |
| ------- | -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ | ------------------------------- |
| Проект  | `title` (trimmed 1–160); пропущенный `slug` генерируется | `kind: school \| media \| program`, `description` (trimmed plain text 1–2000), ровно один допустимый куратор | `cover_ref`                     |
| Эксперт | `name` (trimmed 1–160); пропущенный `slug` генерируется  | `professional_role` (1–160), `credentials` (1–500), `affiliation` (1–240), `bio` (trimmed plain text 1–4000) | `photo_ref`; фолбэк-инициалы    |
| Тема    | `title` (trimmed 1–120); пропущенный `slug` генерируется | дополнительных полей и связей нет                                                                            | нет                             |
| Партнёр | `title` (trimmed 1–160); пропущенный `slug` генерируется | дополнительных полей и связей нет                                                                            | `logo_ref`, HTTPS `website_url` |

- Каждый slug — lowercase ASCII длиной 1–80 символов по шаблону `[a-z0-9]+(?:-[a-z0-9]+)*`. Если он пропущен при создании, сервер применяет каноническую транслитерацию/slugification к отображаемому имени; UI показывает тот же кандидат. Конфликт с сохранённой строкой возвращает 409 `SLUG_CONFLICT`, чтобы оператор задал другое значение. Первая успешная публикация один раз выставляет `first_published_at`; любая последующая смена slug, включая после retire/restore, возвращает 409 `SLUG_IMMUTABLE`.
- В draft можно не заполнить только дополнительные publish-поля из таблицы. Пропущенные члены PATCH не меняются; явный `null` очищает опциональное поле или nullable-поле неполного draft. Мутация уже опубликованной сущности обязана сохранить валидность её publish-контракта. Отклонённая публикация/правка возвращает 409 `PUBLISH_REQUIREMENTS_NOT_MET` с ошибками по полям и ничего не меняет.
- Проект может публиковаться с нулём мероприятий и партнёров, когда заполнены поля и куратор. Эксперт, тема и партнёр могут публиковаться с нулём связей. Опциональные медиа и сайт партнёра никогда не блокируют публикацию.
- URL сайта, если задан, — абсолютный HTTPS длиной не более 2048 символов. Медиа, если задано, — JPEG, PNG или WebP, не более 10 MiB, не более 6000 px по каждой декодированной оси и не более 25 мегапикселей; минимального размера нет. Refine выполняет такой же preflight, серверная валидация остаётся авторитетной.
- Create/PATCH без файла — строгий `application/json`; media upload — `multipart/form-data` с одной JSON-частью `payload` и не более чем kind-specific файлом `cover|photo|logo`. Клиент никогда не передаёт storage refs/keys. Omission в PATCH сохраняет медиа, JSON `mediaAction: clear` очищает его, а file плюс clear/multiple/wrong file parts дают 400 `MEDIA_INPUT_CONFLICT`; multipart без файла — 415 `UNSUPPORTED_MEDIA_TYPE`. Первая media vertical (#1283) владеет одним shared decoder/normalizer для project covers, expert photos и partner logos: он заново кодирует принятые изображения в canonical output, удаляет EXIF/XMP/GPS/original filename и все ancillary metadata, выводит MIME из normalized bytes и не сохраняет исходную загрузку. Ошибка object storage — 503 `MEDIA_STORAGE_UNAVAILABLE` без domain/audit mutation.
- Та же #1283 vertical владеет retained-очередью `media_cleanup_jobs`, отдельной от claim-scoped upload cleanup. Каждый committed replace/`mediaAction: clear` в той же транзакции, что ref swap, пишет cleanup row для superseded reference; worker повторно проверяет отсутствие ссылок, удаляет все versions/derivatives, purge/invalidate CDN key, retry до завершения и сохраняет non-content tombstone после очистки raw keys. Expert erasure остаётся `executing` до успеха compliance cleanup jobs; недоступный store не может молча завершить erasure или потерять старый key.
- Декларация input mask: `none` для каждого поля 012, потому что значения — редакционный текст, отдельно валидируемый slug/URL/integer либо файл, а не идентификатор фиксированного формата; маска выдумывала бы или переписывала содержимое вместо помощи при вводе. Поэтому админка использует обычные text/textarea-контролы с trim и счётчиками символов. Slug получает generated preview и проверку шаблона/длины; сайт — URL-контрол; `event_experts.position` — целочисленный контрол с step 1 и диапазоном 0–32767; роль на мероприятии — trimmed 1–80 символов. File-контролы объявляют форматы и отклоняют лимиты размера/разрешения до отправки.

## Ограничения

- **Только retained rows.** Ни один прикладной путь не выполняет `DELETE`, `TRUNCATE`, data-bearing drop, `ON DELETE CASCADE` и не переиспользует идентификаторы этих сущностей, джойнов или мигрированных `event_speakers`. Все FK — `RESTRICT`/`NO ACTION`.
- **Согласованный lifecycle.** `retired` тогда и только тогда, когда `deleted_at` не null; у `draft`, `published` и `active` он null. Обычные переходы сущности: `draft → published`, `draft|published → retired`, `retired → draft`; джойна и migrated speaker: `active → retired → active`. Expert или migrated legacy speaker с `pd_erased_at IS NOT NULL` — явное невосстановимое исключение. Вывод сущности из оборота никогда не меняет её джойны.
- **Публичный default deny.** Публичные чтения включают только сущности `published` с `deleted_at IS NULL`, джойны `active` с `deleted_at IS NULL` и мероприятия, разрешённые существующей публичной политикой событий. Публичные draft/retired/unknown дают одинаковую форму 404.
- **Явное чтение сохранённого.** Admin-списки по умолчанию показывают не-retired сущности / active джойны. Сохранённые строки появляются только при явном status или `includeRetired=true`; admin-detail по стабильному id остаётся доступен для восстановления.
- **Одна текущая проекция спикеров.** Active-сопоставление подавляет matched legacy-строку только при опубликованном не-retired эксперте. Иначе legacy-фолбэк остаётся. Строки сортируются по `position ASC`, затем source rank (`expert` перед `legacy`), затем стабильному row id; одинаковые имена никогда не дедуплицируются. Каждая запись в `event_experts` сначала блокирует затронутую строку эксперта или строки экспертов, затем parent event; каждая запись в `event_speakers` и publish/retire связанного эксперта входят в тот же канонический порядок expert→event. Каждая команда после блокировок перечитывает lifecycle эксперта и обе таблицы спикеров и перед commit повторно проверяет объединённые видимые слоты.
- **Полнота публикации.** Draft может быть неполным только по правилам матрицы редактирования. Публикация применяет эту матрицу; никакая связь не обязательна, кроме ровно одной active-связи `curator` проекта с published/non-retired экспертом.
- **Инвариант куратора опубликованного проекта.** В каждом committed-состоянии у published-проекта ровно один допустимый куратор. Публикация, мутации curator-связей, замена куратора и lifecycle-мутации эксперта используют общий expert-first порядок блокировок LD-4 и повторно проверяют состояние после блокировки. Retire этого эксперта и retire/понижение единственной curator-связи запрещены, пока не выполнена атомарная замена либо не retired сам проект.
- **Актуальное согласие на lifecycle-переход.** Подтверждение retire или restore действует только для точного подписанного сервером dependency snapshot, показанного в `LifecycleImpact`; изменение цели, incident relation, eligibility противоположного конца или пересекающийся serialization conflict требуют нового preview.
- **PD эксперта стираются без удаления строки.** Обычные retire/restore остаются обратимыми и сохраняют payload/media эксперта. Отдельный ADR-0009 путь, заблокированный на #1305, сохраняет stable row/timestamps как минимизированный retained tombstone, но стирает expert fields/media, каждую явно mapped legacy-speaker копию `name`/`regalia` и active idempotency replay content; relation rows сохраняются только в юридически классифицированной post-erasure форме. Он удаляет каждую версию/производную normalized media object и purge/invalidate CDN key. Если expert — sole curator published-проекта, execution требует явного решения по каждому проекту: атомарно поставить eligible replacement или retire проект; невалидного published-проекта не остаётся. Он обязательно сохраняет keyed old-slug reservation digest, никогда не использует heuristic name matching и делает erased expert невосстановимым с 409 `PD_ERASED`. #1240 подтверждает только taxonomy/product package; #1305 должен записать свежее explicit sign-off Product Lead и Legal/Compliance по точной retention/erasure policy до миграции.
- **Без заглушек.** Схема, миграции, API, generated SDK, Refine UI и браузерная проводка поставляются настоящими вертикальными слайсами. Seeds, fake repositories, placeholder-селекторы и ручные шаги в БД не закрывают EARS.
- **Сохраняемые ограниченные записи идемпотентности.** Idempotency claim остаётся `active` 24 часа replay-окна и использует fenced request-owner и отдельные orphan-cleanup leases из design §6. Active scope содержит только purpose-keyed actor digest плюс method/route template и никогда не сохраняет raw admin `sub`; PD-bearing cached responses добавляют sorted active-only `pd_subject_refs`. На границе 24 часов expiry UPDATE независимо от object storage переводит row в `status='expired'` + `deleted_at` и очищает response payload/headers, request fingerprint, upload digest/object key, actor digest, `pd_subject_refs` и все другие content-bearing inputs; approved erasure выполняет ту же fenced minimization досрочно для matching subject claims. Tombstone сохраняет только keyed request-key digest, method/route template, terminal lifecycle fields и non-content cleanup handle, пока cleanup pending. Row никогда не TTL-delete/reactivate/reuse, а recurring reconciliation перепроверяет abandoned/expired media claims до отсутствия unreferenced object, включая поздний PUT stale owner.

## Prior decisions

- **ADR-0003 §4:** каждая прикладная сущность и связь сохраняется; обычные чтения фильтруют `deleted_at IS NULL`, historical/restore чтения подключают строки явно, все FK restrictive.
- **ADR-0002 §§3–4, 9:** Zod — SSOT запросов/ответов, REST версионирован под `/v1`, растущие публичные списки используют opaque cursor, admin-таблицы могут использовать offset, ошибки мутаций — RFC 7807, мутации идемпотентны.
- **ADR-0009 §§3, 7:** каждая новая PD-bearing table классифицируется до миграции с legal basis, retention, retained-row erasure mechanism, audit exception и owner; non-exempt PD стираются за 30 дней, а Postgres tombstone сохраняется.
- **ADR-0004 §3:** редактирование таксономии расширяет существующую Refine-админку через custom data/auth/access providers; второй backend и Payload CMS не создаются.
- **ADR-0013 + AGENTS.md §6:** реализация проходит design-system-first гейт; interaction states и token discipline приходят из `@ds/design-system`.
- **Фича 007:** текущий агрегат мероприятия владеет `specialties[]` и упорядоченными `event_speakers`; 012 добавляет таксономию рядом и переводит reconciliation спикеров с физической замены на стабильные сохраняемые строки.
- **Фича 010:** каждая таблица сущностей/связей таксономии и migrated speaker-domain получает generic audit trigger, поэтому её мутации пишут атрибутированные `data.<table>.<op>` без отдельной реализации аудита таксономии. Retained technical coordination tables остаются без audit только через явный allowlist фичи 010 и собственное доказательство ограниченного lifecycle.
- **Фича 011 EARS-10/11:** каждый admin route принимает только выделенную MFA-verified admin session, а state-changing маршруты требуют CSRF double-submit. #1304 inline-согласует ADR-0001/011 и даёт token-free high-stakes authority revalidation, потому что shipped admin session намеренно не хранит IdP access/refresh token.

## Технические решения лида

- **LD-1 — оптимистические версии и привязка lifecycle snapshot.** ADR-0002 требует идемпотентность, но не мешает двум разным валидным запросам перезаписать друг друга. Поэтому каждая mutable taxonomy/speaker-строка несёт монотонную `version`, возвращаемую как ETag. Create endpoints не требуют `If-Match`; PATCH, publish, retire и restore требуют ETag цели; curator replacement — ETag проекта; `EraseExpertPd` и `EraseLegacySpeakerPd` — ETag соответствующего эксперта или speaker-строки. Lifecycle preview дополнительно возвращает подписанный opaque `impactToken` по transition, identity/version цели, issued-at/15-minute expiry и каноническим версиям и lifecycle/public-eligibility inputs каждой incident relation и противоположного конца. Confirmation retire/restore работает на `SERIALIZABLE`, заново вычисляет dependency fingerprint и требует `Lifecycle-Impact-Token`; mismatch цели/dependency, tampered/expired token, wrong transition/target или serialization abort возвращает 412 `LIFECYCLE_IMPACT_STALE` без мутации и никогда не auto-retry.
- **LD-2 — стабильный порядок и сериализация объединённых спикеров.** `position` задаёт редакционный порядок. Полный tie-break: `position ASC`, source rank (`expert` перед `legacy`), stable row id ASC; write path также отвергает конфликт видимого слота, кроме случая, когда mapped expert намеренно занимает позицию подавленной legacy-строки. Каждый create/update/retire/restore `event_experts` 012 сначала блокирует все затронутые old/new строки экспертов в порядке stable id, затем parent-row `events`, после чего перечитывает lifecycle экспертов и обе child-таблицы и пересчитывает проекцию; каждый reconciliation legacy-спикеров 007 блокирует ту же event boundary. Publish/retire эксперта уже держит expert lock, затем блокирует все связанные parent events в порядке stable id и выполняет ту же проверку, потому что может раскрыть unpaired expert или matched legacy fallback. Глобальный порядок остаётся expert→project→event. Поэтому каждое committed-чтение детерминировано и не имеет name-based поведения или cross-table uniqueness race.
- **LD-3 — постоянная блокировка slug после первой публикации.** `first_published_at` один раз выставляется в транзакции первой публикации и никогда не очищается. Это отличает восстановленную бывшую публикацию от никогда не публиковавшегося draft и реализует подтверждённую постоянную идентичность slug без вывода истории из текущего status.
- **LD-4 — атомарная замена куратора с общим порядком блокировок.** Команды, влияющие на куратора, сначала блокируют все затронутые expert rows в порядке stable id, затем project rows в порядке stable id, затем `project_experts`; eligibility и связи перечитываются только после этих блокировок. `ReplaceProjectCurator(projectId, expertId)` блокирует текущего и кандидата плюс проект, проверяет, что кандидат всё ещё published/non-retired, понижает прежнюю curator-связь до `member`, затем повышает или восстанавливает целевую связь в той же транзакции. Этот порядок удовлетворяет immediate partial unique index; при ошибке promotion rollback возвращает прежнего куратора. Lifecycle-команда эксперта блокирует эксперта, заново запрашивает его текущие curator-проекты, блокирует их по stable id и повторно валидирует перед сменой status. Committed-состояния с нулём или двумя допустимыми кураторами нет и при гонке replacement с retire.
- **LD-5 — token-free live authority revalidation.** Каждая admin mutation 012 сначала проходит local dedicated-session/fingerprint/MFA/CSRF checks, затем вызывает #1304 `IdpClient.revalidateAdminAuthority({ zitadelSessionId, sub })` через service authentication до validation, idempotency ownership, upload или handler entry. Inactive/missing/mismatched provider session даёт 401 `ADMIN_SESSION_REQUIRED`; current-role loss — 403 `PLATFORM_ADMIN_REQUIRED`; timeout, transport, 429, provider 5xx, service-auth/config failure или malformed provider shape — 503 `IDP_REVALIDATION_UNAVAILABLE`, сохраняет local session и не создаёт side effect.
- **LD-6 — retained-граница стирания PD эксперта.** #1305 блокирует миграцию экспертов до свежего explicit sign-off Product Lead и Legal/Compliance по ADR-0009 lawful basis, term, audit exception и owner. До любой expert migration он инвентаризирует historical `audit_ledger` diffs `data.event_speakers.*` на plaintext `name`/`regalia`; каждый hit получает legal classification и remediation через approved feature-010/ADR-0009 append-only-safe encryption или crypto-shred mechanism, чтобы raw ledger output не содержал unclassified plaintext, а lawful retention exception имел точный term, owner и совместимое per-row audit-retention encryption. Command принимает явное решение для каждого published-проекта, где subject — sole curator: атомарно заменить его eligible expert или retire проект и убрать его из public surfaces при сохранении joins. Он ставит `status='retired'`, `deleted_at`/`pd_erased_at`, `slug='erased-<stable-id>'`, `name='[erased]'`, `professional_role=NULL`, `credentials=NULL`, `affiliation=NULL`, `bio=NULL`, `photo_ref=NULL` и mandatory non-null keyed old-slug reservation digest; mapped legacy rows становятся `retired` с non-null `deleted_at`/`pd_erased_at`, `name='[erased]'` и `regalia=''` и не могут быть restored/repopulated. Каждый PD-bearing idempotency response записывает active-only sorted `pd_subject_refs`; erasure находит все claims с этим экспертом, двигает fence, переводит их в expired и очищает replay/fingerprint/upload/target/actor/subject content, чтобы paused owner не вернул PD, а любое дальнейшее использование ключа дало `IDEMPOTENCY_KEY_REUSED`. Command сохраняет stable ids/lifecycle timestamps и юридически классифицированную post-erasure форму joins и использует durable cleanup jobs для всех photo versions/derivatives/CDN keys. SQL `audit_pd_columns()` и TS `AUDIT_PD_COLUMNS` перечисляют все expert PD columns плюс `event_speakers.name`/`event_speakers.regalia` с parity/no-plaintext proof до следующего affected write. Обычный retire этого не делает; heuristic name matching запрещён.
- **LD-7 — полная граница replica, linkage и legacy subject.** #1305 классифицирует каждое поле и endpoint link `event_experts`/`project_experts`, всю таблицу legacy `event_speakers.name`/`regalia`, public JSON/HTML/page/card/CDN caches, возможные search/index replicas, logs и metrics. Expert erasure retire его joins, очищает `legacy_speaker_id`, ставит free-text event role в `[erased]` и оставляет stable endpoint ids/position только по подписанному pseudonymous operational-evidence basis/term; явная `EraseLegacySpeakerPd(eventSpeakerId, approvedRequestId)` обслуживает legacy-only человека без name matching и ставит такой же irreversible `pd_erased_at` speaker tombstone. DB transaction пишет tombstones и durable jobs; request остаётся `executing` до object/CDN/cache/index acknowledgements и red-team scans без plaintext, затем завершается в пределах 30 дней. Permanent slug reservation — `HMAC-SHA-256` под стабильным non-exportable Vault purpose DEK, чей wrapping KEK вращается без изменения digest; unique index плюс единый transaction lock по candidate digest сериализуют readable-slug/reservation conflict checks, а raw old slug невосстановим.
- **LD-8 — retained cleanup committed-media.** #1283 владеет одной technical-таблицей `media_cleanup_jobs`, отдельной от cleanup нового upload в idempotency claim. В ней есть retained `status: active | expired`, `execution_state: pending | processing | completed`, nullable `deleted_at`, монотонный fenced `lease_epoch` и bounded leases. Транзакция committed replace/clear записывает старые server-generated object/CDN keys плюс entity/slot pointer; worker перечитывает ссылки и повторяет работу, пока отсутствие каждой версии/производной и CDN key не подтверждено. Completion атомарно ставит `expired` + `deleted_at`, очищает raw keys, endpoint pointer, lease/error content и сохраняет только job id, cleanup kind, outcome и timestamps; строка не удаляется и не реактивируется. Изменение domain reference остаётся под feature-010 audit, а `media_cleanup_jobs` — явное проверяемое technical-table audit exclusion; #1305 классифицирует её active expert-scoped linkage и erasure acknowledgement.

## Модель событий

### Команды

- `CreateTaxonomyEntity(kind, fields)` / `UpdateTaxonomyEntity(kind, id, fields)` — создать сущность в `draft` или изменить ту же сохраняемую строку.
- `PublishTaxonomyEntity(kind, id)` — `draft → published` после валидации публичной проекции.
- `PreviewLifecycleImpact(target, transition)` — вернуть текущие видимые связанные проекции, которые retire уберёт или restore добавит, и подписанный `impactToken` полного dependency snapshot.
- `Retire(target, impactToken)` / `Restore(target, impactToken)` — явные lifecycle-переходы без каскада; оба требуют совпадающий `Lifecycle-Impact-Token`, обычная сущность восстанавливается в `draft`, джойн — в `active`, а expert с `pd_erased_at IS NOT NULL` отказывает с 409 `PD_ERASED`.
- `CreateRelationship(kind, endpoints, attributes)` / `UpdateRelationship(id, attributes)` — создать или изменить один сохраняемый джойн; `event_experts` принимает `role`, `position` и опциональный `legacySpeakerId`.
- `ReplaceProjectCurator(projectId, expertId)` — атомарно заменить куратора опубликованного проекта, не открывая gap для retire/понижения.
- `EraseExpertPd(expertId, explicitLegacySpeakerIds, approvedRequestId, curatorResolutions)` — выполнить одобренное retained-row erasure только для явно перечисленных mapped legacy rows и только после явной eligible replacement или явного retire каждого sole-curator project; все решения, lifecycle effects и PD scrubbing commit атомарно.
- `EraseLegacySpeakerPd(eventSpeakerId, approvedRequestId)` — стереть retained `name`/`regalia` одного явно идентифицированного legacy-only человека без expert id или поиска по имени, поставить irreversible `pd_erased_at` tombstone и отклонять последующие restore/repopulation с 409 `PD_ERASED`.

Каждый mutating HTTP endpoint требует `Idempotency-Key` как один canonical UUID. Missing/blank даёт 428 `IDEMPOTENCY_KEY_REQUIRED`; malformed/non-canonical — 400 `IDEMPOTENCY_KEY_INVALID`. POST create не требует `If-Match`; PATCH/publish/retire/restore требуют ETag цели; replace-curator — ETag проекта; `EraseExpertPd` и `EraseLegacySpeakerPd` — ETag соответствующего эксперта или speaker-строки. Retire/restore дополнительно требуют `Lifecycle-Impact-Token` из transition-specific preview.

| Событие                                                    | Смысл                                                                                                                                                                                                            |
| ---------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `TaxonomyEntityCreated/Updated/Published/Retired/Restored` | Изменились данные или состояние одной сущности; фича 010 пишет diff строки в той же транзакции.                                                                                                                  |
| `TaxonomyRelationshipCreated/Updated/Retired/Restored`     | Изменилась одна явная связь; концы и соседние связи не меняются.                                                                                                                                                 |

### Модели чтения

- `TaxonomyAdminList/Detail` — все поля редактирования, status, version и сводки связей; page/offset, поиск и явные retained-фильтры.
- Полные публичные сущности точны: `PublicProject { id, slug, kind, title, description, coverUrl }`; `PublicExpert { id, slug, name, professionalRole, credentials, affiliation, bio, photoUrl, initials }`; `PublicTopic { id, slug, title }`; `PublicPartner { id, slug, title, logoUrl, websiteUrl }`; optional URL присутствуют как nullable.
- Точные summaries: `PublicEventSummary { id, slug, title, school, startsAt, state }`, `PublicProjectSummary { id, slug, kind, title, coverUrl }`, `PublicExpertSummary { id, slug, name, professionalRole, photoUrl }`, `PublicTopicSummary { id, slug, title }`, `PublicPartnerSummary { id, slug, title, logoUrl, websiteUrl }`. Bidirectional items используют эти summaries; только event↔expert добавляет `{ role, position }`, project↔expert — `{ role: curator | member }`.
- `PublicEventPageSpeaker` — ровно legacy `{ source: legacy, name, credentials }` либо expert `{ source: expert, expertId, expertSlug, name, credentials, photoUrl, role }`; `photoUrl` присутствует и nullable. Один resolver питает эту ordered page/endpoint union и `UpcomingBroadcastCard.speakers[] { name }`.
- `LifecycleImpact` — переход, id/version цели, идентификаторы затрагиваемых сейчас публичных событий/проектов/экспертов/тем/партнёров и opaque подписанный `impactToken`; скрытого содержимого в ответе нет.

### Политики

- Slug и логические пары концов остаются уникальными среди сохранённых строк; конфликт создания направляет оператора к сохранённой строке для restore. Возможность менять slug определяется только `first_published_at`.
- У проекта не более одного active `curator`; у опубликованного проекта ровно один допустимый куратор, меняемый только атомарной командой замены. Остальные эксперты проекта — `member`. Legacy-спикер сопоставлен не более чем одной сохранённой строке `event_experts` и обязан принадлежать тому же событию.
- Тема выбирается только из существующих не-retired тем. `specialties[]` никогда не читается из `topics` и не записывается туда.
- Медиа используют существующую абстракцию object storage; публичные DTO отдают CDN URL, не storage keys. Retire/restore никогда не удаляет медиа.

## EARS-требования

> Плоская нумерация по ADR-0006 §4. Каждая формулировка реализует одну или несколько историй PRD и покрыта `012-scenarios.feature`.

- **EARS-1** _(realizes: US-1, US-9)_ — Когда `platform_admin` создаёт или редактирует проект через его Refine-ресурс, система должна проверить матрицу редактирования и сохранить одну полноценную retained-строку `projects` со стабильными id/slug/version, типом `school | media | program`, названием, описанием и опциональной ссылкой на обложку, а затем показать ту же строку в list/detail; проект никогда не должен быть строкой мероприятия или второй копией.
- **EARS-2** _(realizes: US-2, US-9)_ — Когда `platform_admin` создаёт или редактирует эксперта через его Refine-ресурс, система должна проверить матрицу редактирования и сохранить одну самостоятельную редакционную строку `experts` со стабильными id/slug/version, именем, профессиональной ролью, регалиями, аффилиацией, био и опциональной ссылкой на фото из shared normalizer, с фолбэком из инициалов и без обязательной связи с пользователем платформы или параллельного типа эксперта. Она должна потребить approved ADR-0009 classification из #1305: обычные retire/restore сохраняют payload/media, а approved PD erasure сохраняет минимизированные retained DB tombstones, очищает/заменяет каждую expert, explicitly mapped legacy-speaker и active-replay PD копию плюс photo objects, обязательно резервирует старый slug keyed digest и заставляет restore вернуть 409 `PD_ERASED`; SQL/TS audit-mask parity доказывает, что old/new PD эксперта не попадают в `audit_ledger` открытым текстом. Approved erasure legacy-only спикера должен адресовать один stable `eventSpeakerId`, ставить такой же irreversible retained speaker tombstone и никогда не выбирать другую строку по имени.
- **EARS-3** _(realizes: US-5, US-9)_ — Когда `platform_admin` создаёт или редактирует тему через её Refine-ресурс, система должна сохранить одну курируемую строку `topics` со стабильными id/slug/version и названием; темы никогда не должны быть свободными тегами мероприятия.
- **EARS-4** _(realizes: US-6, US-9)_ — Когда `platform_admin` создаёт или редактирует партнёра через его Refine-ресурс, система должна сохранить одну описательную строку `partners` со стабильными id/slug/version и названием плюс опциональные ссылку на логотип и HTTPS URL сайта; коммерческие условия и контакты не являются полями публичного контракта.
- **EARS-5** _(realizes: US-1, US-2, US-5, US-6, US-10, US-12)_ — Когда оператор публикует валидную сущность из `draft`, система должна проверить точную матрицу полей, навсегда заблокировать slug однократной установкой `first_published_at` и перевести сущность в `published`; только проект дополнительно требует ровно одного active `curator`, связанного с published/non-retired экспертом, и может иметь ноль мероприятий/партнёров, а каждый другой вид — ноль связей. Public list/detail после этого отдают только allow-list вида и CDN URL, а incomplete draft, retired и internal/storage поля остаются скрыты и неотличимы от unknown. Любой последующий PATCH, который сделал бы published-проекцию неполной, должен вернуть 409 `PUBLISH_REQUIREMENTS_NOT_MET` без изменения значения, version или audit history.
- **EARS-6** _(realizes: US-4, US-11)_ — Когда оператор связывает мероприятие с проектом, система должна создать или восстановить одну строку `event_projects`, позволить мероприятию иметь несколько проектов, отдать event→projects и project→events и не менять lifecycle концов побочным эффектом.
- **EARS-7** _(realizes: US-3, US-8)_ — Когда оператор связывает эксперта с мероприятием, система должна сохранить одну строку `event_experts` с обязательной ролью, неотрицательной позицией и опциональным явным `legacySpeakerId`; legacy id обязан указывать на retained-спикера того же события и быть уникальным среди retained expert links, имя никогда не используется для сопоставления, а каждая запись expert link должна заблокировать затронутых экспертов до parent event, перечитать lifecycle и обе speaker tables и отвергнуть конфликт объединённого видимого слота с 409 `SPEAKER_POSITION_OCCUPIED`.
- **EARS-8** _(realizes: US-2, US-3, US-8, US-10)_ — Когда читается публичная проекция спикеров события, система должна объединить active-linked экспертов с active legacy-строками по полному порядку LD-2: допустимый published-эксперт заменяет только явно matched строку, а unmatched и fallback для draft/retired/unlinked эксперта остаются; обычный match не перезаписывает, не retire и не name-dedupe legacy-строку, и только отдельно одобренное ADR-0009 erasure может стереть `name`/`regalia` явно mapped строки. Один canonical resolver должен питать `/events/:key/speakers`, точную union `PublicEventPageSpeaker` и тонкую `UpcomingBroadcastCard.speakers[] { name }`, чтобы поставленные public surfaces не расходились.
- **EARS-9** _(realizes: US-1, US-2, US-11)_ — Когда оператор связывает эксперта с проектом или заменяет куратора опубликованного проекта, система должна сохранить retained-строки `project_experts` с `curator | member`, обеспечить не более одного active curator, выполнить замену одной version-checked транзакцией с общим expert/project lock order LD-4 и post-lock проверкой eligibility, сохранить ровно одного допустимого куратора у каждого published-проекта при конкурентном expert lifecycle и отдать project→experts и expert→projects с ролью.
- **EARS-10** _(realizes: US-6, US-11, US-12)_ — Когда оператор связывает партнёра с проектом, система должна сохранить одну строку `project_partners` и отдать project→partners и partner→projects только с title/logo URL/website URL; commercial/internal данные не входят в проекцию.
- **EARS-11** _(realizes: US-5, US-11)_ — Когда оператор размечает мероприятие, event form должна предложить только существующие non-retired темы без inline creation, сохранить одну строку `event_topics` на пару, отдать оба направления и оставить `specialties[]` побайтно неизменным.
- **EARS-12** _(realizes: US-10, US-11, US-12)_ — Когда public caller читает taxonomy collections или любое направление под `/v1/public`, система должна запросить те же авторские строки, вернуть только точные full/summary/relationship item DTO выше, применить published/active/non-deleted allow-list на каждом hop, использовать opaque cursor с `{ data, pagination: { nextCursor, hasMore } }`, не вернуть duplicate pair и не раскрыть draft, retired endpoint, inactive join или admin-only field. Unknown/ineligible source даёт 404 `RESOURCE_NOT_FOUND`; eligible source без eligible relations — 200 с empty data и terminal pagination.
- **EARS-13** _(realizes: US-7)_ — Когда оператор запрашивает retire сущности или связи, admin сначала должен показать transition-specific `LifecycleImpact` и сохранить его подписанный `impactToken`; confirmation должна требовать тот же target `If-Match` плюс `Lifecycle-Impact-Token`, а сервер — транзакционно отвергать изменившийся dependency snapshot цели/relation/endpoint с 412 `LIFECYCLE_IMPACT_STALE`. Сервер должен запретить retire/понижение единственного допустимого curator-эксперта/связи опубликованного проекта, иначе один раз выставить `retired` + `deleted_at`, сохранить строки/FK, не менять lifecycle связанного и убрать цель из defaults/current public только фильтрацией.
- **EARS-14** _(realizes: US-7, US-8)_ — Когда оператор восстанавливает retained entity/relation, admin сначала должен показать transition-specific `LifecycleImpact` и сохранить его подписанный `impactToken`; confirmation должна требовать тот же target `If-Match` плюс `Lifecycle-Impact-Token`, а сервер — отвергать изменившийся dependency snapshot с 412 `LIFECYCLE_IMPACT_STALE`. Для expert с `pd_erased_at IS NOT NULL` admin не показывает restore control, а прямая попытка вместо этого возвращает 409 `PD_ERASED` с нулевым side effect; иначе система очищает `deleted_at` и переводит entity в `draft`, join в `active`. Detail и явный `includeRetired` обращаются к той же stable row, defaults её исключают. HTTP Delete route и Delete control не существуют. Отдельно editor фичи 007 не показывает restore control для migrated legacy speaker с `pd_erased_at IS NOT NULL`, а прямая попытка restore или payload repopulation возвращает 409 `PD_ERASED` с нулевым side effect.
- **EARS-15** _(realizes: US-9)_ — Когда оператор открывает список taxonomy resource, admin API и Refine table должны поддержать bounded page/offset, total, case-insensitive title/name/slug search и явные status/`includeRetired`; retired entity не появляется в new-link selector, empty result — успешная пустая page.
- **EARS-16** _(realizes: US-1, US-2, US-3, US-4, US-5, US-6, US-7, US-8, US-9, US-12)_ — По фиче 011 EARS-10/11 каждый admin route должен принимать только выделенную MFA-verified admin session, а каждая mutation проходит CSRF плюс token-free `IdpClient.revalidateAdminAuthority({ zitadelSessionId, sub })` из #1304 до validation/idempotency/upload/handler, пока public reads остаются zero-auth `public`. Security-floor refusals сохраняют non-disclosure: 401 `ADMIN_SESSION_REQUIRED` для absent/wrong/expired/fingerprint/MFA/CSRF или inactive/missing/mismatched provider session; 403 `PLATFORM_ADMIN_REQUIRED` при current-role loss; 503 `IDP_REVALIDATION_UNAVAILABLE` при provider transport/timeout/429/5xx/service-auth/config/malformed-shape failure, с сохранением local session и нулём side effects. Все ошибки — RFC 7807 Problem Details с `traceId` и точным `errorCode`: 400 `VALIDATION_FAILED | MEDIA_INVALID | MEDIA_INPUT_CONFLICT | CURSOR_INVALID | IDEMPOTENCY_KEY_INVALID`; 404 `RESOURCE_NOT_FOUND`; 409 `RELATIONSHIP_CONFLICT | SLUG_CONFLICT | SLUG_IMMUTABLE | PUBLISH_REQUIREMENTS_NOT_MET | PUBLISHED_PROJECT_REQUIRES_CURATOR | INVALID_TRANSITION | LEGACY_SPEAKER_CONFLICT | SPEAKER_POSITION_OCCUPIED | PD_ERASED | IDEMPOTENCY_KEY_REUSED | IDEMPOTENCY_REQUEST_IN_PROGRESS`; 412 `PRECONDITION_FAILED | LIFECYCLE_IMPACT_STALE`; 415 `UNSUPPORTED_MEDIA_TYPE`; 428 `IDEMPOTENCY_KEY_REQUIRED | PRECONDITION_REQUIRED | LIFECYCLE_IMPACT_REQUIRED`; 503 `MEDIA_STORAGE_UNAVAILABLE | IDP_REVALIDATION_UNAVAILABLE`.
- **EARS-17** _(realizes: US-7, US-10, US-11)_ — Система должна требовать один canonical UUID `Idempotency-Key` для каждого mutating HTTP endpoint; absent/blank даёт 428 `IDEMPOTENCY_KEY_REQUIRED`, malformed/non-canonical — 400 `IDEMPOTENCY_KEY_INVALID`, оба до upload, ownership, domain или audit side effects. Fingerprint включает concrete target params, canonical JSON/normalized-output digest, `If-Match` и `Lifecycle-Impact-Token`; изменённый semantic input или другой normalized output/digest с тем же ключом даёт 409 `IDEMPOTENCY_KEY_REUSED`. В 24-часовом active-окне scope хранит только purpose-keyed actor digest плюс method/route template, никогда raw `sub`, а каждое request/cleanup lease acquisition увеличивает monotonic `lease_epoch`; heartbeat и completion обусловлены owner+epoch+purpose. Каждое deterministic post-claim completion, включая отказы 409/412, fenced и сохраняет точные status/body плюс разрешённые `ETag`/`Location` в той же транзакции, что возможные domain/audit writes, поэтому same-key retry повторяет тот же исход, а stale owner откатывает всё; PD-bearing responses дополнительно хранят sorted active-only `pd_subject_refs`, чтобы approved erasure мог fence и minimize каждый relevant claim. Provider/DB faults без достоверного terminal verdict остаются явно takeover-eligible. Только request takeover может HEAD/reuse/upload и продолжить command; отдельно захваченный cleanup lease никогда не входит в domain handler и лишь удаляет unreferenced claim object/помечает abandonment. На границе 24 часов, независимо от доступности object storage, expiry UPDATE переводит row в `expired` + `deleted_at` и очищает response payload/headers, request fingerprint, upload digest/object key, actor digest, `pd_subject_refs` и все content inputs. Он сохраняет только keyed request-key digest, method/route template, terminal lifecycle fields и non-content cleanup handle, пока cleanup pending, без delete/reactivate/reuse; recurring reconciliation перепроверяет abandoned/expired claims до отсутствия unreferenced claim object, включая поздний PUT stale owner, а каждое последующее использование ключа в этом method/route scope даёт 409 `IDEMPOTENCY_KEY_REUSED`. Этот claim cleanup отделён от retained cleanup старой ссылки после committed media replace/clear из LD-8. По LD-1 method-specific ETag preconditions предотвращают lost writes; LD-2/LD-4 сериализуют и повторно проверяют dependencies. Каждая committed mutation taxonomy entity, relationship или speaker-domain получает audit capture фичи 010 в той же транзакции; `idempotency_keys` и `media_cleanup_jobs` остаются explicit parity-tested technical-table audit exclusions фичи 010.
- **EARS-18** _(realizes: US-1, US-2, US-3, US-4, US-5, US-6, US-7, US-8, US-9)_ — До старта любого нового/изменённого taxonomy/event-admin UI slice команда должна завершить Stage A: выполнить `build-ui-from-design-system`, представить 2–3 Refine-композиции и записать выбор владельца; реализация использует `@ds/design-system` с полными states и без Delete UI, а реальный результат проходит live Playwright и owner Stage B до merge.

## Инварианты

- Ни одна сущность таксономии, джойн или мигрированная legacy-строка спикера физически или каскадно не удаляется; стабильные ids/slugs/pairs не переиспользуются.
- Slug редактируется только пока `first_published_at IS NULL`; retire и restore никогда не сбрасывают этот постоянный identity-lock. Единственное исключение — ADR-0009 erasure PD эксперта, заменяющее readable identity на минимизированный retained tombstone, пока mandatory keyed digest запрещает reuse старого slug.
- `retired ⇔ deleted_at IS NOT NULL`; обычное восстановление сущности даёт `draft`, обычное восстановление джойна/migrated speaker — `active`, а erased expert или migrated legacy speaker возвращает 409 `PD_ERASED`.
- У каждого published-проекта ровно один active curator с published/non-retired экспертом; замена атомарна, прямая инвалидация запрещена.
- В каждой committed-проекции спикеров события не более одной видимой строки на position; expert-speaker writes 012 блокируют затронутых экспертов до event, а legacy-speaker writes 007 и publish/retire связанного эксперта используют те же затронутые per-event boundaries в глобальном порядке expert→project→event.
- Подтверждение retire и restore принимается только для неизменившегося transition-specific подписанного dependency snapshot, который видел оператор.
- Публичная связь видима только при active-джойне и published/non-retired концах таксономии.
- Сопоставленная legacy-строка спикера остаётся сохранённой и неизменной при обычном matching/lifecycle; единственное исключение стирания значений — одобренная ADR-0009 команда над явно mapped `event_speakers.name`/`event_speakers.regalia`, чей `pd_erased_at` tombstone нельзя restore/repopulate, а единственное правило подавления в проекции — явное допустимое сопоставление.
- `specialties[]` и topics — разные оси и никогда не синхронизируются.
- Одна авторская Postgres-строка питает admin и public проекции; export/sync/fake seam нет.
- Product retire эксперта обратим; lawful PD erasure отделён от него, сохраняет DB tombstones, разрешает каждый sole-curator project атомарной заменой или retire, стирает каждую explicitly linked copy/media/replay и не оставляет ни невалидного published-проекта, ни unclassified plaintext PD в текущем или историческом audit evidence.
- Idempotency rows используют fenced request/cleanup leases, истекают retained-lifecycle UPDATE-переходом, очищают каждый payload/fingerprint/upload reference и никогда физически не удаляются или переиспользуются; по явному allowlist фичи 010 они не создают domain-audit rows.

## Зависимости и последовательность

- Фича 007 даёт существующую форму мероприятия и legacy-проекцию спикеров; #1278 делает speaker rows стабильно retained, а 012 добавляет явный expert match/current-projection без поломки немигрированных событий.
- GitHub [#1278](https://github.com/doctor-school/ds-platform/issues/1278) — critical-path runtime prerequisite после merge спеки и speaker-PD masking/remediation из #1305, и до любой новой entity 012: он владеет retained-row conformance текущих таблиц, UUID-PK `event_speakers` с partial active-position uniqueness и `UNIQUE(event_id,id)`, общей parent-event блокировкой, retained idempotency lease/takeover/expiry/payload-minimization и удалением существующих cascade/delete paths. 012 потребляет этот runtime и не дублирует его.
- GitHub [#1304](https://github.com/doctor-school/ds-platform/issues/1304) должен inline-согласовать ADR-0001/011 и поставить token-free IdP authority-revalidation port до первой taxonomy mutation vertical; ни один handler не хранит user IdP token и не превращает provider outage в 401.
- GitHub [#1305](https://github.com/doctor-school/ds-platform/issues/1305) должен получить свежее explicit Product Lead и Legal/Compliance sign-off и закрыть ADR-0009 classification/remediation для experts, legacy speakers, joins, historical audit и каждой public/cache replica до следующей affected speaker-write из #1278 и до миграции `experts`; #1284 реализует expert/legacy erasure surface и proofs. #1283 первым поставляет shared normalizer плюс retained old-reference cleanup queue, которые потребляют #1284/#1286.
- Фича 010 даёт generic audit capture; каждая новая entity/join/speaker-domain таблица должна попасть под его coverage guard, а каждый technical-table exclusion — под явный allowlist parity guard.
- 013–016 потребляют публичное API только после попадания этой спеки в `main`; весь врачебный рендеринг принадлежит им.
- EARS-18 Stage A — первый UI-гейт и блокирует UI-части EARS-1…15; каждый entity kind и каждый join/projection остаётся отдельным bounded vertical slice, а не одним CRUD issue на четыре сущности.
- Исполнимый порядок срезов: project → expert → topic → partner → `project_experts` → `event_experts` → publication → остальные joins/projections → cross-route verification. Поэтому обе реальные связи существуют до того, как EARS-5 пытается опубликовать проект с допустимым куратором или эксперта с повторной проверкой speaker-visibility на связанных мероприятиях.
- EARS-16 и EARS-17 — сквозные критерии приёмки каждого применимого read/mutation начиная с первой project-вертикали. Их поздние WBS-дети — verification sweeps по уже compliant real handlers, а не отложенная реализация протокола или scaffold seam.
