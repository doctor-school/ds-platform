# 019 — Лента событий врача (Требования)

## Действующие решения Stage-A

Все четыре развилки PRD закрыты; ничего ниже их не переоткрывает.

| Развилка    | Решение                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **F-019-1** | **Б — панель фасетов: боковая панель на десктопе, шторка на мобильном.** Выбор владельца 2026-08-25, дословно «Б — боковая панель (Рекомендуется)». Умолчание канваса `panelVariant` `А` (строка чипов над лентой) отменено; варианты А и В не собираются.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| **F-019-2** | **Б — календарь месяца и лента по дням показываются одновременно**, месяц как навигация, лента как тело. Выбор владельца 2026-08-25, дословно «Б норм, но тогда надо предусмотреть отдельую страницу с календарём по анаогии с той, что мы сделали в Академии». Выбор несёт **условие владельца — отдельная страница календаря по аналогии с Академией**, и его владеет **EARS-5**, оно не отложено. Переключатель «один вид за раз» варианта А не собирается: при Б строка вида «Неделя / Месяц» не рисуется вовсе — решение владельца 2026-08-26, дословно «Убрать переключатель». Навигация по времени при Б — это лента по дням, сетка месяца в ленте (EARS-4) и отдельная страница календаря (EARS-5); единственный контрол уровня вида на экране — строка времени (Будущие / Прошедшие), и в релизе 1 эта строка не рисуется вовсе: лента только «Будущие» по **LD-10**, а строка приходит в волне 2 вместе со срезом «Прошедшие» ([#1525](https://github.com/doctor-school/ds-platform/issues/1525)). |
| **F-019-3** | **А — «Идёт сейчас» это блок над лентой.** Выбор владельца 2026-08-25, дословно «А — блок над лентой (Рекомендуется)». Закреплённая строка (Б) и выделенная карточка внутри дня (В) не собираются.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| **F-019-4** | **N/A — не продуктовая развилка.** `filterWave` — умолчание просмотра канваса; по решению владельца **D-1** все три состояния наполнения панели — волна 1, промежуточное, полный набор — остаются обязательными для юнита. Какие фасеты собирает сама 019 — решение уровня спеки, зафиксировано как **LD-4**.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |

Состояния канваса — не развилки, а обязательства от данных, которые обязана отрабатывать каждая поверхность 019: `loggedIn` (гость / вошёл) и `dataState` (`обычно` · скелет загрузки · пусто по фасетам · пусто по специальности · ошибка · нет живого эфира), плюс собственные состояния карточки (обычная, наведение, фокус, «вы записаны», «мест не осталось», «идёт сейчас», «прошло — есть запись»). Стенд состояний `cardBoard` — средство дизайн-ревью, он не собирается.

## Результаты

- Врач открывает «События» и за один экран узнаёт, что идёт прямо сейчас, что будет на этой неделе по его специальности и что он пропустил из того, у чего есть запись, — без поиска и не покидая витрину врача.
- Календарь месяца и лента по дням стоят рядом (F-019-2): «что в четверг» отвечает лента, «что вообще в этом месяце» — календарь рядом, и врач не меняет один вопрос на другой.
- Есть отдельная страница календаря по аналогии с Академией — для врача, который пришёл спланировать месяц, а не выбрать вечер (условие владельца при F-019-2).
- Каждое событие с аудиторией «врачи» (LD-11) любого вида — Вебинар, Эфир, Конгресс, Встреча клуба, Мастер-класс и любой вид, который редактор добавит в открытый справочник (LD-12), — живёт в одной ленте, каждый формат (онлайн / офлайн / гибрид) различим с одного взгляда, а офлайн-событие всюду несёт город и остаток мест.
- Общая панель `events-filter` вырастает здесь до полного набора фасетов врача (LD-4) в виде **боковой панели на десктопе и шторки на мобильном**, и каталоги Академии дальше переиспользуют тот же юнит, а не копию.
- Состояние ленты адресуемо: время, применённые фасеты и горизонт живут в URL, поэтому ссылка, кнопка «назад» и возврат из регистрации приводят на тот же экран, который врач оставил.
- Пустой страницы не бывает: пустой результат по фасетам называет условие, пустая специальность предлагает смежные области, читающийся блок показывает скелет, а упавший — причину по-русски и рабочий повтор.
- Лента не переизобретает движок: листинг и `WebinarCard` приходят из 004, записи — из 014, комната — из 006, а 019 их композирует, расширяя только словарь форматов и видов карточки (REQ-137, LD-12).

## Рамки

**Входит:**

- **Маршрут событий** `#d-events` в `apps/doctor` на `doctor.school` внутри оболочки 017, с хлебными крошками «<специальность> › События» и заголовком экрана; релиз 1 **не рисует строку времени вовсе** и читает только «Будущие» по LD-10, строка приходит в волне 2 вместе со срезом «Прошедшие» ([#1525](https://github.com/doctor-school/ds-platform/issues/1525)).
- **Лента с группировкой по дням**, таргетированная специальностью врача и её набором смежности из управляемого таргетинга/смежности, поставленного в 017 по [#1484](https://github.com/doctor-school/ds-platform/issues/1484), но никогда не вычисленного здесь.
- **Календарь месяца рядом с лентой** по F-019-2 в роли навигации над тем же чтением, с «Сегодня» и пометкой живого эфира.
- **Отдельная страница календаря** по аналогии с месячным видом Академии — условие владельца при F-019-2 — как собственный маршрут `apps/doctor` над тем же контрактом чтения (EARS-5).
- **Блок «Идёт сейчас» над лентой** по F-019-3 со счётчиком присутствующих: записанный врач попадает в комнату 006, остальные — на страницу события 020; живого эфира нет — блока нет, а не пустой блок.
- **`WebinarCard` фичи 004** из `design-source/unit-event-card.dc.html`, расширенный здесь до полного словаря форматов, всегда показывающий счётчик записавшихся, город и остаток мест для офлайна, стоимость только в Pul с нулём как «бесплатно для врача» и НМО только бейджем.
- **Панель `events-filter`** как общий юнит дизайн-системы в форме F-019-1 (боковая панель на десктопе, шторка за кнопкой «Фильтры» со счётчиком на мобильном), несущая полный набор REQ-138, показывающая применённые фасеты со сбросом и корректно отрисованная во всех трёх состояниях наполнения D-1.
- **Состояние ленты в URL** — время, применённые фасеты и горизонт — как единственный источник состояния экрана (LD-1).
- **Срез «Прошедшие»**, перечитывающий те же карточки с записью и материалами фичи 014 вместо действия записи, — **работа волны 2** по срезу А1 для релиза 1 (груминг владельца 2026-09-01, [#1703](https://github.com/doctor-school/ds-platform/issues/1703)), поскольку он читает записи 014; релиз 1 поставляет только «Будущие», обязательство остаётся открытым как [#1525](https://github.com/doctor-school/ds-platform/issues/1525).
- **Краткий срез «Мои события»** для вошедшего врача со ссылкой «Все мои события в личном кабинете →» в `#d-lk`, у гостя отсутствующий полностью (D-2), — **работа волны 2** по тому же срезу, отслеживаемая [#1526](https://github.com/doctor-school/ds-platform/issues/1526); релиз 1 не рисует ни среза, ни заглушки на его месте.
- **Гостевой путь чтения**: вся лента и календарь читаются без учётной записи, действие на карточке уводит в фичу 021 и возвращает ровно в то состояние ленты, которое было.
- Все состояния `dataState` — скелеты ленты и сетки месяца, два разных пустых состояния, ошибка блока с повтором — и состояние «нет живого эфира».
- Паритет на 390, обе темы и планка `playwright-axe` на маршруте событий и на странице календаря — прогон ([#1528](https://github.com/doctor-school/ds-platform/issues/1528)) покрывает только поверхности релиза 1 и не ждёт ни среза «Прошедшие», ни среза «Мои события» из волны 2.

**Не входит:**

- **Сама комната эфира** — фича **006**: единый общий юнит комнаты, который каждая витрина монтирует тонким маршрутом на своём хосте: цель извлечения — пакет `packages/room` (`@ds/room`), маршрут врача — `/events/[slug]/room` (извлечение — [#1722](https://github.com/doctor-school/ds-platform/issues/1722)); 019 рисует только вход в комнату на хосте витрины врача.
- **Страница события** `#d-event` — фича **020**; в неё ведут все карточки и блок эфира.
- **Регистрация и согласия** — фича **021**; 019 задаёт только переход в неё и цель возврата.
- **Полный раздел «Мои события», билеты на конгресс и чекины НМО** — `#d-lk` (фича **022**), фичи **020** / **038**. Срез 019 перечисляет записи и ведёт наружу; билета, QR и чекина он не рисует.
- **Производство записей и состояния монтажа** — фича **014**; 019 ссылается на опубликованное и не моделирует состояний монтажа.
- **Движок листинга и базовая анатомия карточки события** — фича **004**; 019 их композирует, расширяет словарь форматов общего юнита и не создаёт своей копии (REQ-137).
- **Управляемый таргетинг специальностей и смежность** — поставка фичи **017** по [#1484](https://github.com/doctor-school/ds-platform/issues/1484); 019 потребляет разрешённый набор и не определяет собственной смежности. Фича 018 владеет только своим отрисованным блоком смежных областей.
- **Поверхности Академии** — проекты, партнёры, подкасты Академии и новости Академии (NG-2, REQ-24).
- **Создание события / конструктор мероприятий** — фича **041**, волна 7.
- **Фронт конгресса** — фича **026**; события конгресса живут в этой ленте как формат (LD-5), собственная поверхность конгресса — нет.
- **Экраны мобильного приложения** — отдельный трек (F-4).
- **Обсуждение в сообществе из US-11** — «Прошедшие» дают запись и материалы (EARS-10), а половина «перенести обсуждение в сообщество» **отложена**. Связи «событие → сообщество» в модели нет, поверхности сообществ — фичи **027** / **022**, и выбор сообщества для обсуждения события это продуктовое решение, а не деталь отрисовки. Ни ссылки на обсуждение, ни выбора сообщества, ни заглушки в 019 не появляется; отсрочка ведётся отдельным Issue у родителя 019 (#1532) и вынесена в открытые вопросы ниже.
- **Юридическая маркировка партнёрских материалов** — CON-8 / CON-14 отдают обязательство маркировки (правовая квалификация, ответственное лицо, ERID, ОРД) фичам **040** / **024**. 019 своей маркировки не рисует и поля маркировки не моделирует.

## Ограничения

- **019 гейтят точные артефакты, а не завершение родителей.** Она потребляет оболочку [#1478](https://github.com/doctor-school/ds-platform/issues/1478), выбор специальности [#1482](https://github.com/doctor-school/ds-platform/issues/1482), управляемый таргетинг/смежность [#1484](https://github.com/doctor-school/ds-platform/issues/1484) и общий `WebinarCard` фичи 004. Ни один пункт 019 не может быть закрыт переизобретением оболочки, карточки или правила смежности и ни один — сборкой внутри `apps/promo` или `apps/portal`; незавершённые несвязанные дети 017 или 018 не являются общими блокерами.
- **Одна кросс-фронтовая способность событий, а не только общая картинка.** У ядра домена/запросов событий, переносимого кодека URL-состояния, сеток месяца, карточки, независимого от маршрута блока ленты, состояния комнаты, политики регистрации/входа и проекции записей/архива фичи 014 есть названные канонические владельцы в матрице design-документа. Academy и Doctor могут публиковать тонкие проекции со своими дефолтами, таргетингом, конвертами ответа, маршрутами и композицией, но эти проекции делегируют одному ядру. Если переиспользуемая реализация Academy локальна в приложении или её общий вынос ещё открыт, Doctor ждёт зафиксированного владельца (#1346 для `EventList` + архивного состояния), а не создаёт конкурента. Второе ядро запросов, URL-кодек, комната, машина LIVE-состояний, проекция записи или copy/fork UI-блок — дефект; прямые импорты между приложениями запрещены (D-3, ADR-0013 A1, REQ-137).
- **Нигде не говорится, кто платит.** Стоимость выражается только в очках внимания Pul, нулевая читается «бесплатно для врача». Ни одна строка ни в одном состоянии, брейкпоинте и теме не называет источник финансирования события, и формулировок «кто платит» нет ни в интерфейсе, ни в полях ответа.
- **Канон глоссария.** Если организация за платформой вообще названа — это «инвестор (организация)» / «первоинвестор»; «партнёр» никогда не используется как носитель денег в строке, обращённой к врачу.
- **Никакой коммерции.** Ни цены в рублях, ни корзины, ни подписки, ни платёжного действия ни на одной поверхности 019 (REQ-48, NG-5 / CON-16).
- **НМО — атрибут и фасет, но не заголовок.** НМО может пометить событие и сузить ленту; заголовком экрана и главным фильтром он не становится (NG-1).
- **Никакого инфошума Академии.** Подкасты Академии, новости Академии, новости партнёров, карточки проектов и служебная навигация не появляются ни в одном блоке ленты; слово «проект» не встречается ни в одной строке, обращённой к врачу (NG-2, REQ-24). **Подкаст-эфир** — событие собственной ленты врача, а не медийный шум Академии: различие в сущности, а не в теме.
- **По умолчанию публично.** Вся лента, календарь и страница календаря читаются без учётной записи. Вход меняет то, что делает действие, но не то, что можно прочитать.
- **Незаписанный врач не попадает в комнату из ленты.** Действие блока эфира ведёт в комнату 006 только при наличии регистрации на это событие; любой другой читатель уходит на страницу события 020.
- **Честные состояния, без заглушек.** Каждый блок показывает ровно одно из: содержимое, скелет, честное пустое утверждение или явную ошибку по-русски с рабочим повтором. Пустая подписанная коробка, незавершающийся спиннер, мёртвый контрол и заглушка «скоро» вместо недостающего результата — каждое не проходит ревью.
- **Только дизайн-система.** Все элементы — примитивы `@ds/design-system` со всеми состояниями взаимодействия и стилизацией только токенами; завендоренный канвас — источник композиции, а его стенд `cardBoard` — средство ревью, которое не собирается.

## Prior decisions (предшествующие решения)

- **ADR-0015 §2:** лента событий и страница календаря — маршруты `apps/doctor`; публичные страницы витрины статические или ISR, авторизованные виды — SSR с host-only cookie сессии, поэтому блок эфира и «Мои события» — две зависящие от читателя части экрана.

- **ADR-0016 §5:** закрытый справочник `specialties_minzdrav` и открытый `directions` со смежностью как взвешенной само-связью — основа таргетинга «моя и смежные» и запасного варианта при пустой специальности.

- **Фича 017** владеет оболочкой, справочниками, запомненным выбором и управляемым таргетингом/смежностью, поставленным по #1484. **Фича 004** владеет движком листинга, базовым `WebinarCard` и вышедшими по #1050 календарными юнитами `MonthCalendarGrid` / `MonthDotGrid`; 019 расширяет словарь форматов общей карточки и композирует существующие календарные юниты. **Фича 018** владеет своей карточкой контента врача и отрисованным блоком смежных областей, ни то ни другое не является основой этой ленты. **014** владеет записями, **006** — комнатой. 019 композирует эти артефакты и ничего из них не переизобретает.

## Технические решения ведущего

Каждое фиксирует выбор, который PRD оставил открытым. Это решения ведущего в смысле decision-debt AGENTS.md §6 — обратимые за объявленным контрактом и названные здесь, а не спрятанные в дизайне.

- **LD-1 — URL это единственный источник состояния ленты.** PRD помечает вопрос о персистентности URL нерешённым. 019 кладёт время (`upcoming` | `past`), каждый применённый фасет, горизонт и выбранный день в query-строку — параметра `view` нет, потому что F-019-2 Б рисует сетку месяца и ленту по дням одновременно, а переключатель «Неделя / Месяц» владелец убрал, — и отрисованный экран — чистая функция этого URL и сессии читателя. Ссылка воспроизводит экран у другого врача, кнопка «назад» ходит между состояниями ленты, а не выбрасывает из неё, а возврат из регистрации фичи 021 — просто тот URL, который врач оставил. Это же делает гостевой путь EARS-12 специфицированным возвратом, а не приблизительным, и закрывает для 019 тот самый вопрос, который 014 оставила открытым для своей вкладки «Прошедшие» — 014 может перенять контракт, не меняя свою модель чтения.
- **LD-2 — лента идёт до фиксированного горизонта и дальше листается; бесконечной прокрутки нет.** «Будущие» показывают ограниченный горизонт дней вперёд, «Прошедшие» — назад, у каждого явное «показать ещё», расширяющее диапазон в URL по LD-1. Глубина живёт в одном месте контракта чтения, поэтому её изменение — конфигурация, а не правка спеки; и экран с адресуемым состоянием не может быть одновременно безграничной прокруткой, позицию которой нельзя воспроизвести.
- **LD-3 — календарь в ленте и отдельная страница календаря это один юнит над одним контрактом чтения.** Сетка месяца из F-019-2 и страница календаря по условию владельца рисуют один и тот же юнит `webinars-month` над тем же таргетированным чтением; страница отличается лишь тем, что месяц там тело, а не навигация, и что у неё свой маршрут, свои хлебные крошки и полноширинная композиция. Два календаря над двумя чтениями разъедутся за один релиз; так условие владельца стоит маршрута и раскладки, а не второго механизма.
- **LD-4 — 019 собирает полный набор фасетов врача, и панель всё равно обязана всем трём состояниям наполнения D-1.** PRD сознательно оставляет открытым «какие фасеты едут в волне 1 самой 019». Набор врача — формат (онлайн / офлайн / гибрид), вид (открытый справочник видов события, LD-12), специальность, город для офлайна, «только с НМО», направление и поиск по названию; каждый читает атрибут, который несёт модель события, поэтому подмножество ничего бы не отложило, но выдало бы врачу панель, отвечающую на меньше вопросов, чем умеет лента. Фасета «бесплатно по Pul» в наборе нет — решение владельца 2026-10-01, дословно «"бесплатно по Pul" - это можно убрать, они все будут бесплатными для врачей». Фасет темы — **направление** (темы фичи 012, таблица `directions`), пока таксономия медицинских тем не наполнена. При этом юнит панели объявляет и рисует состояния «волна 1», «промежуточное» и «полный набор» (D-1), потому что каталоги Академии смонтируют её с меньшим числом фасетов, и сетка обязана держаться в каждом из них.
- **LD-5 — конгресс это формат карточки в этой ленте, а не собственная поверхность.** PRD отмечает противоречие: события конгресса появляются в волне 1, а фронт конгресса — фича 026 поздней волны. 019 трактует конгресс как значение формата: он рисуется той же карточкой, может занимать несколько дней и быть гибридным и ведёт на страницу события 020, как любой другой формат. Фича 026 позже добавит собственный фронт конгресса, не меняя эту ленту: лента показывает события, а событие конгресса — событие.
- **LD-6 — блок эфира разрешается на сервере и гасит себя сам, никакой клиентской выдумки «живого».** «Идёт сейчас» рисуется из состояния комнаты, которое публикует фича 006, вместе с приходящим оттуда счётчиком присутствующих; блок обновляется с ограниченным интервалом и исчезает по окончании эфира, а не застывает с устаревшим LIVE. Клиент никогда не выводит «идёт сейчас» из времени старта, а когда живого нет — блока нет в дереве, а не есть пустой, и дыры в сетке он не оставляет (REQ-137).
- **LD-7 — цель гостевого действия сохраняется, а не выводится заново.** Действие гостя на карточке уносит в фичу 021 и событие, и URL ленты из LD-1, а 021 возвращает врача на этот URL с возобновлённым действием на той же карточке. Никакой эвристики «последняя страница», никакой крошки в сессии и никакого приземления на состояние ленты по умолчанию после регистрации.
- **LD-8 — «Мои события» это срез по читателю с настоящей целью, поставленный за своими зависимостями и вынесенный из релиза 1.** Блок читает собственные регистрации вошедшего врача (их создаёт фича 021) и ведёт в `#d-lk` (фича 022). Срез А1 для релиза 1 (груминг владельца 2026-09-01, [#1703](https://github.com/doctor-school/ds-platform/issues/1703)) помещает его в **волну 2** вместе со срезом «Прошедшие», который ждёт записей 014; релиз 1 не рисует ни того, ни другого, и на их месте нет ни пустого списка, ни маркера «скоро». Он едет за обеими зависимостями: его Issue `blocked_by` 021 по данным и 022 по цели ссылки, а не раньше — с пустым списком или ссылкой в никуда. У гостя блока нет вовсе (D-2), и билета, QR и чекина здесь не рисуется.
- **LD-9 — пустая специальность и пустой результат по фасетам это два разных состояния.** «По вашим фильтрам ничего нет» называет самое узкое применённое условие и предлагает ослабить именно его; «в вашей специальности пока ничего нет» предлагает ближайшие события смежных областей из управляемого артефакта таргетинга/смежности 017 #1484. Слить их в одно означало бы предложить врачу редкой специальности ослабить фильтр, который он не ставил.
- **LD-10 — в релизе 1 ни один маршрут 019 не рисует контрол времени: отложенное отложено, а не заглушено.** Срез А1 для релиза 1 (груминг владельца 2026-09-01, [#1703](https://github.com/doctor-school/ds-platform/issues/1703)) отправляет срез «Прошедшие» в волну 2 за записями 014 ([#1525](https://github.com/doctor-school/ds-platform/issues/1525)), и у строки остаётся один достижимый вариант. Контрол с единственным вариантом — мёртвый элемент, а выключенный второй вариант или маркер «скоро» — ровно та заглушка, которую запрещает LD-8; поэтому релиз 1 не рисует контрол времени ни на одном маршруте 019 — ни строку времени маршрута событий (EARS-1), ни контролы времени отдельной страницы календаря (EARS-5); оба читают время `upcoming`, зафиксированное горизонтом EARS-3, и оба получают контрол обратно в волне 2 вместе с «Прошедшие». Это универсальное правило владельца для поверхности без данных — заглушка или ничего, здесь ничего, — и та же форма, что LD-6 уже применяет к блоку эфира: отсутствовать в дереве, а не рисоваться пустым. Контракт URL из LD-1 не меняется: параметр `tense` остаётся в контракте чтения со значением по умолчанию `upcoming`, поэтому волна 2 возвращает контрол, не перекраивая кодек.
- **LD-11 — лента событий — один модуль на обеих витринах; витрина меняет только набор событий, набор фильтров и текст заголовка.** Решение владельца 2026-10-01. Карточка, лента по дням, календарь месяца и страница календаря, блок эфира, запись одной кнопкой, срез «Мои события», переключатель времени и состояния загрузки / пусто / ошибки / гостя — один и тот же модуль на витрине врача и в Академии, нарисованный один раз в [`events-feed.dc.html`](../../../../../../design-source/events-feed.dc.html) (+ `events-feed-month.dc.html`, в архиве с 2026-10-05 — см. «Amendment — 2026-10-05») за пропом `host`; `doctor-events.dc.html` поглощается им и уходит в архив. Три допустимых различия перечислены ниже в «Differences between storefronts»; любое другое различие витрин — дефект, а не продуктовый факт. **Набор событий** выбирается **на сервере** контрактом чтения каждого хоста — никогда не читается целиком и не прячется в клиенте, — и единственный выбор — **аудитория** события (012 LD-12, EARS-29), дословно «они четко делятся аудиториями, да, эксперты — это академия, врачи — это витрина врача»: контракт врача `GET /v1/storefront/doctor/events` читает каждое опубликованное событие с аудиторией `doctors` любого вида (EARS-16), и мобильное приложение читает тот же набор; контракт Академии `GET /v1/public/events` — только события с аудиторией `experts` (фича 004, Amendment 2026-10-01). Конкретное событие показывается ровно на одной витрине.
- **LD-12 — вид события — открытый справочник под управлением редактора, а не перечисление в коде.** Решение владельца 2026-10-01, дословно «урок - контент ленты специальности. Список видов события может пополняться. Надо как-то заложить возможность его расширения, он пока не фиксирован.» Вид — самостоятельная сущность фичи 012 (012 EARS-25…EARS-28), каждое событие ссылается ровно на один вид, а фасет вида и метка вида на карточке читают справочник, так что редактор добавляет вид в админке без изменения кода. Начальные виды, ровно пять, у каждого — допустимые форматы участия (012 LD-11): Вебинар {online} · Эфир {online} · Конгресс {offline, hybrid} · Встреча клуба {online, offline, hybrid} · Мастер-класс {offline, hybrid}. **Формат** — отдельная закрытая ось: способ проведения онлайн / офлайн / гибрид, — и событие создаётся или сохраняется только с форматом, который допускает его вид; сужение вида никогда не переписывает существующие события, а существующее событие, чей формат вид больше не допускает, помечено в админке до следующего корректного сохранения, пока лента продолжает показывать его как есть (012 LD-11). Вид не несёт правила витрины; витрину выбирает только аудитория события (LD-11; 012 LD-12). Группировка — это проект, а не вид: Doctor Club — проект с аудиторией «врачи», его встречи — события вида «Встреча клуба», а карточка называет проект события; в ленте врача нет фильтра по проекту (владелец, дословно «Пока без фильтра»). **Урок** — не событие: это контент ленты специальности (фича 018), в эту ленту он не попадает.
- **LD-13 — «Прошедшие» — единственный механизм архива общей ленты на обеих витринах, с одним правилом группировки.** Решение владельца 2026-10-01: прошедшие события — это та же лента со временем в прошлом, а не отдельная страница или вкладка архива; отдельная вкладка архива Академии уступает место этому времени (фича 014, Amendment 2026-10-01). Группировка — одно правило на обеих витринах, выбранное лидом по практике просмотра: «Будущие» группируются **по дням**, ближайшие сверху, потому что ближний выбор — «какой вечер»; «Прошедшие» группируются **по месяцам**, новые сверху, потому что прошедших событий в день мало и их ищут по периоду, а не по вечеру. Группировка прошедших по месяцам открыта: её закрепит перерисованный канвас events-feed (#2076).

## Модель событий

### Команды

019 — поверхность чтения и **новых команд не вводит**. Записи, достижимые с неё, принадлежат другим фичам и выполняются на их поверхностях:

- `RegisterForEvent(eventId)` — фичи 021 / 005, вызывается действием на карточке и возвращает на URL ленты из LD-1 / LD-7.
- `EnterRoom(eventId)` — фича 006, вызывается из блока эфира записанным врачом.
- `ChangeSpecialty(specialtyId)` — фича 017, из хлебных крошек.

### События

019 доменных событий не порождает. Он **потребляет**:

| Потребляемое событие              | Эффект на экране                                                                                                                                                 |
| --------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `SpecialtyChosen` (017)           | Лента, календарь и страница календаря существуют для этого актора и таргетированы специальностью и её смежными областями.                                        |
| `SpecialtyChanged` (017)          | Лента, сетка месяца и панель фасетов перечитываются под новую специальность; оставшиеся валидными фасеты сохраняются, остальные снимаются, и об этом сообщается. |
| `RoomOpened` / `RoomClosed` (006) | Блок эфира появляется со счётчиком присутствующих и исчезает из дерева по окончании эфира (LD-6).                                                                |
| `RecordingPublished` (014)        | Карточка прошедшего события получает состояние «прошло — есть запись» и ссылку на запись и материалы.                                                            |
| `RegistrationCreated` (021)       | Карточка врача переходит в «вы записаны», а событие попадает в срез «Мои события».                                                                               |

### Модели чтения

- `DoctorEventsFeed { tense: 'upcoming' | 'past', facets: AppliedFacets, groups: DayGroup[] | MonthGroup[], horizon: { from, to, hasMore }, live: LiveStrip | null, myEvents: MyEventsCut | null }` — весь экран как функция URL (LD-1) и сессии; `groups` — дни в «Будущие» и месяцы в «Прошедшие» (LD-13).
- `DayGroup { date, weekday, items: PublicEventSummary[] }` — группировка «Будущие» по дням.
- `MonthGroup { month, items: PastEventSummary[] }` — группировка «Прошедшие» по месяцам, новые сверху.
- `EventKindRef { id, slug, title }` — одна запись справочника видов события фичи 012 (LD-12); набор видов читается, а не перечисляется в коде.
- `PublicEventSummary { id, href, startsAt, endsAt, format: 'webinar' | 'online-meeting' | 'offline-meetup' | 'congress' | 'podcast', kind, title, speaker, source, nmo: boolean, pulCost, signUpCount, city?, seatsLeft?, state: normal | registered | soldOut | live | recorded }` — содержимое карточки; `pulCost === 0` рисуется как «бесплатно для врача», и ни одно поле не называет источник финансирования.
- `MonthGrid { month, days: { date, count, hasLive }[], today }` — юнит месяца из LD-3, общий для календаря в ленте и страницы календаря.

- `FacetPanelState { fill: 'wave-1' | 'intermediate' | 'full', appliedCount, resetHref }` — состояния наполнения D-1, объявляемые общим юнитом.

- `MyEventsCut { items: PublicEventSummary[], cabinetHref }` — только для вошедшего (D-2, LD-8).
- `EmptyState { reason: 'no-match' | 'empty-specialty', narrowestFacet?, weakenHref?, adjacentAreas?: { direction, feedHref }[] }` — два разных состояния из LD-9.

### Политики

- Все чтения 019 публичны; сессия меняет только цель действия в блоке эфира, `state` карточки и наличие среза «Мои события».
- Отрисованный экран определяется URL и сессией и ничем больше (LD-1); никакая память о прошлом визите его не меняет.
- Таргетинг и направленная смежность разрешаются из управляемого артефакта 017 #1484; собственной логики смежности и собственного ранжирования у 019 нет.
- Блок эфира существует ровно пока 006 сообщает об открытой комнате таргетного события (LD-6).
- Прошедшее событие предлагает запись ровно тогда, когда 014 её опубликовала; отсутствие записи рисуется как карточка без действия записи, а не как мёртвая ссылка.

## Инварианты

- Экран рисуется внутри ровно одной оболочки — 017 — и не определяет собственных шапки, навигации и подвала.
- Ровно одна кросс-фронтовая реализация событий владеет состоянием листинга/чтения, календарём, карточкой, панелью фасетов, разрешением LIVE и политикой входа в комнату; у 019 нет приватной копии и параллельной машины состояний.
- Отрисованный экран — чистая функция URL и сессии читателя; состояния ленты, которое нельзя воспроизвести ссылкой, не существует.
- Блок эфира существует ровно пока 006 сообщает об открытой комнате, а вход в комнату доступен только записанному врачу.
- Каждая карточка в каждом состоянии показывает счётчик записавшихся; каждая офлайн-карточка показывает город и остаток мест.
- Ни одно поле ответа и ни одна строка фичи не сообщают, кто финансирует событие, и ни одна не несёт цены в рублях, корзины или подписки.
- Слово «проект» не встречается ни в одной строке, обращённой к врачу, и на поверхностях 019 нет содержимого и переходов Академии.
- НМО появляется только бейджем и фасетом, но не заголовком и не главным фильтром.
- Пустой результат по фасетам и пустая специальность — два разных состояния, и ни одно из них не пустая страница.
- Каждый блок рисует ровно одно из: содержимое, скелет, честное пустое утверждение, явную ошибку с рабочим повтором; упавшее чтение локализовано своим блоком.
- Срез «Мои события» существует только у вошедшего врача и никогда у гостя.

## Зависимости и последовательность

- **019 потребляет точные артефакты, а не завершение родителей.** Вышедшие оболочка #1478, выбор специальности #1482 и управляемый таргетинг/смежность #1484 — предпосылки. Ни один пункт 019 не может быть закрыт их переизобретением или ручным засевом смежности; несвязанные открытые дети 017 и 018 не гейтят независимые от маршрута основы 019.
- **Ацикличный порядок внутри одной WBS: основы → чтение → представление/состояния → первая публикация.** Независимые от маршрута общие основы [#1517](https://github.com/doctor-school/ds-platform/issues/1517) (компонент/showcase `WebinarCard`) и [#1522](https://github.com/doctor-school/ds-platform/issues/1522) (компонент/showcase `events-filter`) предшествуют API-only чтению [#1518](https://github.com/doctor-school/ds-platform/issues/1518), которое потребляет #1517, #1522 и #1484. Доказательство календарных компонентов [#1519](https://github.com/doctor-school/ds-platform/issues/1519) переиспользует `MonthCalendarGrid` и `MonthDotGrid` фичи 004 / #1050; чистый URL/query-state юнит [#1523](https://github.com/doctor-school/ds-platform/issues/1523) и независимая от маршрута матрица честных состояний [#1524](https://github.com/doctor-school/ds-platform/issues/1524) каждое потребляют #1518. Затем product-complete интеграция [#1516](https://github.com/doctor-school/ds-platform/issues/1516) интегрирует все Playwright-обязательства EARS-2/3/4/7/8/9 на уровне маршрута и впервые публикует `/events` внутри оболочки #1478, потребляя #1519, #1523, #1524 и исправление порядка [#1620](https://github.com/doctor-school/ds-platform/issues/1620).
- **[#1516](https://github.com/doctor-school/ds-platform/issues/1516) — явная отслеживаемая отложка внутри той же WBS, а не скаффолд.** Предшествующие дочерние задачи основ/чтения не открывают частичный маршрут. Первый публичный `/events` включает хлебные крошки, заголовок, адресуемое в URL время, унаследованную оболочку, порядок канваса, календарь и честные состояния; области контента, которыми владеет более поздний handler, отсутствуют, а не рисуются пустыми подписанными коробками, стабами, заглушками или маркерами «скоро».
- **EARS-8 предшествует EARS-12.** Гостевой возврат LD-7 — это контракт URL из LD-1; до адресуемого состояния цели возврата не существует.
- **EARS-6 зависит от фичи 006** по состоянию комнаты и счётчику присутствующих, от извлечения [#1722](https://github.com/doctor-school/ds-platform/issues/1722) — по общему юниту комнаты `packages/room` (`@ds/room`) и маршруту врача `/events/[slug]/room`, и от фичи 020 по адресу для незаписанного.
- **EARS-10 зависит от фичи 014** по опубликованным записям и материалам; 019 рисует опубликованное и никогда подмену. Поэтому срез А1 для релиза 1 (груминг владельца 2026-09-01, [#1703](https://github.com/doctor-school/ds-platform/issues/1703)) помещает срез «Прошедшие» в **волну 2**, обязательство несёт [#1525](https://github.com/doctor-school/ds-platform/issues/1525).
- **EARS-11 заблокирована фичами 021 и 022** по LD-8 — 021 создаёт читаемые регистрации, 022 владеет целью `#d-lk` — и является работой **волны 2** по тому же срезу А1, обязательство несёт [#1526](https://github.com/doctor-school/ds-platform/issues/1526).
- **Прогон паритета мобильного брейкпоинта и axe из EARS-13 ([#1528](https://github.com/doctor-school/ds-platform/issues/1528)) покрывает только поверхности релиза 1.** Он не ждёт ни среза «Прошедшие», ни среза «Мои события»: каждый несёт собственное обязательство по паритету и axe, когда придёт в волне 2.
- **Фича 020** `blocked_by` 019 по анатомии карточки и переходу из ленты врача; зависимость идёт в одну сторону в каждом направлении, и ни одна фича не строит поверхность другой.
- **Каталоги Академии (фичи 030 / 031)** потребляют юнит `events-filter`, который выращивает EARS-7, и не должны его переопределять.

## Перенесённые открытые вопросы

Они остаются открытыми; выше каждый обойдён проектным решением, а не закрыт, и каждый остаётся продуктовым решением владельца.

- **Где живёт обсуждение события** — половина US-11 про сообщество отложена из 019 и ведётся отдельным Issue у родителя 019 (#1532). В какое сообщество попадает обсуждение события, задаётся ли связь на событие, школу или направление и что видит гость — решения владельца; 019 отдаёт «Прошедшие» с записью и материалами, не выдумывая адресата.
- **Какими фасетами врач реально пользуется** — LD-4 отдаёт полный набор фасетов врача; заслуживает ли каждый фасет места, покажет живой экран, и убрать один потом — это удалить фасет, а не размонтировать механизм.
- **Как глубоко идут «Будущие» и «Прошедшие» до постраничности** — LD-2 фиксирует ограниченный горизонт с «показать ещё»; конкретная глубина — конфигурация контракта чтения.
- **Вытянет ли фронт конгресса события конгресса из этой ленты** — LD-5 оставляет конгресс видом события здесь; фича 026 позже может добавить свою поверхность, не меняя ленту.
- **Что конкретно значит «моя и смежные»** — управляемым артефактом таргетинга/смежности владеет 017, он поставлен по #1484; 019 его потребляет и не определяет, а 018 владеет только своим отрисованным блоком смежных областей.
- **Перейдёт ли фича 014 на контракт состояния в URL** для своей вкладки «Прошедшие» — LD-1 закрывает вопрос только для 019.

**Происхождение.** Владелец 2026-10-01 решил, что список видов события открыт и пополняется редактором — дословно «урок - контент ленты специальности. Список видов события может пополняться. Надо как-то заложить возможность его расширения, он пока не фиксирован.» — поэтому вид становится записью справочника (LD-12; 012 LD-11, EARS-25…EARS-28), а не значением формата карточки.

**Правило.**

- **Формат** карточки — закрытая ось способа проведения `online | offline | hybrid`, различимая без вчитывания; `PublicEventSummary.format` становится `'online' | 'offline' | 'hybrid'`.
- **Вид** карточки — одна запись справочника видов события, `PublicEventSummary.kind: EventKindRef { id, slug, title }`, рисуемая меткой, которая выдерживает любое название вида, в том числе длинное, например «Клинический разбор с пациентом» (EARS-17).
- Метка формата из пяти значений уходит; вид берётся из пяти начальных видов справочника и любого вида, добавленного редактором, — Вебинар, Эфир, Конгресс, Встреча клуба, Мастер-класс (012 LD-11), — каждый допускает только объявленные форматы. Конгресс (LD-5) поэтому — **вид** события в этой ленте (Конгресс {offline, hybrid}), а не формат, и по-прежнему не собственная поверхность; он может занимать несколько дней.
- Параметр запроса `format` из `019-design.md` §7 после этого принимает три значения способа проведения; параметр `kind` — слаги справочника.

**Что не меняется.** Все остальные обязательства EARS-2 — общий `WebinarCard`, дата и время, спикер, школа-источник, НМО бейджем, стоимость в Pul с нулём как «бесплатно для врача», счётчик записавшихся в каждом состоянии, город и места для офлайна и отсутствие сведений о финансировании — и ссылка LD-5 на страницу события 020.

## Amendment — 2026-10-05 — лента событий по утверждённому канвасу: вкладки времени, месячный вид на той же странице, липкая колонка фасетов, ограниченный блок эфиров, три строки «Мои события» и цена только в Pul (источник: [#2569](https://github.com/doctor-school/ds-platform/issues/2569), решения владельца 2026-10-05)

> **Статус:** лента событий работает в продакшене на `/events` в композиции первого релиза, поэтому это записано как amendment, а не как inline-переписывание F-019-1, F-019-2, LD-10, LD-11, EARS-1, EARS-2, EARS-4…EARS-7, EARS-11, EARS-13, EARS-15 и строки `filterSet` раздела «Differences between storefronts» (AGENTS.md §6). Эти пункты остаются решением в исходном виде и читаются под этим amendment. EN-двойник — [`019-requirements-en.md`](./019-requirements-en.md) → «Amendment — 2026-10-05». Живое поведение не меняется, пока не приземлится срез кода [#2028](https://github.com/doctor-school/ds-platform/issues/2028).

**Происхождение.** 2026-10-05 владелец утвердил единый канвас ленты событий обеих витрин ([#2076](https://github.com/doctor-school/ds-platform/issues/2076), завендорен PR [#2567](https://github.com/doctor-school/ds-platform/pull/2567)): [`design-source/events-feed.dc.html`](../../../../../../design-source/events-feed.dc.html) с модулем `events-feed-kit.js` и панелью фасетов [`design-source/events-facets.dc.html`](../../../../../../design-source/events-facets.dc.html), переключаемый пропом `host`. Он поглощает `doctor-events.dc.html` и `events-feed-month.dc.html`, которые перенесены в архив `design-source/archive/` и больше не являются источником композиции. В том же ревью владелец подтвердил порядок и умолчание вкладок времени — дословно «Сначала прошедшие, потом - будущие … так и должно быть» — и то, что фраза подвала оболочки врача «Бесплатное образование для врачей.» остаётся.

**Правила.** Каждое правило действует на обеих витринах, потому что лента — один модуль (LD-11, EARS-18).

- **Вкладки времени (EARS-1, LD-10, F-019-2).** Шапка страницы несёт вкладки «Прошедшие | Будущие» в этом порядке, по умолчанию выбраны «Будущие», и в ленте, и в месячном виде. Правило первого релиза из EARS-1 и LD-10 о том, что контрол времени не рендерится, заменено. Время остаётся в URL с умолчанием `upcoming` (LD-1); чтение «Прошедшие» — это EARS-10, с группировкой по месяцам от новых к старым (LD-13).
- **Месячный вид — вид той же страницы (EARS-4, EARS-5, F-019-2).** Ссылка «Календарь на месяц →» переключает страницу в месячный вид, «← Лента событий» возвращает обратно; время и применённые фасеты переживают переключение. На десктопе ссылка стоит в шапке страницы, ниже — рядом с контролом «Фильтры». Месячный вид рендерит пикер месяца с листанием ‹ ›; при ширине ≥1024 px — 7-колоночную сетку месяца, где в дне не больше трёх плашек (время с поясом · название, live-плашка с пометкой «Идёт сейчас», прошедшие плашки приглушены, «сегодня» обведено) и «+N ещё» в этот день ленты, с легендой «Идёт сейчас · Запланировано · Прошло»; ниже 1024 px — сетку с точками и список выбранного дня. Ниже 1024 px нажатие на день показывает список этого дня под сеткой с точками; при ≥1024 px у ячейки дня в сетке месяца нет собственного действия — плашка открывает страницу события, а «+N ещё» открывает этот день в ленте. Клик по дню, переводящий ленту, принадлежит компактному месяцу боковой колонки ленты (следующее правило). **Отдельная страница календаря** EARS-5 как собственный маршрут заменена; маршрут один.
- **Колонка на десктопе и шторка на мобильном (EARS-4, EARS-7, EARS-13, F-019-1).** При ширине окна 1024 px и больше у страницы есть левая липкая колонка: в ленте — компактный месяц (сетка с точками и листанием ‹ ›, клик по дню переводит ленту на этот день) над панелью фасетов; в месячном виде — только панель фасетов. Так реализуется «месяц и лента дня одновременно» из EARS-4. Ниже 1024 px колонки нет: кнопка «Фильтры (N)» — N это число применённых фасетов, без них просто «Фильтры» — открывает ту же панель фасетов шторкой справа с «Сбросить» и «Показать N событий» (в Академии «Показать N эфиров»). Брейкпоинт 1024 px заменяет «десктопный» и «мобильный» брейкпоинты F-019-1, EARS-4 и EARS-13; все остальные обязательства EARS-13 (390 px, обе темы, `playwright-axe`, подписанные контролы) сохраняются, включая вкладки времени.
- **Блок эфиров (EARS-6).** Во вкладке «Будущие» блок «Идёт сейчас» рендерит **не больше двух** live-полос, сначала раньше начавшиеся; когда в эфире больше событий, ссылка «Ещё N в эфире →» ведёт на сегодняшний день ленты. Пока live-чтение в полёте, блок — скелетон; при ошибке блок говорит «Не удалось проверить, что сейчас в эфире» с повтором, а лента и «Мои события» продолжают работать. Все остальные обязательства EARS-6 сохраняются.
- **«Мои события» (EARS-11).** Вошедшему врачу во вкладке «Будущие» срез показывает **ближайшие три** будущих события, на которые он записан, без идущих в эфире, компактными строками (время с поясом · дата и школа · название), затем «Все мои события →» в «Мои события» личного кабинета; блок **отсутствует, когда список пуст**, и для гостя (D-2). Текст ссылки «Все мои события в личном кабинете →» заменён.
- **Цена на карточке (EARS-2).** Карточка показывает «N Pul» только когда событие требует Pul; у события без цены в Pul нет строки цены и нет формулировки о бесплатности — «бесплатно для врача» выводится из употребления. Цены в рублях нет, как и раньше. Фраза подвала «Бесплатное образование для врачей.» принадлежит оболочке врача (фича 017), а не карточке, и остаётся.
- **Фасет специальности (EARS-7, `filterSet`).** Группа «Специальность» панели фасетов врача предлагает два варианта — «Моя и смежные» (по умолчанию) и «Все специальности» — и комбобокс с поиском, выбирающий конкретные специальности; выбор специальностей заменяет охват этим списком, каждая выбранная специальность показывается применённым чипом, а снятие последней возвращает «Моя и смежные». Пустой результат из-за выбранной специальности предлагает «Показать смежные специальности» (LD-9).
- **Набор фасетов задаёт витрина (EARS-7, EARS-13, `filterSet`, LD-4).** Общий блок `events-filter` рендерит набор фасетов, который передаёт витрина, — строку `filterSet` раздела «Differences between storefronts»: набор врача (поиск по названию, специальность, формат, вид события, город с подсказкой про офлайн, «Направление», «Только с НМО») или набор Академии (проект, эксперт, тема) — под заголовком «Фильтры» с «Применено: N» и «Сбросить», как только что-то применено; каждое выбранное в комбобоксе значение показано снимаемым чипом под своим фасетом. Это заменяет три состояния заполнения D-1 из EARS-7 и `FacetPanelState.fill` в модели чтения, которая становится `FacetPanelState { host, appliedCount, resetHref }`. Устойчивость, которой EARS-7 требовал от состояний заполнения, сохраняется: фасет, для которого витрина не передала подписи или значения, не рендерится, а панель не задаёт собственной ширины и рамки — её размещают колонка на десктопе и шторка на мобильном.
- **Ссылки на канвасы (LD-11, EARS-15).** Там, где 019 называет архивные `events-feed-month.dc.html` или `doctor-events.dc.html`, читать `events-feed.dc.html` (его месячный вид) и `events-facets.dc.html`; гейт EARS-15 прогоняется против этих двух канвасов.

**Что не меняется.** URL как единственный носитель состояния (LD-1, EARS-8), серверный набор событий (EARS-16), справочник видов (EARS-17), один модуль с тремя допустимыми различиями витрин (EARS-18), правило гостя (EARS-12), правила пустых состояний и ошибок (EARS-9), правило «только события» (EARS-14) и правило времени из amendment 2026-10-02.
