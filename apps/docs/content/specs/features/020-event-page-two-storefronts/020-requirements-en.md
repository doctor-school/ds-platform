## Outcomes

- A doctor who arrives on a medical representative's link, out of the 019 events feed or out of the 018 specialty feed reads the whole event — description, programme, speaker, teaser, source school — **with no account**, and decides in seconds whether the evening is worth it.
- The page carries **exactly one call to action**, «Участвовать», and pressing it as a guest leads through feature 021's registration and back to **this exact page**, never to a cabinet or a home screen.
- **One page serves both storefronts.** `#d-event` on `doctor.school` and `#a-event` on `academy.doctor.school` are two thin host routes over one core; there is no second Academy event page, and the two hosts can never show a different event (D-4).
- **One page serves all three formats.** Online эфир, offline meet-up and hybrid differ in the **format block only**: the room for online, the address, the map and «как добраться» for offline, and both behind two tabs for hybrid (F-020-2 Б).
- A registered doctor **enters the live room on the storefront host they are already on** — for the doctor that is `apps/doctor` on `doctor.school`, never a hop to `academy.doctor.school` — over the one shared room UI unit above feature 006's unchanged engine.
- When offline seats run out the page is honest about it in the shape the owner picked: a hybrid event moves the doctor to online participation and says so; a pure offline event states «мест нет» and offers no dead CTA (F-020-3 Б).
- The page re-invents no engine: the public read, the lifecycle machine and the single-CTA contract come from **004**, registration from **005** / **021**, the room from **006**, recordings from **014**, and 020 composes them over one core while widening those contracts only at their canonical owners.
- What wave 1 cannot honestly ship — the points economy, live-эфир interaction, НМО check-ins, the ticket/QR unit, the post-event feedback block and the event-level partner link — is **absent from the page, not stubbed**, and each absence is a tracked obligation rather than a comment in the code.

## Constraints

- **One core, two thin host routes.** The event-page read model, the lifecycle resolution, the participation-CTA policy, the composed page unit, the format block, the room-entry policy and the URL/state codec each have exactly one canonical owner. `apps/doctor` and `apps/portal` add only a route, a header, an envelope and copy defaults. A second read model, a second CTA resolver, a second page composition, a rival room or a forked block is a defect, and direct `apps/doctor` → `apps/portal` imports are forbidden (D-4, ADR-0013 A1, AGENTS.md §6).
- **004 is extended at its canonical owner, never forked.** The `PublicEventPage` projection, the `EventLifecycleState` machine and the one-CTA contract of 004 EARS-3 are widened in place — in `packages/schemas/src/events/` and `apps/api/src/events/` — so the Academy surface that runs in production today gains the same behaviour rather than diverging from it. Nothing 004 / 005 / 006 / 014 ship in production may regress.
- **The doctor never leaves their storefront to take part.** Registration, the registered state and room entry all happen on `doctor.school`; a redirect to `academy.doctor.school` at any step of the doctor's funnel is a defect (ADR-0015 §4, [#1722](https://github.com/doctor-school/ds-platform/issues/1722)). «The doctor sees exactly one trace of the Academy» stays the single entry point recorded in ADR-0015 §4, and no backstage navigation is reachable from this page.
- **Exactly one CTA.** No «купить», «оставить заявку», «скачать» or second participation affordance exists in any state, at any breakpoint, on either host. In a state where participation is impossible the CTA is **absent**, never a dead or disabled control (004 EARS-4).
- **No financing statement, anywhere.** Cost is stated only in Pul attention points and a zero cost reads «бесплатно для врача». No rendered string and no response field in any state, breakpoint, theme or host names who funds an event; the legal advertising marking, when it lands, is features 040 / 024's and carries no payer wording either (CON-8, CON-14).
- **Glossary canon.** Where an organisation behind the platform is named at all it is «инвестор (организация)» / «первоинвестор»; «партнёр» is never used as the money-carrier in a doctor-facing string.
- **No commerce.** No price in roubles, no cart, no subscription and no payment affordance on any 020 surface (REQ-48, NG-5 / CON-16).
- **НМО is a badge and a conditions-line value, never the page headline** (NG-1).
- **Public by default.** The whole open part is readable with no account on both hosts, and the guest and signed-in renders of that part are content-identical. Signing in changes what the CTA does and which states exist, never whether the description is readable (004 EARS-1). No gated payload is delivered to the client and hidden there.
- **The room is never entered by an unregistered doctor.** Room entry resolves only for a doctor holding a registration on that event; every other reader gets the participation path instead (006, 019 EARS-6).
- **Honest states, no placeholders.** Every block renders exactly one of content, a skeleton, an honest statement or an explicit Russian-language error with a working retry. An empty labelled box, an unresolving spinner, a dead control and a «скоро» marker standing in for a deferred deliverable each fail review — and every wave-2 clause below renders **nothing at all** in release 3 rather than a placeholder (LD-8).
- **Design-system only.** Every element comes from `@ds/design-system` primitives with tokens-only styling and full interaction states; the vendored canvas is the composition source of truth, and the canvas's `board` fork stand is a review aid that is not built.

## Lead technical decisions

Each records a call the PRD left to engineering. They are lead decisions in the AGENTS.md §6 decision-debt sense — reversible behind a stated contract, and named here rather than buried in the design.

- **LD-1 — the event page is one core with two host routes, and the core is where 004 already lives.** D-4 says «one canvas, one page»; the mechanical reading of that is one **read model** (`EventPageView`, a widening of 004's `PublicEventPage` at its canonical owner in `packages/schemas/src/events/`), one **composed page unit** in `@ds/design-system`, and two routes that supply a host header, a route envelope and copy defaults. The Academy route is not «the old page kept alive»: `apps/portal`'s existing `/webinars/[slug]` composition is refactored onto the same unit in the same slice, so the two hosts cannot drift by construction rather than by review vigilance.
- **LD-2 — participation is one server-resolved policy object, not client-side branching.** The page reads a single `ParticipationCta { action, label, href, reason }` whose `action` is one of `register` · `registered` · `enter-room` · `switch-to-online` · `sold-out` · `unavailable`, resolved on the server from the lifecycle state, the viewer's registration, the format and the seat count. The client renders what it is given and computes no eligibility of its own. This is what makes «exactly one CTA» checkable, keeps the guest and signed-in renders honest, and stops the F-020-3 Б switch from becoming a rendering rule each host could interpret differently.
- **LD-3 — the doctor enters the room on the doctor host over the shared room UI unit.** Owner correction [#1722](https://github.com/doctor-school/ds-platform/issues/1722): the room **engine** of feature 006 stays single and unchanged, its composed **UI** becomes a shared cross-front unit under `packages/`, and each storefront mounts a thin route over it. 020 owns the **entry** — the CTA that resolves to that route for a registered doctor — and nothing inside the room. A doctor sent to `academy.doctor.school` to watch an эфир is a defect, not a shortcut.
- **LD-4 — the format block is the only format-varying part, and the hybrid tab is URL state.** Everything else on the page renders identically for online, offline and hybrid. The F-020-2 Б tabs write `mode=online|offline` into the query string, so a shared link reproduces the tab another doctor was looking at and the browser back button moves between tabs rather than off the page. The default tab is the one the server's participation policy resolves for that viewer, which is what lets F-020-3 Б land the doctor on «онлайн» when the offline seats are gone without a client-side redirect.
- **LD-5 — seats and the offline→online switch are facts of the read, not of the renderer.** `seatsLeft` and the F-020-3 Б switch resolve in the same server policy as the CTA (LD-2): a hybrid event with no offline seats returns `switch-to-online` with the reason stated, and a pure offline event returns `sold-out`. No waiting list exists in the model, so none can be half-built in the UI.
- **LD-6 — the cancelled-or-moved state is added to 004's one lifecycle machine, never beside it.** `EventLifecycleState` stays the single source of every rendered lifecycle signal across the feed, the card, the calendar and this page (004 EARS-9). The cancelled / rescheduled state the PRD needs is a value of that machine, added at its canonical owner, so a card and a page can never contradict each other about the same event.
- **LD-7 — a points statement is a ledger fact or it is absent.** Following the 021 EARS-9 precedent: the page renders the event's Pul **cost parameter** (configuration, and «бесплатно для врача» when it is zero) in release 3, and renders **no balance, no shortfall, no advance and no accrual** until feature 025 asserts them for that account. A configuration-derived stand-in for a ledger fact is forbidden, and so is a «скоро» marker in its place (EARS-12).
- **LD-8 — what is deferred is deferred, not stubbed.** Every wave-2 clause below renders nothing at all in release 3 — no disabled control, no empty labelled box, no «скоро». This is the same rule 019 applied to its LD-10 tense row and its LD-6 live block, and it is what keeps the F-22 «no untracked seam» rule true here, where six substantial product surfaces are consciously postponed.
- **LD-9 — the return target is carried, not re-derived.** The CTA carries the event and the page's own URL — including the F-020-2 Б tab — into feature 021, and 021 returns the doctor to that URL with the participation intent resumed. There is no «last page» heuristic, no session-stored breadcrumb and no landing on a cabinet or a feed after registering. This is the same contract 019 LD-7 established for its card action, and 021's return-context handling is its counterpart.
- **LD-10 — the Academy route ships in the same slice as the doctor route, not after it.** D-4 is a structural claim, and a structural claim proved by only one consumer is not proved at all. The slice that publishes `#d-event` also re-mounts `#a-event` on the same core, and the verification matrix carries a cross-host row that asserts the two renders are content-identical under different headers.

## Event Model

### Commands

020 is a read surface plus one context handoff; it introduces **no new commands**. The writes reachable from it belong to other features and are performed on their own surfaces:

- `RegisterForEvent(eventId)` — features 021 / 005, entered from the single CTA and returning to this page's URL (LD-9).
- `CancelRegistration(eventId)` — feature 005, reached from the registered state of the sticky card.
- `EnterRoom(eventId)` — feature 006, reached from the live CTA on the doctor storefront host (LD-3).

### Events

020 emits no domain events. It **consumes**:

| Consumed event                                     | Effect on the page                                                                                                                                                 |
| -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `EventPublished` / `EventStateChanged` (004 / 007) | The page becomes publicly reachable, or moves to the live, ended, archived or cancelled render of the one lifecycle machine (LD-6).                                |
| `RoomOpened` / `RoomClosed` (006)                  | The CTA becomes room entry with the presence count, and returns to its non-live resolution when the эфир ends; the client never infers liveness from a start time. |
| `RegistrationCreated` (021 / 005)                  | The sticky card moves to «Вы записаны» with the calendar add, the cancel affordance and the link into «Мои события».                                               |
| `RegistrationCancelled` (005)                      | The sticky card returns to the participation CTA for that viewer.                                                                                                  |
| `RecordingPublished` (014)                         | The ended page gains the recording and materials already carried by the shared recording projection of the public read.                                            |

### Read models

- `EventPageView { …PublicEventPage, storefront: 'doctor' | 'academy', format: EventFormat, formatBlock: FormatBlock, cta: ParticipationCta, signUps: SignUpProof, lifecycle: EventLifecycleState, medGate: MedGate | null, links: AroundEvent }` — the whole page as a function of the event, the host and the viewer's session; a widening of feature 004's `PublicEventPage` at its canonical owner (LD-1).
- `ParticipationCta { action: 'register' | 'registered' | 'enter-room' | 'switch-to-online' | 'sold-out' | 'unavailable', label, href, reason?, presenceCount? }` — the one server-resolved policy object of LD-2; `unavailable` renders **no control at all** rather than a disabled one.
- `FormatBlock` — a discriminated union over `EventFormat`: `{ kind: 'online', roomOpensAt }` · `{ kind: 'offline', address, mapRef, howToGet, seatsTotal, seatsLeft }` · `{ kind: 'hybrid', online, offline, activeTab: 'online' | 'offline' }` — the only format-varying part of the page (LD-4).
- `SignUpProof { total, sameSpecialty, adjacentSpecialties }` — the social proof of EARS-3, rendered identically for a guest and for a signed-in doctor.
- `MedGate { closedMaterialIds, reason, verificationStatus, confirmHref }` — the CON-11 gate of EARS-11 in its base form, `null` when the event carries no material requiring a confirmed status.
- `AroundEvent { school?: { label, href }, speakerPages: Array<{ speakerKey, href }>, communityHref? }` — the «Вокруг события» links of EARS-2, resolved per HOST; `speakerKey` is the 012 EARS-8 `expertSlug` (a legacy speaker has no key and therefore never a page). A link whose target does not exist is **absent** — the key is missing — rather than dead, `null`-valued or empty-stringed.
- `EventLifecycleState` — feature 004's single machine, extended at its canonical owner with the cancelled / rescheduled value (LD-6). Not a 020-local type.

### Policies

- The open part of the read is public on both hosts and identical for a guest and a signed-in viewer; only `cta`, `medGate` and the registered affordances are viewer-dependent (004 EARS-1, EARS-10).
- `cta.action` is resolved server-side from the lifecycle state, the viewer's registration, the format and the seat count, and by nothing else (LD-2).
- `enter-room` resolves **only** for a viewer holding a registration on that event, and its `href` is a route of the storefront host the viewer is on (LD-3).
- A hybrid event whose offline seats are exhausted resolves to `switch-to-online`; a pure offline event resolves to `sold-out`; neither resolves to a waiting list, which does not exist in the model (LD-5).
- A `draft` event is not publicly reachable on either host and returns not-found; an `archived` event renders 004 EARS-5's notice with no participation CTA (004 EARS-6).
- The page renders whatever the shared recording projection of the public read carries and models no recording state of its own.

## Open questions carried forward

These stay open; each is designed around above rather than resolved here, and each is a product decision the owner still owns.

- **The points price of a unit of content and the accrual / advance rules** (REQ-48 / REQ-49) — that the cost is a per-event parameter is settled; the policy is not. 020 renders the parameter and, per LD-7, renders no ledger fact it has not been given. Feature 025 owns the answer.
- **What exactly grants НМО credit** — the legacy site's ≥ 90 minutes of presence and 2 check-ins are unconfirmed for the new platform. EARS-14 is deferred behind feature 038, which owns both the thresholds and the accounting.
- **What happens to points when an event is cancelled** — the draft copy promised they are returned; the actual rule follows from the REQ-48 / REQ-49 economy. EARS-10 therefore renders no points statement in the cancelled state until feature 025 asserts one.
- **Where an event's community discussion belongs** — EARS-2 renders the «Вокруг события» community link when a target exists and omits it when none does; which community an event maps to is the same open product decision feature 019 carried forward (#1532).
- **Whether the Academy storefront needs any content difference beyond the header** — D-4 says no, and EARS-1 makes that a checkable property. A future Academy-only block is a change to D-4, not a build-time decision.
- **Whether the live-эфир interaction of EARS-13 belongs on the page or inside the room** — the PRD places it on the page and feature 006 owns the room; the wave-2 slice that builds it decides where the one shared interaction channel lives, and 020's constraint is only that there be one.
