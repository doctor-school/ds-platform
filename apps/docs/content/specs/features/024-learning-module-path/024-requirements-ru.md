# 024 — Путь курса, шаги урока и конструктор правил (Требования)

## Результаты

- Врач учится **уроками — наборами шагов** примерно на академический час, а не одним видео, и всегда видит **один сквозной путь курса**: модули — его разделы, шаги — узлы, урок — группа шагов подряд, каждый модуль закрывает узел клуба, курс — узел документа.
- Состояние каждого шага — пройден · вы здесь · открыт · закрыт с причиной · можно перейти, сдав тест по пропущенному — **вычисляется** одним вычислителем из сохранённых фактов и действующих правил; сайт и мобильное приложение читают одни данные пути и различаются только подачей.
- **Каждое правило — настройка**: зачёт, открытие, порядок, видимость закрытого, тесты, test-out и повтор — слоёные данные с наследованием и пресетами, которые меняются в `apps/admin` без релиза; кодом остаются только каталог типов элементов, каталог типов условий и вычислитель.
- **Ничего сделанного врачом не теряется молча**: факты только добавляются; смена правила пересчитывает статусы, сохраняет заработанные зачёты, если изменение не требует их заново, и объясняет врачу, почему статус изменился.
- Фича **025** получает `lesson.completed` и `module.completed` ровно тогда, когда статус по вычислителю впервые становится «пройден», и решает все очки.

## Рамки

**Входит:**

- **Модель структуры** в `packages/learning`: строки школы, курса, модуля, урока и шага (минимальная строка школы — направление, ведущий эксперт, название, slug, ссылка на проект, состояние, — и минимальные строки курса и модуля — школа, проект, slug, название, порядок, состояние, — которые нужны пути), состав урока из каталога типов элементов и admin API, которое их пишет.
- **Каталог типов элементов** и **каталог типов условий** (код), с определением «просмотрено» для каждого типа и его значением по умолчанию.
- **Модель правил**: слои настроек платформа → школа → курс → модуль → урок → шаг, резолвер с уровнем-источником, грамматика правила зачёта, настройки открытия, порядка, видимости, тестов, test-out и повтора, три засеянных пресета.
- **Факты прогресса**, **вычислитель**, проекция статусов с причинами и передача `lesson.completed` / `module.completed` в 025.
- **Экраны врача** в `apps/doctor`: страница пути курса `/courses/{courseSlug}` и экран шага; гейт гостя; тесты, исправительный материал, test-out, повтор, оценки и отзывы; те же чтения для мобильного приложения.
- **Экраны админки** в `apps/admin`: состав урока, редактор правил (пресеты, переопределения, показ «унаследовано от», значения платформы и состав пресетов) и диалог изменения на живом курсе; staff-роль правил обучения в «Доступах» (047).

### Вне рамок

- **Экран школы, описательные поля школы, отзывы выпускников, наставничество и стажировка, состояние «скоро», шапка страницы курса и экраны редактора структуры** — фича **023**, поверх строк школы, курса и модуля из EARS-1: шапка курса (описание, автор, документ, сводка правил) на маршруте из EARS-14 и экраны админки, которые создают и упорядочивают школы, курсы и модули. Таблицу школ 023 не добавляет; 024 пишет эти строки через своё admin API (EARS-1).
- **Очки** — начисление, траты и плашка очков — фича **025**; 024 только сообщает факты (EARS-12).
- **Выдача и проверка документа курса** — фичи **038** / **037**; узел документа показывает состояние прохождения курса и ведёт к документу 038.
- **Само мероприятие клуба** — живой эфир и факт посещения принадлежат 005 / 020; узел клуба читает этот факт (EARS-6).
- **Маршрут производства контента, длительность и состав шаблона урока** — фича **040** (решение лида 5: доля теории — значение шаблона, а не правило платформы).
- **Мобильное приложение** — свой трек; оно потребляет чтения и записи из EARS-10, EARS-13, EARS-15, EARS-18, EARS-20, EARS-23 (EARS-25).
- **Игровой слой** (серии, сердца, лиги, XP) — слой приложения, на сайте не показывается.

## Ограничения

- **Правила — это данные.** Ни порог, ни процент, ни порядок, ни условие открытия, ни число попыток, ни пауза, ни видимость не являются литералом в коде; каждое читается из разрешённых слоёв (EARS-5). Единственные значения по умолчанию в коде — засев слоя платформы и пресетов, мигрируемый как строки.
- **Факты только добавляются.** Ни UPDATE, ни DELETE не доходит до строки факта — это обеспечивает триггер БД (ADR-0003 §2.7); статус никогда не хранится как истина, проекция пересобирается из фактов и правил.
- **Доказательства на сервере.** Ответы теста проверяются на сервере, правильные ответы не попадают к клиенту до отправки; клиент никогда не утверждает зачёт — только факты, которые читает вычислитель.
- **Никакого открытия за оплату.** Врачи ничего не покупают (D10); ни правило, ни условие, ни настройка не ссылаются на цену или оплату.
- **Тексты из данных.** Даты, числа, длительности, пороги и фразы правил строятся из данных и разрешённых правил, а не фиксированными строками (решение лида 8); ни один текст интерфейса не пишет «бесплатно», не говорит о деньгах и о том, кто платит, и не пишет «проект».
- **Один пакет.** `packages/learning` владеет моделью, вычислителем и UI-блоками; `apps/doctor` добавляет только файлы маршрутов и поля host-config, `apps/admin` — только свои файлы маршрутов над admin-блоками пакета (ADR-0013 §A1).

## Prior decisions (предшествующие решения)

- **ADR-0016 §4:** школа, курс, модуль, урок — результаты проекта и несут `project_id`; урок — единица финансирования. **§5:** школа висит на направлении (`directions`), у направления несколько школ, у каждого ведущего эксперта одна (эксперт по §3); курс всегда внутри школы. **§6:** 024 не пишет проводок. **§8:** строки структуры и факты — `doctor`; слои правил, пресеты и строки авторинга — `admin-only`. **§9:** смена правила поглощает, а не переписывает факты.
- **ADR-0003 §2.7:** факты несут уникальный `event_id`, триггер отклоняет UPDATE/DELETE.
- **ADR-0013 §A1:** один общий пакет на возможность — `packages/learning`, строка реестра возможностей «Learning path — course page and lesson».
- **ADR-0014:** этот триплет формализует `024-product.md`; каждый пункт `realizes:` историю US.
- **025 EARS-7, EARS-8, EARS-32:** типы фактов `lesson.completed { mode }` (ссылка на урок) и `module.completed { mode }` (ссылка на модуль) зарегистрированы в каталоге 025; 024 записывает их через `PointsEngine` в своей транзакции.
- **Владелец D16:** набранный прогресс при смене правила — по умолчанию «сохранить», автор может выбрать «потребовать заново» для каждого изменения. **Владелец D17:** test-out выключен в «ДПО / аккредитация», включён в «Путь (Duolingo)»; переопределение на уровне курса может его включить.
- **Лид, 2026-11-12:** каталог типов условий и значения «просмотрено» по умолчанию — список PRD; на черновом курсе правила меняют его редакторы, на опубликованном — только обладатель права правил обучения, видя влияние и выбор D16, каждое изменение аудируется 010, второго подтверждения нет; экраны авторинга входят в рамки и собираются из `@ds/design-system` без канваса и без Stage A.

## Модель событий

**Команды** — `CreateSchool`, `CreateCourse`, `CreateModule`, `CreateLesson`, `UpdateLesson`, `AddStep`, `UpdateStep`, `ReorderSteps`, `RemoveStep`, `PublishLesson`, `UnpublishLesson` (админка); `SetRuleLayer`, `ClearRuleSetting`, `ApplyPreset`, `UpdatePreset`, `PreviewRuleChange`, `ConfirmRuleChange { earnedProgress: keep | require-again }` (админка); `RecordProgress`, `StartAttempt`, `SubmitAttempt`, `StartTestOut`, `RateLesson`, `SendFeedback` (врач).

**События** — `LessonPublished`, `LessonUnpublished`, `RuleLayerChanged`, `PresetApplied` (каждое — строка аудита изменений 010); `ProgressRecorded`, `AttemptSubmitted`, `TestOutPassed`, `CompletionKept` (неизменяемые факты); `StepCompleted`, `LessonCompleted`, `ModuleCompleted`, `CourseCompleted`, `TestPassed`, `StatusChanged { cause: fact | rule-change }` (переходы вычислителя); в 025: `lesson.completed`, `module.completed`.

**Модели чтения** — путь курса; урок с шагами и фразами правил; содержимое шага; результат попытки с исправительным материалом; состав урока в админке, действующие правила области с уровнями-источниками, влияние изменения правила.

**Политики** — «статус вычисляется, а не утверждается»; «побеждает ближайший слой»; «факт никогда не меняется и не удаляется»; «смена правила сохраняет заработанные зачёты, если автор не требует их заново»; «025 слышит зачёт один раз — когда он впервые становится пройденным»; «гостю никогда не отдаётся закрытый контент»; «неопубликованного урока нет на пути врача».

## Требования EARS

> Плоская нумерация по ADR-0006 §4. Каждый пункт реализует одну или несколько историй PRD и покрыт `024-scenarios.feature`.

- **EARS-1** _(realizes: US-1, US-18)_ — СИСТЕМА ДОЛЖНА хранить структуру как данные в `packages/learning`: школу (направление по ADR-0016 §5, ведущий эксперт по ADR-0016 §3 — одна школа на эксперта и направление, — название, slug, ссылка на проект, состояние `draft` | `published`), курс (его школа, никогда не пустая, ссылка на проект, slug, название, состояние `draft` | `published`), его упорядоченные модули, упорядоченные уроки каждого модуля и упорядоченные шаги каждого урока; урок ДОЛЖЕН нести свой модуль (никогда не пустой), ссылку на проект, название, описание и тизер, а шаг — тип элемента из каталога EARS-2, название, ожидаемую длительность в минутах и содержимое своего типа; длительность урока ДОЛЖНА быть суммой длительностей его шагов; каждая строка ДОЛЖНА объявлять принадлежность витрине `doctor` (ADR-0016 §8), ни один курс НЕ ДОЛЖЕН существовать вне школы и ни один урок — вне модуля; admin API, создающее курс, ДОЛЖНО принимать его школу и отклонять отсутствующую или неизвестную с ошибкой поля.
- **EARS-2** _(realizes: US-18, US-1, US-15)_ — СИСТЕМА ДОЛЖНА держать **каталог типов элементов** кодом в `packages/learning` с начальными типами `video` (серия сериала), `microlearning` (карточки), `download` (материал для скачивания, в том числе партнёрский), `podcast`, `test` и `clinical-case`; каждый тип объявляет схему содержимого, записываемые факты прогресса и своё **определение «просмотрено»** со значением по умолчанию — `video` досмотрено на 100 % (владелец D15), `podcast` прослушан на 90 %, `download` открыт один раз, `microlearning` просмотрены все карточки, `clinical-case` пройден до конца, `test` сдан на пороге, — где процент является настройкой EARS-5; шаг типа, которого нет в каталоге, ДОЛЖЕН отклоняться с ошибкой поля, ничего не сохраняя.
- **EARS-3** _(realizes: US-18, US-15)_ — СИСТЕМА ДОЛЖНА держать **каталог типов условий** кодом с начальными типами `viewed` (определение «просмотрено» шага из EARS-2), `watched-at-least { percent }`, `opened`, `listened-at-least { percent }`, `test-passed { test }`, `club-attended { module }`, `manual-mark`, `all-steps-done` и `lessons-done`; правило с условием, которого нет в каталоге, ДОЛЖНО отклоняться; добавление типа условия ДОЛЖНО быть изменением кода, а добавление комбинации или числа — НЕ ДОЛЖНО.
- **EARS-4** _(realizes: US-1)_ — КОГДА автор публикует урок, СИСТЕМА ДОЛЖНА отклонить публикацию с `409 PUBLISH_REQUIREMENTS_NOT_MET` и ошибками полей, называющими каждое недостающее — хотя бы один шаг, обязательное содержимое каждого шага и, если разрешённые правила их требуют, выходной тест (`test.exitRequired` из EARS-8) и входной тест (`test.entryRequired`), — а иначе ДОЛЖНА опубликовать урок целиком; ПОКА урок не опубликован, СИСТЕМА ДОЛЖНА не показывать его ни в одном чтении врача, а неопубликованный урок ДОЛЖЕН сохранять факты своих врачей.
- **EARS-5** _(realizes: US-14, US-13)_ — СИСТЕМА ДОЛЖНА разрешать каждую настройку через слои платформа → школа → курс → модуль → урок → шаг: побеждает ближайший слой, в котором настройка задана, слой без строки пропускается; резолвер ДОЛЖЕН возвращать для каждой настройки значение, уровень, откуда оно пришло, и, если значение этого уровня записано пресетом, имя пресета; слой платформы ДОЛЖЕН содержать значение каждой настройки, чтобы разрешение всегда заканчивалось значением.
- **EARS-6** _(realizes: US-15, US-3)_ — СИСТЕМА ДОЛЖНА выражать правило зачёта деревом из `all`, `any` и `n-of { n }` над условиями EARS-3 с проверкой при записи (каждый упомянутый шаг, тест и модуль — внутри области правила, `n` от 1 до числа детей, глубина не больше 4); зачёт шага по умолчанию ДОЛЖЕН быть `viewed` его типа, урока — `all-steps-done` и — только ПОКА разрешённая настройка «выходной тест обязателен» из EARS-8 включена — `test-passed` его выходного теста, модуля — `lessons-done`, а `club-attended` — только ПОКА у курса включены и настройка закрывающего клуба, и настройка «клуб входит в зачёт» (решение лида 023: по умолчанию выключена, клуб — живое событие по расписанию), курса — пройдены все модули; правило, не прошедшее проверку, ДОЛЖНО отклоняться с ошибками полей без изменений.

- **EARS-28** _(realizes: US-1, US-10, US-6, US-18)_ — КОГДА сотрудник открывает уроки модуля в `apps/admin`, СИСТЕМА ДОЛЖНА показать экран состава урока из `@ds/design-system`: создать урок (название, описание, тизер, проект), добавить шаг любого типа каталога с содержимым — медиа по медиаконтракту 012, файл, тест с вопросами, вариантами, правильным вариантом и исправительным материалом к каждому вопросу, этапы клинического случая, организацию-партнёра из реестра 032 для партнёрского материала, — переупорядочить и удалить шаги, отметить подкаст как спутник урока, увидеть общую длительность урока, посмотреть шаг так, как его отрисует EARS-15, опубликовать и снять с публикации по EARS-4 и прочитать отзывы врачей из EARS-23; отклонённая запись НЕ ДОЛЖНА ничего менять и ДОЛЖНА называть ошибки полей.
- **EARS-29** _(realizes: US-13, US-14, US-15, US-16)_ — КОГДА сотрудник открывает правила области платформы, школы, курса, модуля, урока или шага в `apps/admin`, СИСТЕМА ДОЛЖНА показать редактор правил из `@ds/design-system`: каждую настройку из EARS-6…8 с действующим значением и «Унаследовано от: <уровень>» (и именем пресета) или «Задано здесь», переопределение и «Вернуть унаследованное» для каждой настройки, конструктор правила зачёта из `all` / `any` / `N из M` над условиями каталога, «Применить пресет» на школе или курсе и состав каждого пресета в области платформы; отклонённое правило НЕ ДОЛЖНО ничего менять и ДОЛЖНО называть ошибки полей.
- **EARS-30** _(realizes: US-17, US-13)_ — СИСТЕМА ДОЛЖНА позволять менять правила чернового курса сотрудникам, которые могут редактировать этот курс, а правила опубликованного курса, слой платформы и пресеты — только обладателю staff-роли `learning_rules_editor` («Редактор правил обучения»), выданной в «Доступах» (047), со вторым фактором; каждый admin-эндпоинт обучения ДОЛЖЕН требовать отдельной admin-сессии, CSRF, канонического ключа идемпотентности и, кроме создания, текущей версии `If-Match`, отклоняя устаревшую с `412 PRECONDITION_FAILED`; каждое изменение ДОЛЖНО оставлять одну строку аудита изменений 010 от имени сотрудника; ни одно изменение НЕ ДОЛЖНО требовать подтверждения второго человека.
- **EARS-31** _(realizes: US-17, US-19)_ — КОГДА `learning_rules_editor` сохраняет изменение правила на опубликованном курсе, СИСТЕМА ДОЛЖНА сначала показать диалог изменения с числом врачей, чьи статусы изменятся, — вычисленным вычислителем по их фактам при старых и новых правилах без записи, — и выбором «Сохранить заработанные зачёты» (выбран по умолчанию, владелец D16) или «Потребовать заново»; КОГДА изменение подтверждено, СИСТЕМА ДОЛЖНА применить его, при «сохранить» записать факт `completion-kept` для каждого элемента, который был `done` и перестал бы им быть, пересчитать статусы затронутых врачей по EARS-11 с изменением как причиной и передать переходы по EARS-12; не ДОЛЖНО требоваться ни релиза, ни миграции данных, и ни один факт НЕ ДОЛЖЕН меняться или удаляться.

## Инварианты

- Ни один статус не хранится как истина; каждый статус — результат вычислителя над фактами и разрешёнными правилами, проекцию можно пересобрать (EARS-11).
- Ни одна строка факта никогда не обновляется и не удаляется; изменение правила только добавляет факты (EARS-10, EARS-31).
- Каждая настройка разрешается ровно в одно значение с названным уровнем-источником (EARS-5).
- 025 слышит каждый зачёт урока и модуля врача не больше одного раза (EARS-12); 024 не пишет проводок.
- Гостю никогда не отдаётся содержимое шага; закрытому шагу никогда не отдаётся его контент (EARS-10, EARS-15, EARS-22).
- Неопубликованный урок никогда не появляется на пути врача (EARS-4, EARS-13).
- Ни правило, ни настройка, ни текст не ссылаются на цену или оплату для врача (EARS-7, EARS-26).
- Каждое изменение правила на опубликованном курсе делает `learning_rules_editor`, и оно оставляет одну строку аудита 010 (EARS-30).
