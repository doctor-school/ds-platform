> Input to the [048 PRD](./048-product.md) (Prior art) and to the 048 design spec. EN only: a technical research note, not an owner-facing product document.

**Scope.** `academy.doctor.school` shows the newest publications of Doctor.School's own official accounts (we are their admins) in one mixed, date-sorted feed rendered in our own design. The question per platform: is there a documented, lawful server-side read path, what does it return, and what may we store and show.

**Method.** Primary sources only: official API docs, terms of use, official help, official GitHub. Checked on 2026-10-29.

**Marks.** **CONFIRMED** — the primary source says so. **PROBED** — a live read-only request worked, but no current official document describes it. **UNCONFIRMED** — a gap, not verified.

YouTube is blocked in the RF and is not in the 048 starting set (owner, chat 2026-10-29). ## Conclusion

1. Telegram and VK have documented server-side read paths that need no partner agreement. Both are push-based: a Telegram bot in our channel, and the VK Callback API configured by our community admin. Both need a one-off backfill: Telegram has no history read; VK backfills with `wall.get` and a service key.
2. VK video is reachable only as post attachments or `video_new` events; `video.get` needs a scope VK grants on request. Clips have no documented method. The monthly call cap (10k unverified) rules out naive polling.
3. RuTube has a public, keyless JSON channel list. It works today, but the official doc dates from 2016 and the ToS says "personal non-commercial use" — ask RuTube to confirm in writing before relying on it in production.
4. Dzen has no read interface, and its ToS forbids access beyond what is permitted. The lawful options are the company's written permission, or the reverse model: our site is the source, Dzen imports our RSS, and the feed shows our own record.
5. Every platform allows its official embed player for opening a material. Storing metadata and text is fine; mirroring media files is not (VK §1.6, YouTube III.E.1). Telegram previews must be copied, because `getFile` links expire.

## Gaps (UNCONFIRMED)

- Telegram: whether the docs state that a channel bot must be an admin.
- VK: clips read method; whether clips fire `video_new`; the official permalink format; whether copying preview images to our storage is allowed under §1.6; whether a separate VK Видео API exists.
- RuTube: a current official API doc; rate limits; official status of mrss / oEmbed; a partner API for authors.
- Dzen: an outbound channel RSS / API (none found); the embed-code procedure.
- YouTube: reachability from the RF hosting network.
