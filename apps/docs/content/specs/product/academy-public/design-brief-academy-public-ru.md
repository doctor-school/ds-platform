# Дизайн-пакет: публичные разделы Академии Doctor School

> Как пользоваться: на claude.ai/design в проекте «DS Platform» создавайте **отдельный чат на каждую страницу**. В каждый чат вставляйте: раздел «0. Общий UX-фундамент» + раздел нужной страницы. Порядок прогона: 1 (главная) → 4 (архивный эфир) → 2 → 3; страницы 2–5 можно гнать параллельно после главной.

---

## 0. Общий UX-фундамент (вставлять в каждый чат)

### Контекст

Doctor.School — медицинская образовательная платформа: бесплатное образование для врачей, финансируемое фарм-партнёрами. Портал academy.doctor.school живёт в продакшене: витрина эфиров `/webinars`, страница эфира, вебинарная комната, «Мои события», профиль. Достраиваем публичный контур: главная `/`, проекты `/projects`, эксперты `/experts`, архив записей (состояние страницы эфира).

### Основа — что уже задизайнено (обязательно к переиспользованию)

- `tokens/` + `brand/` — токены и бренд, единственный источник правды по цвету/типографике/отступам.
- `as-is/*.dc.html` — готовые экраны текущего портала: карточка эфира, витрина (список + месяц), страница эфира, «Мои события», профиль. Новые страницы — продолжение этого визуального языка, не отдельный сайт.
- ⚠ Никакого глассморфизма, градиентных свечений и стороннего «премиального дарка». Строго существующий язык.

### Сквозная навигация и связность (главное в этом пакете)

Контентная модель: **эфир** относится к одному или нескольким **проектам**; в эфире участвуют **эксперты** (роли: спикер/модератор); у проекта есть **партнёр(ы)**; у эфира есть **темы**. Всё связано перекрёстными ссылками:

- шапка портала (существующая) получает пункты: Эфиры · Проекты · Эксперты (+ «Мои события» для залогиненных);
- карточка эфира показывает бейджи проекта и аватары/имена экспертов — оба кликабельны (→ страница проекта / эксперта);
- страница проекта и страница эксперта показывают СВОИ эфиры тем же юнитом списка;
- страница эфира ссылается вверх: на проект(ы) и на каждого эксперта.

Пользовательские маршруты, которые обязаны работать без тупиков: врач с главной → лента → эфир → «чей это проект?» → проект → другие эфиры проекта → регистрация; посетитель → эксперт → его прошлые эфиры → запись (плеер за логином → мягкий призыв войти); партнёр с любой страницы → «Партнёрство» → форма на главной.

### Переиспользуемые юниты (менять в одном месте — применяется везде)

1. **Карточка эфира** (`as-is/webinar-card`) — как есть; добавляются бейджи проекта/экспертов.
2. **Список эфиров** (`as-is/webinars-listing`) — единый юнит с фильтрами (проект, эксперт, тема, прошедшие/будущие) и **пагинацией**; живёт на /webinars, странице проекта, странице эксперта, в ленте главной (усечённый режим: без фильтров, N карточек + «Все эфиры»).
3. **Карточка эксперта** — НОВЫЙ юнит: фото, имя, роль/регалии; используется на главной, в /experts, на странице эфира (состав спикеров) и странице проекта (команда).
4. **Карточка проекта** — НОВЫЙ юнит: обложка/лого, название, короткое описание, партнёрский бейдж, счётчик эфиров.
5. **Плашка партнёра** — НОВЫЙ юнит: лого + название + роль (спонсорский пакет); на странице проекта и эфира.
6. **Пагинация** — единый компонент для всех списков.

### Тексты

Рыбу пишите сами, осмысленную по назначению блоков (старые тексты забракованы). Финальные тексты владелец доработает по готовой структуре.

### Формат выхода (каждая страница)

2–3 варианта композиции там, где развилка реальна; оба брейкпоинта (desktop + mobile), обе темы, интерактивные состояния (hover/focus карточек, поля формы, пустые состояния списков). Выбор владельца = спека для разработки.

## 1. Главная `/` (приоритет №1)

**Аудитория — двойная входная точка.** Врач → контент (лента эфиров, проекты, эксперты); партнёр (фарма/медбизнес/эксперт) → понять идею → лид-форма. Потоки взаимозависимы: без врачей не интересно партнёрам, без партнёров нет бесплатного образования. Тон: экспертный, чистый, без инфобизнеса, ощущение влияния и статуса.

**Структура (9 блоков, порядок можно предлагать иначе):**

1. **Hero** — что это и для кого; двойной CTA: [Стать партнёром] (якорь на форму) и [Смотреть эфиры] (→ /webinars).
2. **Лента контента** — «Ближайшие и последние эфиры»: юнит списка в усечённом режиме, 3–6 карточек, ссылка «Все эфиры».
3. **Что это** — 3–4 карточки: Эксперты / Индустрия / Образование / Партнёры.
4. **Зачем** — 2 колонки: «Сейчас» (устаревающие модели) vs «Мы создаём» (гибкая экспертная среда).
5. **Что мы создаём** — ecosystem map: школы, сообщества, дискуссии и подкасты, программы, стандарты.
6. **Люди** — карточки экспертов (юнит #3) + медиа-блок «Кто стоит за брендом» (подкаст: выпуски).
7. **Партнёрам** — 3–4 benefit-карточки: репутация, участие в среде, влияние, доступ к экспертам.
8. **Форматы участия** — карточки: эксперт, партнёр, участник подкаста, соавтор направления, компания.
9. **Финальный CTA + лид-форма** — имя, компания/клиника, email или Telegram, роль (селект); обязательный чекбокс согласия на обработку персональных данных со ссылкой на политику (152-ФЗ); кнопка «Обсудить партнёрство»; состояния: заполнение / ошибки / успех.

**Развилка для вариантов:** (а) контент-первый — лента сразу под hero; (б) смысл-первый — «что это» раньше ленты; (в) сплит-hero: колонка врача + колонка партнёра.

## 2. Проекты: каталог `/projects` + страница проекта `/projects/[slug]`

**Каталог:** сетка карточек проектов (юнит #4); фильтров в v1 нет (проектов пока немного) — но композиция должна выдержать рост до десятков.

**Страница проекта:** (1) шапка проекта — обложка, название, описание, куратор; (2) партнёрский блок — плашка партнёра (юнит #5), заметная, но не рекламная: «партнёр направления»; (3) команда — карточки экспертов проекта; (4) **эфиры проекта** — юнит списка с предустановленным фильтром по проекту, вкладки «Будущие / Прошедшие», пагинация; (5) CTA вниз: для врача «записаться на ближайший эфир», для компании «стать партнёром проекта» (→ форма главной с преселектом).

**Развилка:** (а) партнёр в шапке рядом с названием vs (б) отдельным блоком после описания; (в) команда до/после списка эфиров.

## 3. Эксперты: каталог `/experts` + страница эксперта `/experts/[slug]`

**Каталог:** сетка карточек экспертов (юнит #3), поиск по имени; фильтр по проекту — вторично.

**Страница эксперта:** (1) шапка — фото, имя, роль, регалии полностью, био; (2) проекты, где участвует (карточки-мини); (3) **эфиры с участием эксперта** — юнит списка с фильтром по эксперту, «Будущие / Прошедшие», пагинация: будущий → регистрация, прошедший → запись; (4) опционально блок «подкаст-выпуски с ним».

**Развилка:** (а) био слева + контент справа (двухколоночная) vs (б) широкая шапка + контент вниз одной колонкой.

## 4. Страница эфира — архивное состояние (`/webinars/[slug]` после завершения)

Существующую страницу эфира (as-is/webinar-page) НЕ переделываем — проектируем её **пост-эфирное состояние**:

1. **Плеер записи** на месте hero. Логика двух записей: пока есть только сырая запись трансляции — играет она; когда смонтированное видео готово — сверху смонтированное, а сырая уезжает во вторичный слот «Смотреть оригинал трансляции» (спойлер/вкладка — предложите 2 варианта подачи).
2. **Гейт логина:** страница публична (анонс, описание, спикеры видны всем), но сам плеер — только авторизованным. Для гостя на месте плеера — постер + мягкий призыв «Войдите, чтобы посмотреть запись» (вход бесплатный) — это двигатель регистраций, не пейволл.
3. Остальное как на живой странице: спикеры (карточки экспертов, кликабельные), проект(ы), темы, материалы.
4. Состояние «запись ещё готовится» (эфир кончился, записи нет): честная плашка со сроком.

**Развилка:** подача вторичной записи — (а) спойлер под плеером, (б) вкладки «Монтаж / Оригинал», (в) отдельная секция внизу.

## 5. Витрина `/webinars` — доработка (не редизайн)

Существующая витрина получает: вкладку/переключатель «Прошедшие», фасеты фильтра (проект, эксперт, тема) и пагинацию — всё в рамках юнита #2. Прогонять этим же чатом после страницы 4 или отдельным коротким чатом.
