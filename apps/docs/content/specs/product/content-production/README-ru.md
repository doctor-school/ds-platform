# Производство контента DS — модель процесса и себестоимости

## Зачем, с какой точки зрения, как

- **Цель:** себестоимость продуктов DS и масштабирование команды производства без персонального узкого места → обоснованные КП для фармы.
- **Точка зрения:** продуктовая команда направления — самоуправляющийся круг, который ведёт полный цикл от продажи до отчёта.
- **Граница:** запрос → договор → производство → выпуск → отчёт и закрывающие документы → развитие команд. На A0 уроки, подкасты и мероприятия — две линии одного блока A3 «Произвести продукты».
- **Метод (SADT):** реестр объектов и функций → IDEF0 (A-0, A0, декомпозиция) → IDEF3 / BPMN для времени и циклов → ABC-себестоимость по производственным единицам (урок → модуль → курс; мероприятие отдельно).

## Правила модели

| Правило                                    | Содержание                                                                                                                                                                                                                        |
| ------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| R1. Давность                               | При конфликте источников действует более поздний: решения владельца 2026-10-08…12 > ответы 2026-10-05 > 2026-10-01 > интервью 2026-09-30 > встречи 09 > 08 > … Вытесненное значение помечается «Заменено», а не открытым вопросом |
| R2. Роли — не люди                         | Функции закрепляются только за абстрактными ролями; наблюдаемые сегодня совмещения — AS-IS-наблюдение, не модельная роль                                                                                                          |
| R3. Состав ролей — результат моделирования | Какие DS-роли существуют и где их границы — выход моделирования; такие роли помечены «роль-кандидат»                                                                                                                              |
| R4. Глоссарий обязателен                   | Каждый доменный термин реестра определён в `glossary-ru.md`                                                                                                                                                                       |
| R5. Бирюзовые принципы                     | Процессы проектируются по бирюзовым принципам ([`teal-principles-ru.md`](teal-principles-ru.md)); образец организации выбирается для каждого процесса отдельно                                                                    |
| R6. Только TO-BE                           | Модель описывает целевой процесс; текущая практика — только источник функций и объектов реестра                                                                                                                                   |

## Источники

- Черновик владельца «Процесс разработки образовательного контента» (2026-09-30) — теги `S:n` (n — строка черновика).
- Расшифровка статус-встречи BBM 2026-09-30 (bbm-kb, meetings) — теги `Ln` / «L1234» / «стр. 1234»: номер строки этой расшифровки. Участники описаны ролями; отдельные лица в модель не входят.
- Ответы владельца на пакеты вопросов 2026-10-01 и 2026-10-05 — тег `ВЛ`; решения владельца 2026-10-08…12 по разбору модели после статус-встречи 2026-10-07 — комментарии эпика #2522 и Issue #2840, раздел «Решения владельца (2026-10-08…12)» `process-to-be-ru.md`.
- Legacy AS-IS BPMN мероприятий DS (bbm-kb) — тег `P:`; встречи BBM 2026-04…09 — тег `M:`; механика авторской доли BBM finmodel — тег `AS`.
- Проходы A / B / C (хронологический, роли и передачи, деньги) — сведены в канонические ID; покрытие проверено: ни один ID проходов не потерян.

## Просмотрщик

`viewer/index.html` — статическая страница без сборки: читает `model/index.yaml` и YAML-диаграммы, раскладывает их лестницей IDEF0 (блоки A1 … An по диагонали слева сверху вправо вниз в порядке номеров; вход — слева, управление — сверху, выход — справа, механизм — снизу; ортогональные стрелки, обратные связи по управлению — над всеми блоками, по входу и механизму — под блоком-источником; подписи — там, где не перекрывают блоки и другие подписи) и рисует React Flow. Начальный вид — вся диаграмма целиком по ширине и высоте вместе с граничными кодами и подписями, колесо мыши прокручивает, кнопки «+ / −» масштабируют. Двойной щелчок по блоку с ▼ (или кнопка в панели) раскрывает дочернюю диаграмму, цепочка уровней — в шапке; наведение на блок или стрелку показывает короткую подсказку: название, строку блока процесса TO-BE и краткое описание; подсказка выключается переключателем «Подсказка при наведении» в шапке (выбор запоминается). Полное пояснение — в панели справа после щелчка: стрелки блока по сторонам ICOM («Входы», «Управление», «Выходы», «Механизмы») с другим концом каждой (код блока или граничный код), — наведение на строку подсвечивает эту ветку на схеме, — затем названия и определения F-ID / O-ID из `registry-ru.md` и их шаг TO-BE или причину исключения из `process-to-be-ru.md` (страница читает оба файла при открытии). Наведение или щелчок по блоку подсвечивает его собственные выходы и из чужих стрелок только ветки, которые входят в этот блок; остальные стрелки и блоки, не связанные с ним подсвеченными ветками, бледнеют. Подпись стрелки выделяется, только если стоит на подсвеченной ветке, иначе бледнеет вместе со своей веткой. Наведение на стрелку оставляет яркими только блоки на её концах. Стрелки идут ортогонально со скруглёнными изгибами; движение по стрелкам выключается переключателем «Анимация стрелок» (выбор запоминается; при системной настройке «уменьшить движение» по умолчанию выключено).

Открытие: страница загружает YAML через `fetch`, поэтому с `file://` не работает — папку пакета отдаёт любой статический сервер, например из корня репозитория:

```bash
npx http-server apps/docs/content/specs/product/content-production -p 8080 -c-1
```

и в браузере `http://localhost:8080/viewer/` (уровень — в адресе: `#A-0`, `#A0`, `#A31` …). Библиотеки берутся с CDN jsDelivr, нужен интернет.

## Калькулятор

`calculator/index.html` — статическая страница без сборки на том же стеке, что и просмотрщик; считает [`compute.mjs`](calculator/compute.mjs), формулы — [`cost-model-ru.md`](calculator/cost-model-ru.md). Открывается тем же сервером: `http://localhost:8080/calculator/`.

- **Продукт** — стандартный из `products.yaml` или «своя сборка»: единицы с количеством и число сделок.
- **Грейд и ход работы** — две независимые оси вместо одного сценария: «Грейд» (junior, middle, senior, смесь команды) меняет ставки, «Ход работы» (гладко, обычно, с переделками) — часы и круги; матрица 3 × 3 показывает все сочетания.
- **Итоги и цена** — себестоимость «по загрузке» и «с полным фондом оплаты», цена одним ведущим способом (множитель, наценка, маржа или сумма) с остальными выведенными, аванс и оплата за контакты мало / план / много, безубыточность, рыночный ориентир с разрывом и золотая цена; полоса ключевых цифр с разницей к запомненной базе.
- **Разложение** — прямые затраты по ролям (участники «Продуктовой команды» поимённо по ролям) и по функциям схемы, час штата по шагам, эксперты, накладные, резерв актуализации, внешние затраты и чёрные ящики («не задано» не входит в итог и даёт флаг), инструменты и инфраструктура, неиспользованная мощность штата, итог по статьям затрат; мощность команды, узкое место и срок; все флаги.
- **Что двигает цену и бюджет** — торнадо драйверов, график безубыточности, себестоимость и маржа на одной оси; ползунок и поле на каждую статью затрат и список ролей ниже рыночного минимума грейда.
- **Раскрытие** — любая цифра раскрывается до состава: продукт → единица (количество) → операция → роль, часы за проход × круги × количество = часы, × стоимость часа = ₽; накладные, инструменты и неиспользованная мощность — ставкой на прямой час × прямые часы, с пулом месяца плана. Номер операции открывает её диаграмму в просмотрщике. Термины и сокращения объясняются подсказкой при наведении и при переходе клавишей Tab.
- **Калибровка** — правка часов операций, кругов и ожиданий петель, ставок ролей по грейдам, формы привлечения (с предустановками «Всё в штате», «Всё почасово», «Как в модели»), грейдов экспертов, FTE команды, переменных, параметров продуктов, внешних затрат, рыночных ориентиров и цены; у вкладок с правками — пометка «изменено N» и сброс вкладки; пересчёт сразу, сброс по одной и «Сбросить всё». Правки хранятся в браузере; «Скачать правки» сохраняет JSON `{ base, overrides }` с ключами правок из `cost-model-ru.md`, «Загрузить правки» читает его обратно. В YAML модели правки переносит ведущий PR-ом по этому файлу.
- **Команда и период** — состав команды (FTE), оплаченные, непроизводственные, загруженные и свободные часы по ролям, рубли свободного времени и фонд оплаты — источник разницы между двумя итогами.
