# IDEF0-модель — формат YAML

Одна диаграмма — один файл; `index.yaml` перечисляет диаграммы в порядке раскрытия (`root`, затем `id` / `file` / `parent`).

## Диаграмма

| Поле                     | Смысл                                                                                   |
| ------------------------ | --------------------------------------------------------------------------------------- |
| `id`, `parent`           | Номер узла IDEF0 (`A-0`, `A0`, `A1` …) и диаграмма, блок которой раскрывается           |
| `title`                  | Имя родительской функции                                                                |
| `viewpoint`, `purpose`   | Только у A-0: точка зрения и цель модели                                                |
| `boxes[]`                | Функциональные блоки: `id`, `name` (глагол + объект), `functions`, `mechanisms`, `note` |
| `boxes[].functions`      | F-ID реестра; на A0 каждый F-ID TO-BE стоит ровно в одном блоке                         |
| `boxes[].process_blocks` | Номера блоков `process-to-be-ru.md`, которые реализует блок (A0 и A3)                   |
| `boxes[].mechanisms`     | Роли и круги — никогда не люди (R2)                                                     |
| `boxes[].leaf`           | `true` — лист: одна исполняющая роль и измеримая трудоёмкость `effort` (ниже)           |
| `boxes[].repeats`        | Блок без F-ID, повторяющий шаг другой линии: `id` блоков, где стоят F-ID этого шага     |
| `boxes[].decomposition`  | `pending` — блок раскрывается на следующем шаге декомпозиции (сейчас таких нет)         |
| `icom`                   | Ниже A0: граничный код дочерней диаграммы → `id` стрелки родителя (раздел «Стрелки»)    |
| `arrows[]`               | Стрелки: `id`, `label`, `objects` (O-ID реестра), `from`, `to`                          |

Каждый блок — ровно одно из трёх: лист (`leaf: true`), раскрыт дочерней диаграммой (её `id` равен номеру блока, `parent` — эта диаграмма) или `decomposition: pending`. Ниже A0 F-ID блока-родителя — ровно объединение F-ID блоков дочерней диаграммы, каждый ровно один раз; блок без F-ID — шаг, которого нет в реестре («новое» в процессе), или повтор шага другой линии, чьи F-ID стоят в одном блоке. У блока-повтора поле `repeats` обязательно: оно называет блоки, где стоят F-ID шага (A33 `A332`: `repeats: [A321, A322]`); каждый названный блок есть в модели, у самого повтора `functions` пусты — `trace-check.mjs` проверяет оба условия.

## Лист и черновая трудоёмкость

Лист — функция, которую выполняет одна роль и чью трудоёмкость можно измерить. Поле `effort`:

| Поле              | Смысл                                                                                                                                                            |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `role`            | Одна роль или круг из «Роли и круги TO-BE» `process-to-be-ru.md`: имя из таблицы или `<имя> — <подроль>` с подролью из списка ниже (`Медиа-круг — монтажёр`)     |
| `unit`            | Единица, на которую считаются часы: урок, курс, направление, договор, КП, запрос, эпизод, мероприятие …                                                          |
| `hours_draft`     | Черновые часы роли на одну единицу за один проход: число или `[min, max]`                                                                                        |
| `lead_days_draft` | Черновой срок одного прохода в рабочих днях, включая ожидание внешней стороны внутри прохода (ответ эксперта, решение фармы): число или `[min, max]`             |
| `lead_days_basis` | Источник срока — по тому же правилу, что `basis`; опорные числа: ролик 15 или 30 дней (O-174), SLA эксперта 24 ч, согласование фармы «днями и неделями»          |
| `driver`          | Что масштабирует часы — из «Драйверов мощности и себестоимости» блока процесса                                                                                   |
| `iterations`      | Необязательно: имя петли из `loops.yaml` (круги одобрения фармы, итерации сценария); `hours_draft` и `lead_days_draft` — на один проход, полные = проход × круги |
| `basis`           | Источник: `оценка аналитика` либо `оценка аналитика; опора: <число из «Нормативы и числа» реестра со ссылкой L… / M:…>` — трудоёмкостей по ролям в реестре нет   |

Подроли — закрытый список: подроль после «<круг> — » берётся только отсюда; новая подроль сначала добавляется в эту таблицу.

| Круг               | Допустимые подроли                                                                                         |
| ------------------ | ---------------------------------------------------------------------------------------------------------- |
| Медиа-круг         | медиа-ведущий, дизайнер схем, медицинская визуализация, аниматор, голос, монтажёр, запись подкаста, анонсы |
| Сервисный круг     | юрист, бухгалтер, оператор платформы, режиссёр трансляции, поддержка                                       |
| Пул экспертов      | эксперт, амбассадор, спикер                                                                                |
| Пул медрецензентов | координатор                                                                                                |
| Ядро               | стандарты, консультант рынка, калькулятор                                                                  |

Часы — черновик для калибровки владельцем при чтении диаграмм; ставки ролей — переменные калькулятора, денежных сумм в модели нет; авторская доля — распределение прибыли, вне себестоимости. Сводка по ролям — [`effort-draft-ru.md`](effort-draft-ru.md).

## Петли одобрения — `loops.yaml`

Одна запись — одна переменная итераций; её `name` дословно совпадает с `effort.iterations` листьев.

| Поле                        | Смысл                                                                                                                                                                                                                                                                |
| --------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `name`                      | Имя переменной итераций, как в листьях                                                                                                                                                                                                                               |
| `leaves`                    | Листья, которые повторяются в каждом круге; каждый несёт это же `iterations`                                                                                                                                                                                         |
| `approver`                  | Кто решает, закончен ли круг: роль или внешняя сторона (фарма, юрслужба фармы, эксперт, медрецензент, лидер)                                                                                                                                                         |
| `rounds_draft`              | Ожидаемое число проходов `[min, max]`, min ≥ 1                                                                                                                                                                                                                       |
| `rounds_from`               | Вместо `rounds_draft` — круги выводятся из других петель: `rule` (`1 + Σ (круги петли − 1)`) и `loops` (имена петель со своим `rounds_draft`); у петли ровно одно из двух. Так петля сценария: каждый непройденный круг медрецензии и этапа 1 фармы — круг доработки |
| `wait_days_per_round_draft` | Разрыв между кругами в рабочих днях (замечания вернулись, повторный вход в очередь согласующего); считается (круги − 1) раз                                                                                                                                          |
| `exit_rule`                 | Что заканчивает петлю: «зелёное» заключение рецензента, подпись или номер одобрения фармы, срок автоодобрения, эскалация по В4                                                                                                                                       |
| `basis`                     | Источник — по правилу `basis` листа                                                                                                                                                                                                                                  |
| `fragment`                  | Фрагмент процесса в духе IDEF3 / BPMN: упорядоченные шаги (ниже)                                                                                                                                                                                                     |

Шаг фрагмента: `id` (`s1…`), `step` (что делается), `actor` (роль из «Роли и круги» или внешняя сторона), `kind` — `task` | `wait` | `decision`, необязательный `box` — лист или блок модели. Шаги `task` и `wait` ведут дальше полем `next` — следующий шаг или `end`. Решение (`decision`) — вопрос с явными ветвями `yes` (ответ «да») и `no` (ответ «нет»), каждая — шаг или `end`; `next` у решения нет. Вопрос формулируется так, чтобы ветви читались буквально: «Есть замечания к сценарию?» — `yes` на доработку, `no` к выходу. Срок `lead_days_draft` листа уже включает ожидание внутри прохода, поэтому шаг `wait` фрагмента показывает, где это ожидание, а не добавляет дни; дни между кругами — только `wait_days_per_round_draft`.

## Команды и мощность — `teams.yaml`

| Поле                 | Смысл                                                                                                                                                                   |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `capacity_variables` | Переменные мощности с `draft`, `unit`, `basis`: `productive_hours_per_month` (часы на 1 FTE), `working_days_per_month`, `team_size_max` (В7), `target_lessons_per_week` |
| `teams[]`            | Стандартный состав команды: `id`, `name`, `basis`                                                                                                                       |
| `teams[].members`    | Роли команды: `role` (из «Роли и круги»), `fte_draft` (число или `[min, max]`), `basis`                                                                                 |
| `teams[].draws_on`   | Общие круги и пулы: `role` (круг или `<круг> — <подроль>`), `kind` (ротация, обязательство мощности, пул, по запросу), `fte_draft` или `commitment`, `basis`            |

Формулы мощности команды на единицу и срока единицы с примером для урока — [`capacity-ru.md`](capacity-ru.md); считает калькулятор (#2527).

## Стрелки (ICOM)

- Конец стрелки — `{ box: A3, side: I | C | O | M }` или `{ boundary: <код> }`; `to` может быть списком (ветвление).
- Граничные коды: `I1…` вход, `C1…` управление, `O1…` выход, `M1…` механизм. На A-0 `id` стрелки равен коду; на A0 граничная стрелка ссылается на тот же код родителя и несёт подмножество его O-ID.
- Ниже A0 коды нумеруются заново на каждой диаграмме, а карта `icom` связывает код со стрелкой родителя, которая касается раскрываемого блока с той же стороны (`I2: a12` — вход A1 «Запрос на следующий цикл» из A5); граничная стрелка несёт подмножество O-ID этой стрелки. Каждая стрелка родителя у блока получает хотя бы один код; несколько кодов на одну стрелку — слияние выходов нескольких дочерних блоков (A3 `O1…O3` → A0 `a03`). Обратная связь родителя на сам блок раскрывается двумя кодами — выходом и входом (A3 `O4` и `I3` → A0 `a04`).
- Внутренние стрелки A0 — `a01…`: выход блока (`side: O`) на вход, управление или механизм другого блока.
- Начало стрелки — только выход блока (`side: O`) или граничный `I` / `C` / `M`; конец — только вход, управление или механизм блока или граничный `O`. У каждого блока есть хотя бы одна стрелка управления и хотя бы одна стрелка выхода.
- Обратная связь IDEF0 — выход блока на его же вход: так A0 `a04` возвращает записи мероприятий линии A3 на вход линии единиц как сырьё микролернингов. Просмотрщик рисует такую петлю под блоком: из выхода вправо, под блоком и его механизмами, во вход слева.
- Одноимённый объект стоит на той стрелке, где он действительно возникает: стандарты DS (`O-141`) формирует A6 (`F-106`), поэтому они на внутренней стрелке `a13`, а внешнее управление `C4` несёт только базовый минимум качества (`O-138`).

## Проверка трассировки

`node apps/docs/content/specs/product/content-production/model/trace-check.mjs` (из корня репозитория) печатает по каждой диаграмме долю O-ID реестра на стрелках со списком отсутствующих и, для A0, долю размещённых F-ID TO-BE. Множество TO-BE = все F-ID реестра минус строка «не входят» раздела «Покрытие реестра» `process-to-be-ru.md`. Код выхода ≠ 0 — при висячем ID (нет в реестре или «исключён» / «объединён»), при F-ID TO-BE вне блоков A0, при F-ID в нескольких блоках, при нарушении структуры IDEF0 (конец стрелки на недопустимой стороне или граничном коде, неизвестный блок, блок без управления или без выхода — правила раздела «Стрелки»), при нарушении ICOM относительно блока-родителя (код без стрелки родителя или на чужой стороне, O-ID вне стрелки родителя, стрелка родителя без кода), при расхождении F-ID дочерней диаграммы с блоком-родителем, при блоке, который не лист, не раскрыт и не `pending`, при листе без полного `effort` (роль не из «Роли и круги» или подроль не из списка подролей, нет единицы, часов, срока, драйвера или источника), при `iterations` листа без записи в `loops.yaml` и при записи петли, чьи `leaves` не несут её имя, при шаге фрагмента со ссылкой на несуществующий шаг или блок, при решении без `yes` и `no` или шаге `task` / `wait` без `next`, при петле без ровно одного из `rounds_draft` / `rounds_from` и при `rounds_from` с петлёй, которой нет или у которой нет своего `rounds_draft` и при роли `teams.yaml` вне «Роли и круги». Печатает число листов по диаграммам и блоки, ждущие декомпозиции. Неполное покрытие O-ID ожидаемо и выход не роняет.

## Просмотр

Диаграммы открывает просмотрщик `../viewer/index.html`. Он читает YAML через `fetch`, поэтому нужен статический сервер, а не `file://`: из корня репозитория `npx http-server apps/docs/content/specs/product/content-production -p 8080 -c-1`, затем `http://localhost:8080/viewer/`. Подробно — раздел «Просмотрщик» в `../README-ru.md`.
