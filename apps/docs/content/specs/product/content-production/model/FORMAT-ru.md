# IDEF0-модель — формат YAML

Одна диаграмма — один файл; `index.yaml` перечисляет диаграммы в порядке раскрытия (`root`, затем `id` / `file` / `parent`).

## Диаграмма

| Поле                     | Смысл                                                                                   |
| ------------------------ | --------------------------------------------------------------------------------------- |
| `id`, `parent`           | Номер узла IDEF0 (`A-0`, `A0`, `A1` …) и диаграмма, блок которой раскрывается           |
| `title`                  | Имя родительской функции                                                                |
| `viewpoint`, `purpose`   | Только у A-0: точка зрения и цель модели                                                |
| `boxes[]`                | Функциональные блоки: `id`, `name` (глагол + объект), `functions`, `mechanisms`, `note` |
| `boxes[].functions`      | F-ID реестра; на A0 каждый F-ID TO-BE стоит ровно в одном блоке                         |
| `boxes[].process_blocks` | Номера блоков `process-to-be-ru.md`, которые реализует блок (только A0)                 |
| `boxes[].mechanisms`     | Роли и круги — никогда не люди (R2)                                                     |
| `arrows[]`               | Стрелки: `id`, `label`, `objects` (O-ID реестра), `from`, `to`                          |

## Стрелки (ICOM)

- Конец стрелки — `{ box: A3, side: I | C | O | M }` или `{ boundary: <код> }`; `to` может быть списком (ветвление).
- Граничные коды: `I1…` вход, `C1…` управление, `O1…` выход, `M1…` механизм. На A-0 `id` стрелки равен коду; на A0 граничная стрелка ссылается на тот же код родителя и несёт подмножество его O-ID.
- Внутренние стрелки A0 — `a01…`: выход блока (`side: O`) на вход, управление или механизм другого блока.

## Проверка трассировки

`node apps/docs/content/specs/product/content-production/model/trace-check.mjs` (из корня репозитория) печатает по каждой диаграмме долю O-ID реестра на стрелках со списком отсутствующих и, для A0, долю размещённых F-ID TO-BE. Множество TO-BE = все F-ID реестра минус строка «не входят» раздела «Покрытие реестра» `process-to-be-ru.md`. Код выхода ≠ 0 — при висячем ID (нет в реестре или «исключён» / «объединён»), при F-ID TO-BE вне блоков A0 и при F-ID в нескольких блоках. Неполное покрытие O-ID на A0 ожидаемо и выход не роняет.
