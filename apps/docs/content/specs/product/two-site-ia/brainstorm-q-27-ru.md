# Брейншторм Q-27 — связывание учётки с сущностью эксперта (REQ-97/98)

**Статус: закрыт 2026-08-19 решением владельца → REQ-106.** Владелец поправил предпосылку: эксперт **не всегда** заводится раньше учётки (в базе уже десятки тысяч врачей; экспертность может мигрировать из старой базы; учётка и эксперт могут существовать порознь) — механизм должен быть универсален для любого порядка. Выбрано: кнопка «Это я» (только авторизованным, только на «незаклеймленной» странице эксперта) → заявка админам Академии → ручная проверка личности → связь ставится в админке. Варианты A/C ниже — история брейншторма, не выбраны. Уровень — продуктовый: кто инициирует, как подтверждается, что с коллизиями. Техника (идентификаторы, хранение, SSO) — в ADR полосы Commit.

**Исходные инварианты (уже зафиксированы):**

- эксперт существует без учётки — спикер/автор/герой подкаста заводится командой заранее (REQ-97);
- одна персона — один эксперт — одна учётка; после связывания история (доклады, уроки, **начисления**) переезжает на учётку (REQ-98);
- роли — атрибуты одной персоны, не типы аккаунтов (OWD-1, REQ-44).

Следствие: связывание — момент с **финансовым значением** (на учётку переезжают начисления автора/соавтора), значит подтверждение должно быть явным, а ошибка — откатываемой.

## Вариант A — «приглашение от Академии» (invite-first)

Инициатор — внутренняя команда. Заводя эксперта, продюсер/методист указывает его контакт (телефон/e-mail); эксперту уходит персональная ссылка-приглашение. Регистрация или вход по ссылке = связывание без дополнительных проверок.

| +                                                              | −                                                                                                                 |
| -------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Инициирует тот, кто знает эксперта лично — самозванец исключён | Нужен контакт **заранее**; у «исторических» экспертов (конгресс, старые доклады) его может не быть или он устарел |
| Нет ручной модерации на каждом связывании                      | Зависимость от доставки сообщения; ссылка может уйти не туда (переслали)                                          |
| Понятно эксперту: «вас пригласили»                             | Не покрывает эксперта, который сам пришёл на сайт и зарегистрировался раньше, чем получил приглашение             |

Коллизии: контакт неверный → команда перевыпускает приглашение; человек уже зарегистрирован с другим контактом → ссылка предлагает «войти в существующую учётку», связывание происходит с ней.

## Вариант B — «это я» (claim-first)

Инициатор — сам человек. На публичной карточке эксперта (страница доклада/урока/подкаста) и в ЛК — действие «Это я». Подтверждение — внутренней командой (ручная проверка продюсером/методистом, который с этим экспертом работал) либо по совпадению контакта из карточки.

| +                                                                                           | −                                                                                       |
| ------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| Не требует контакта заранее — закрывает «исторических» экспертов и базу конгресса (REQ-105) | Ручная модерация → очередь; нужна ответственная роль (кто именно — пересекается с Q-19) |
| Эксперт сам выбирает момент; можно заявить после регистрации, а не только при ней           | Риск самозванца, если подтверждение сведётся к «похоже ФИО»                             |
| Самостоятельная регистрация не ломается отсутствием приглашения                             | Пока не подтверждено — «подвешенная» заявка и ожидания эксперта                         |

Коллизии: двое заявили «это я» на одного эксперта → обе заявки в ручной разбор; одна учётка заявляет второго эксперта → отказ (одна персона — один эксперт), разбор вручную — чаще всего это **дубль эксперта** в базе, лечится слиянием экспертов командой.

## Вариант C — гибрид (рекомендация агента)

Для экспертов, заводимых командой **с запуска**, — A (контакт берётся при заведении, приглашение уходит сразу). Для всех остальных — B. Правило подтверждения одно: **совпадение подтверждённого контакта → автоматически; иначе — подтверждает человек из команды**. Любое связывание обратимо командой (откат с возвратом истории эксперту) — страховка на самозванца и дубли.

| +                                                           | −                                                                          |
| ----------------------------------------------------------- | -------------------------------------------------------------------------- |
| Покрывает оба потока: новых и «исторических» экспертов      | Два входа вместо одного — надо объяснять команде, когда что                |
| Ручная работа только там, где автоматика не сработала       | Нужен процесс слияния дублей экспертов и роль, которая это делает (→ Q-19) |
| Откат делает ошибку дешёвой, а связывание — не one-way door | —                                                                          |

## Что нужно от владельца (один выбор + два уточнения)

1. **Вариант A / B / C** — или свой.
2. Кто в команде подтверждает связывание и сливает дубли (роль; связать с ходом Q-19).
3. Нужно ли связывание **до** первой выплаты автору обязательным условием (т. е. без учётки начисления копятся на эксперте, но не выводятся) — это не решение о технике, а правило для эксперта-без-учётки.
