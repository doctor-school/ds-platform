# Промпты для отрисовки канвасов

Пакет — деливерабл, по которому **владелец (Product Lead) рисует канвасы сам**, в проекте Claude Design «Doctor.School визуальный язык» (`8cc2f39a-d58e-4491-b539-4337881ced4f`). Репозиторий канвасы не рисует и не правит: он держит вендоренные копии в `design-source/` и строит код по ним (ADR-0013, ADR-0014 §4).

Решение владельца 2026-08-22: **сначала дизайн целиком** — все канвасы R4 нарисованы и согласованы (Stage A), и только потом начинается сборка. Поэтому пакет покрывает все 20 экранов, которым нужен канвас, а не только волну 1.

## Как пользоваться

1. Откройте claude.ai/design, проект **«Doctor.School визуальный язык»**.
2. На **каждый экран — отдельный чат**. В чат вставляется два файла подряд: сначала [`00-preamble-ru.md`](./00-preamble-ru.md) (фиксированная преамбула — она одинаковая во всех чатах), затем файл нужного экрана.
3. Порядок прогона — по таблице ниже; это порядок §C [сверки](../canvas-reconciliation-ru.md#c-что-рисует-владелец-дальше--подтверждённый-порядок), подтверждённый владельцем. Шаги 1–3 зафиксированы владельцем как начало; дальше — в удобном порядке, но зависимости в столбце «Опирается на» соблюдаются.
4. Результат прогона — артборды на канвасе. Ваш выбор из предложенных вариантов композиции = Stage A-решение; оно записывается в PRD соответствующей фичи при её авторинге.
5. Готовый канвас вендорится в репозиторий (`design-source/`) отдельным шагом — это делает техлид, не вы.

**Тексты в промптах — черновик.** Каждый промпт несёт готовую рыбу на русском (заголовки, подписи кнопок, пустые состояния, ошибки форм) в медико-образовательном регистре. Она нужна, чтобы канвас не рисовался на «Lorem ipsum» и чтобы длина строк была реальной. Владелец правит тексты по готовой структуре.

## Правила, общие для всех промптов

- **Развилки не решаются промптом.** Там, где макет R4, реестр REQ и решения владельца (§D сверки, §F карты) молчат о композиции, промпт просит 2–3 названных варианта и оставляет выбор владельцу. Там, где решение принято, — промпт называет его и ссылается на источник (`D-1`, `F-3`, `REQ-138`).
- **Блоки — из макета R4.** Структура каждого промпта повторяет блоки соответствующего экрана `wireframe.html`: R4 согласован владельцем, это утверждённая информационная архитектура. Промпт добавляет дизайн-намерение и состояния, но не новые сущности интерфейса. Аффордансы, которых нет в макете, в канвас не заводятся.
- **Один визуальный язык.** Все канвасы — продолжение `design-system.dc.html`; никакого второго стиля, см. преамбулу.
