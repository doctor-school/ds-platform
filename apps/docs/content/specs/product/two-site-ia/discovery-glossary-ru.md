# Словарь терминов — DS Platform (Академия Doctor.School + витрина врача)

**Статус:** драфт по итогам ревизии владельца [R1] и ревизии [R2] по двум независимым ревью, 2026-08-19 (DSP-249). **Мастер — глоссарий репо `ds-platform`:** `apps/docs/content/product/glossary/` (file-per-term, EN, Keystatic-managed, ADR-0006; термины попадают туда PR-ом по конвенциям репо — canonical id, bounded context, sources). Здесь — рабочая RU-версия для пакета discovery; после переноса остаётся стаб-указатель. Не путать с KB BBM (`bbm-kb`) — это база знаний холдинга, не проекта. Правило: во всех документах пакета термины употребляются строго по этому словарю; синонимы из правой колонки — **не употреблять**.

## Роли (ключевые, по финмодели BBM)

| Термин                                  | Определение в DS Platform                                                                                                                                                                                                                                                                                                                                                                                                                                                                       | Не употреблять                                                                                         |
| --------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| **Автор**                               | Человек (эксперт), чей интеллектуальный вклад в продукт проекта (урок, курс, доклад, подкаст) подтверждён; получает начисления по смарт-контракту                                                                                                                                                                                                                                                                                                                                               | «создатель», «контент-мейкер»                                                                          |
| **Соавтор**                             | Человек, вносящий вклад в продукт наравне с авторами (второй эксперт урока, методист/продюсер как соавтор продукта BBM и т. п.); начисления по смарт-контракту                                                                                                                                                                                                                                                                                                                                  | «создатель», «помощник»                                                                                |
| **Инвестор** = **Партнёр** (проекта DS) | Организация (или лицо), финансирующая **проект в Академии** ради внимания врачей: фарма, производители медоборудования. Одно и то же лицо: «партнёр» — в контексте отношений/контракта и публичной витрины, «инвестор» — в контексте денег и смарт-контракта. Аккаунт — организация с несколькими пользователями (OWD-8); членство человека в организации — отзываемая связь (OWD-8 [R2], Q-33). **[R2, C-RV-20]** Не смешивать с инвестором в эволюционную цель холдинга BBM — см. строку ниже | «вкладчик», «рекламодатель» (CON-10, но термин обязателен в юридическом контексте — CON-14), «спонсор» |
| **Инвестор в цель BBM**                 | **[R2, C-RV-20]** Лицо, входящее в холдинг BBM ради его эволюционной цели. **Уровень BBM, вне scope DS**: другой предмет сделки, другие права, другой кабинет; к нему неприменимы лидерборд партнёров по доле намайненного внимания (REQ-62/63) и смарт-контракт проекта DS. В требованиях DS как роль не употребляется (упоминание в REQ-9 читается как уровень холдинга)                                                                                                                      | «инвестор» без уточнения уровня                                                                        |
| **Участник**                            | **[DSP-252]** Участник **BBM** по финмодели BBM: человек, вошедший в среду BBM (Doctor.School — один из проектов BBM) и ставший участником общего пула — претендует на выплаты из пула, может быть автором, соавтором, инвестором, членом команды. **Врач-потребитель контента участником не является** — он пользователь продукта, получает баллы за внимание (Пульс/Дыхание/Сознание), не деньги (CON-4). Эксперт, вошедший на Академию как автор/соавтор, — участник (REQ-44)                | «участник = любой человек экосистемы» (отменено); «участник = субъект учёта внимания» (отменено)       |
| **Инвестор (организация)**              | **[DSP-252]** Канонический термин DS для организации, вкладывающей деньги во внимание врачей или в проект (школа, вебинар); фактически спонсор/рекламодатель, но эти термины не используются. Роль-атрибут организации; другие роли: клиническая площадка, образовательный лицензиат (набор гибкий, Q-40)                                                                                                                                                                                       | «спонсор», «рекламодатель», «партнёр» (как носитель денег)                                             |

Служебные роли (кабинеты по REQ-71/93, не роли смарт-контракта): **методист**, **продюсер**, **администратор** (CRM), **оператор НМО**, **представитель партнёра**, **представитель клинической базы** (кабинета на старте нет — NG-6). **[R2] Добавлено:**

| Роль                                        | Определение                                                                                                                                                                                                                                                                                                      |
| ------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Верификатор**                             | Служебная роль внутренней команды: проверяет документы врача и подтверждает его статус (REQ-22). Единственная роль, которой доступны документы, удостоверяющие личность; объём доступа, сроки хранения и аудит зависят от выбора модели проверки (**OWD-12**). Операции роли разбираются в Q-19 (V-RV-6/C-RV-13) |
| **Медицинский представитель (медпред)**     | Сотрудник партнёра, приводящий врачей «в полях» (REQ-14) по промокоду/персональной ссылке с атрибуцией (REQ-39). Частный случай **представителя партнёра**; является ли он отдельным пользователем организации с **персональной** атрибуцией или анонимным носителем ссылки компании — **Q-34** (C-RV-14)        |
| **Лицензиат / образовательная организация** | Сторона с лицензией на образовательную деятельность: проводит обучение, выдаёт документ ДПО, выступает провайдером НМО (CON-5, Q-31). Не тождественна Doctor.School: DS учитывает результат, но не присваивает его сам (REQ-57)                                                                                  |
| **Клиническая площадка**                    | Организация, предоставляющая физическую базу (лекционный зал, операционные) для практической части и мероприятий (REQ-19/28); отношения — техаренда (REQ-43)                                                                                                                                                     |

Роли **лицензиата**, **клинической площадки**, **медицинской организации** и **работодателя эксперта** в конкретном проекте может совмещать одна организация, но это не правило модели — развести их предстоит в **Q-40** (V-RV-10/C-RV-10).

**Лейблы (атрибуты, не роли):** амбассадор, спикер, модератор, член оргкомитета, наставник, «постоянный участник», «команда».

| **Проект**                   | **[R2, V-RV-9 — единое правило]** **Контейнер работы Академии** со сквозным ID (OWD-9); школа, курс, подкаст, событие, конгресс — **результаты (продукты) проекта**, а не типы проекта (REQ-4/11). Правило применяется во всех REQ, OWD и в этом словаре                                                                                                             | «школа»/«конгресс» как синоним проекта                     |

| **Курс / урок / эпизод**     | Курс — серия уроков (формат «сериал», REQ-16); урок — единица контента и юнит финансирования (REQ-31); эпизод — термин прототипа приложения = урок                                                                                                                                                                                                                                                                        | —                                                          |
| **Событие / мероприятие**    | Вебинар, эфир, офлайн-встреча, конгресс; собирается конструктором мероприятий (REQ-81/83/99). **[R2, V-RV-9]** Событие — **результат проекта**, не проект: конгресс по ортобиологии — событие проекта «Ортобиология» (REQ-79)                                                                                                                                                                                             | «конгресс» как тип проекта                                 |
| **Клиническая база**         | Клиника + работающий на её базе институт — контрагент BBM (REQ-28, OWD-4). **[R2, V-RV-10/C-RV-10]** Совмещение ролей в одном контрагенте — свойство конкретного случая, а не правило модели: роли лицензиата, клинической площадки, медорганизации и работодателя эксперта разводятся в **Q-40**; противоречие REQ-28 × REQ-43 (кому платим) не разрешено                                                                | «клиника» как отдельная от института сущность (контекстно) |
| **Специальность**            | Первичная таксономия контента и профиля врача; список Минздрава (105 + «Другое»); первое действие на `doctor.school` (REQ-101). **[R2, V-RV-13/C-RV-7]** Различать: **регулируемая специальность** (номенклатура Минздрава) — **образовательный трек/интерес** — **школа** как продукт проекта; «смежность» — отдельный справочник связей; перечень специальностей НМО — третий справочник. | **Академия (Doctor.School)** | Закулисье и B2B: проекты, каталоги партнёров/проектов/экспертов, кабинеты автора/соавтора/инвестора; домен `academy.doctor.school` (REQ-95, OWD-5)                                                                                                                                                                                                                                                                        | «отдельный продукт Академии»                               |
