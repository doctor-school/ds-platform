# Wave-2 entry gate — `@ds/events-storefront`

## 1. Purpose and established facts

This is the wave-entry gate required by `2026-09-07-one-code-two-storefronts-plan-en.md` §4 («Wave-entry gate», the paragraph opening «The wave Issue carries a **behaviour matrix**»). No code PR of wave 2 (#2028) opens until every row below carries a test id and an explained difference. The document is slice 0 of #2028 and changes no code; the wave-1 gate (`2026-09-15-auth-flow-wave-1-entry-gate-en.md`) is its template.

- **Scope.** The events surfaces of both storefront hosts that wave 2 folds into `packages/events-storefront`: the Academy listing `/webinars` with its month view and the viewer page `/account/events` (`apps/portal`), the doctor feed `/events` with its live block and month band, and the doctor home nearest-events block (`apps/doctor`). The unit list is the wave-2 row of plan §4: `components/{discovery-listing,event-list-router,calendar-shell,month-calendar-view,month-calendar-mobile,view-switcher}.tsx`, `lib/{public-events,my-events,month-grid,event-lifecycle,msk,recording-signal,recording-cta,participation-cta}.ts`, `app/webinars/page.tsx`, `app/account/events/page.tsx` from `apps/portal`; `app/(storefront)/events/page.tsx` + `events/month-pane.tsx`, `lib/{events-feed,events-feed-cards,events-live,events-month,events-month-grid}.ts` from `apps/doctor`. Two units the plan row does not name travel with them because the listing cannot move without them: `apps/portal/lib/webinars-url.ts` (the Academy URL codec) and the three doctor client islands beside the route — `events/{live-block,day-anchor-scroll,resume-anchor-scroll}.tsx`.
- **Canvas precondition met.** #2076 is closed: ONE canvas `design-source/events-feed.dc.html` (+ module `events-feed-kit.js`) switched by a `host` prop (`витрина врача | Академия`), vendored by PR #2567; `doctor-events.dc.html` and `events-feed-month.dc.html` are archived under `design-source/archive/` and are no longer a composition source (plan §6 table, row «`doctor-events.dc.html` vs `events-feed.dc.html`»).

The doctor read `GET /v1/storefront/doctor/events` and the Academy read `GET /v1/public/events` already select their content sets server-side.

## 2. Behaviour matrix

One row per scenario. `Allowed difference` takes exactly one of: `none` · `config: <HostConfig field>` (with the clause that permits it) · `product divergence: <ref>` · `convergence: <owner decision / spec clause>` (with the PR that lands it) · `OPEN — owner question`. Every `OPEN` row is repeated verbatim in §2.8. A test id is an existing `file:line` test title, or `NEW: <proposed package or host-mount test>` naming what it asserts.

Anchors are `file:line` in this repository at `7a13a8a8`. A cell that could not be anchored reads `UNVERIFIED — <why>`, never a guess. Paths are repository-relative; `@ds/es` abbreviates `packages/events-storefront`.

**PR boundaries.** Six PRs, each at most two layers. PR 2.1 and PR 2.2 are step (a) of plan §4 — the Academy code and its tests move into `@ds/es` with **zero behaviour change**; the Academy is the only consumer. PR 2.3 mounts the viewer's «Мои события» page on both hosts, because the feed's «Все мои события →» link (019 LD-8) may not ship before its destination exists on the doctor host. PR 2.4 (feed view) and PR 2.5 (month view + facet column) are step (b): the doctor host mounts the package and its copy is deleted. They also carry the 2026-10-01 / 2026-10-05 behaviour changes on both hosts, because step (b) requires the doctor host to converge to the canvas when it mounts, «behaviour per canvas, not per the host's previous screen». The alternative ordering — the doctor mounts a pre-canvas Academy composition first — would need temporary host flags for behaviour the canvas retires (cursor paging, the in-list archive tab, the doctor's full-width month band). L39 forbids such a flag unless both of its branches are justified product, and these would not be. PR 2.6 mounts the doctor home nearest-events block (017 EARS-9, #1485) once `/events` is product-complete.

Allowed intermediate state (L148) holds after every PR: each unit listed in §1 is wholly in `@ds/es` or wholly on its host. The doctor units of a surface are deleted in the PR that mounts that surface.

### 4.3 Lead technical decisions

Choices the spec leaves to engineering; each is decided here and is not an owner question.

- **D1 — legacy Academy URLs (row 17).** The package page parses the legacy Academy params on the server and answers a permanent redirect to the canonical URL of the one codec: `tab=past` → `tense=past`; `view=month` and `month=YYYY-MM` keep their meaning in the codec (PR 2.5); `cursor`, `cursorTrail` and `page` are dropped and the reader lands on the first batch. Between PR 2.4 and PR 2.5 the redirect passes `view` and `month` through unchanged — the codec does not carry them until PR 2.5 — so a cached permanent redirect of a legacy `?tab=past&view=month` link never drops the month view. Why: shared and indexed links keep working and the codec stays one (019 LD-1) — accepting both shapes for ever would be a second codec. Test: `NEW: each legacy Academy param redirects to its canonical form; a dropped cursor lands on the first batch`.
- **D2 — «Показать ещё» on the Academy read (row 32).** The Academy read gains the horizon parameters and the package keeps no cursor. Why: the canvas draws one forward control and no back control, the extent must live in the URL (LD-1, LD-2), and the horizon already does that on the doctor host; a cursor in the package would be a host branch with no product reason (plan L39).
- **D3 — kind and format on the Academy read (row 36).** An additive projection of existing columns in PR 2.4; no migration.
- **D4 — the НМО value (row 39).** No aggregate authors НМО today, so the api fills `nmo: false` for every event (`apps/api/src/events/event-economy-facts.ts:32`); no credit count exists to render the canvas's «НМО · N». Modelling НМО credits is not wave-2 scope.
- **D5 — the Academy live read (row 43).** A new `GET /v1/public/events/live` over the same live resolution as the doctor read, parameterised by audience, so both hosts share one resolution, one refresh interval and one self-clearing rule (019 EARS-6). ### 4.5 Closed adapter list

Plan §2 allows a host to contribute a route file and a host-config object and nothing else, and `local/host-config-boundary` rejects function-valued config fields outside a closed list. Wave 2 declares that list as **one** entry:

| Adapter                                     | Row | Why it is an adapter, not a callback                                                                                                                                                                                            |
| ------------------------------------------- | --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `contentSet.adapt: (dto) => EventCardModel` | 8   | a pure mapping of the host's read DTO onto the one card / page model and status vocabulary — the «endpoint / adapter» of plan §2 L30; it takes data and returns data, decides no lifecycle, resolves no route and gates nothing |

If an implementation PR finds a second case, it STOPS and returns the question rather than adding an adapter — the plan's §3 rule 5 brief rule applies to this wave's PRs verbatim.

PR 2.3 (rows 15, 24–27) adds no adapter: the «Мои события» room href is api-resolved data on `MyEventItem` (D8), the endpoint is the data field `contentSet.myEventsPath`, and the guest decision runs in the package route over `routes.login` / `routes.accountEvents` with the shared `withReturnTarget` (§4.4) — no host callback.
