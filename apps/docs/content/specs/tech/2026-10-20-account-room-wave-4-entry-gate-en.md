### 1.1 Lead technical decisions

- **D1 — a separate package `packages/account` (`@ds/account`), not a module inside `@ds/auth-flow`.** The node already exists in the import-boundary graph (`eslint.import-boundary.config.mjs:69`–`:75`: `account → schemas, design-system, room, events-storefront, auth-flow`). The deciding edge is the doctor's congress row (row 14): the cabinet reads `@ds/congress-submissions/client` (DAS:16, :189), and `congress-submissions` imports `auth-flow` (`:63`), so the cabinet inside `@ds/auth-flow` would close a cycle. `@ds/account` sits above both; PR 4.1 adds the edge `account → congress-submissions` (acyclic: nothing imports `account`). What moves: the cabinet client controller (APC + DAS merged per §2.1), the server guard page, the default RU copy (the Academy `account` catalogue, word-identical to DAS `COPY`). The host config is data only (`local/host-config-boundary`, `ALLOWED_ADAPTERS` empty): `authFlow` (the host's existing `@ds/auth-flow` config: the package builds its client from `authFlow.api` with `createAuthClient`, as `apps/{portal,doctor}/lib/auth-flow-client.ts` do today, reads `login`, `account` and `reset` from `authFlow.routes`, and the save-error copy from its resolved `errors`), `eventsHref` (the host's `events-storefront` `routes.accountEvents`), `congress: { path } | null`. The route file keeps its own `metadata` (host brand, row 18).
- **D2 — the transport converges on the bound `@ds/auth-flow` client.** `apps/portal/lib/{profile-client,display-name-client,display-name}.ts` are deleted, not moved; the remaining consumer of `display-name.ts`, `apps/portal/lib/shell-auth.ts:10`, imports `@ds/room/display-name` directly (the module is a one-line re-export, `display-name.ts:11`).
- **D3 — the return carry is `withReturnContext` on both hosts.** AP:44 and APC:99, :195 use the portal's `withReturnTarget` (`apps/portal/lib/registration-handoff.ts:35`); DP:57, DAS:170, :275 use AF `withReturnContext` with the host's auth-flow config. Both emit `/login?returnTo=%2Faccount` for this route (DP:52–:55 comment; `apps/portal/app/account/page.test.tsx:53`). The package uses `withReturnContext`; with its last two importers gone, `registration-handoff.ts` and its test are deleted (REG L171).
- **D4 — the room reads address `serverApiBase()` on both hosts.** PR-room `page.tsx:44` re-spells `process.env.API_PROXY_TARGET ?? "http://localhost:3000"` (without the trailing-slash strip); DR-room reaches the same value through `apps/doctor/lib/room.ts:40`, :54 → AF `server/session.ts:80`. Both route files call `fetchRoomConfig` / `fetchMyDisplayName` with `{ apiBase: serverApiBase() }`; `apps/doctor/lib/room.ts` and its test are deleted.
- **D5 — one forwarded-session declaration, in `@ds/schemas`.** DEBT.md L130: `ForwardedSession` / `forwardedSessionFrom` / `forwardedHeaders` are owned by `packages/events-storefront/src/server/registration-state.ts`, re-exported by `@ds/auth-flow/server`, and structurally mirrored by `RoomSession` + `roomForwardedHeaders` in `packages/room/src/server/session.ts:12`, `:33`, because `@ds/room` may import neither owner. `@ds/schemas` is the one node below all three: the shape and the two pure functions (`Headers` in, plain object out — no Next import) move there together with `SESSION_COOKIE_NAME` and `hasSessionCookie` (`registration-state.ts:29`, `:39`), which `forwardedSessionFrom` calls; `events-storefront`, `auth-flow` and `room` re-point; `RoomSession` is deleted. No package edge is added.
- **D6 — the live-stand env gate moves into `@ds/e2e`.** DEBT.md L136 named «a workspace e2e-support package» as the only correct home and judged it too much machinery then; `packages/e2e` (`@ds/e2e`) now exists and both hosts depend on it (`apps/{portal,doctor}/package.json`). The twins differ only in `LIVE_STAND_VARS` (`E2E_PORTAL_URL` / `E2E_DOCTOR_URL`) and docblocks; the gate moves once and each host passes its variable.
- **D7 — the doctor `(room)` pass-through layout is deleted.** `apps/doctor/app/(room)/layout.tsx` returns `children` only; its docblock says the group exists to opt out of the storefront shell — the route-group folder does that, a layout file is not needed for it. The route-file registry row (REG L199) is removed.
- **D8 — `apps/doctor/lib/academy.ts` folds into the shell host config.** Its only importer is `apps/doctor/lib/shell-config.ts:2`, :80 (the footer's Academy cross-link — a 017 EARS-1 host value); the docblock's second consumer (the `/login` recovery link) no longer exists. The origin becomes a value of `shell-config.ts`; `academy.ts` is deleted. It is not room code; the registry lists it under wave 4 only because it is a doctor `lib/` file the «only allowlisted files» exit needs gone.
- **D9 — the room route mount is a package of its own, `packages/room-page` (`@ds/room-page`).** The Academy room route can only be a `mounted` route file (plan §5 wave exit, `pnpm lint:route-mount`) if the server page — the session read, `fetchRoomConfig` / `fetchMyDisplayName` over `serverApiBase()`, `resolveRoomEntry`, the refusal redirects, the event read — and the client wrapper — `next/link`, `router.refresh`, the shell `HeaderUserCluster` — live in a package. `@ds/room` cannot hold them: its purity guard (`packages/room/src/purity.test.ts`) bans `next`, `next/*` and `process.env`, and its graph row (`eslint.import-boundary.config.mjs`, `room: ["schemas", "design-system"]`) bans `events-storefront`, `auth-flow` and `storefront-shell`; an edge `room → auth-flow` would close a cycle, because `auth-flow` imports `room`. `@ds/event-page` is not the home either: it never imports `auth-flow` (wave-3 D1). So `@ds/room` stays the pure unit and gains the copy, the formatters and the route-table builder (rows 22, 24), and `@ds/room-page` — `room-page → schemas, design-system, room, events-storefront, auth-flow, storefront-shell`, nothing imports it — holds the server page `RoomPage` (`./page`), the client wrapper (row 25) and the data-only `RoomPageHostConfig` (`./host-config`).
